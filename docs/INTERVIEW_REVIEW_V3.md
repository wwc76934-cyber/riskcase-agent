# 面试官审查与升级记录（2026-10-23）

## 判断

当前是有认真评测与审计的支付预警研究系统；作为 Agent 面试项目，最薄弱的是**模型决策的任务空间太小，而工程与文档规模很大**。主路径足以说明受控工作流，却不足以独立证明复杂规划、跨任务记忆、知识检索或持续改进。不能因为功能名称齐全就升级评价。

本次先读取实现、历史结果和测试，以下属于代码与证据审查，不冒充用户访谈或独立复现实验。

## 按面试追问排序的问题

## 本轮实现

### 深度学习 challenger

`NeuralConfig.architecture=feature_transformer`：每个数值及缺失指示映射为可学习 token，MCC 有独立 embedding，CLS 经 pre-norm 自注意力编码器输出分类分数。复用训练期预处理、加权 BCE、梯度裁剪、模型保存加载与开发集日审核指标。注意力预测批次限制为 256，避免旧的 16384 推理批次导致内存激增。

这是受 [FT-Transformer 论文](https://arxiv.org/abs/2106.11959)启发的本地基线，不是官方精确复现，也不是“当前最先进”的结论。[TabM（ICLR 2025）](https://github.com/yandex-research/tabm)的参数高效集成是下一项值得公平比较的方法；它的存在也说明不能因为用了 Transformer 就预设一定更好。

`config/neural-challenger-v3.json` 固定同输入、同宽度、同层数、同批次的残差与注意力对照，各 2 轮，然后按原先日审核主指标选模型并确认三 seed。两个架构参数量和计算量不同，所以还需报告耗时和规模。两轮定位为全数据可行性实验，不声称充分收敛。原六配方预案保持原样。

复现：`scripts/run_project.ps1 -m app.cli.train_neural_v2 --policy config/neural-challenger-v3.json --output runs/新的目录`。

本轮完整实验已完成，训练 841,892 笔，开发 422,088 笔（683 个源正标签），每天 10 笔共 3,650 个审核名额。结果与指纹见 [机器汇总](neural-challenger-v3-results.json)：

| 两轮配方（seed42） | 捕获 | AP | 参数量 | 本机实验耗时 |
|---|---:|---:|---:|---:|
| 匹配残差 | 103 | 0.01664 | 6,715 | 72.6秒 |
| 特征 Transformer | 90 | 0.01570 | 13,729 | 724.0秒 |

两种模型的保存重载最大分数差均为 0。遵循事前主指标，选中残差而不是注意力模型；确认 seed42/43/44 捕获分别103/105/91，等权集成106，AP=0.01924。全部实验耗时约1,041秒。**本轮注意力模型更慢且更差，不替换原已发布检测器**。历史原配方开发捕获122，本次短预算小网络集成106，也不能宣称刷新原系统成绩。仅选中配方做三 seed，不足以比较两个架构的种子分布。

本轮没有读取2019。原始运行的 selected-recipe.json 带旧 runner 的通用文字“final refit may include 2018 before one-time 2019 test”；它不是本轮授权，本轮 policy 的 final_refit_contract 明确禁止把已见2019当新留出，且本轮只执行开发训练与评测，没有 refit 或最终期评测。随后已修正 runner，后续运行直接复制协议中的训练期与最终评测限制；也清理 challenger policy 中从旧预案继承的“六配方十轮”说明。原始回执保留，不回写美化，数值结果不受这些元数据文案修复影响。

### 经验记忆与检索的第一层

新增 `app/tools/knowledge_tools.py`，SQLite 持久化 reviewed procedure / lesson；记录来源、审阅人、可得时间、版本和内容 hash。审阅导入为宿主接口，不向模型暴露写入；模型只可控制 query，scope、as_of 与预算由宿主绑定。版本不可覆盖，检索只返回截至指定时间的最新版，旧版不会因为关键词更匹配而重新出现。

检索采用中文双字词和英文词的 IDF 加权词法基线，明确没有 embedding 或重排。无匹配时返回 insufficient_knowledge。`KnowledgeTools(case_tools, store, scope=..., as_of=...)` 可以直接传给现有 `run_investigation`；新增 `knowledge_trace` 保留检索回执。K 类引用与交易证据注册表隔离，无法用经验文本替代交易事实。

时间必须区分：交易事实使用 alert 事件时间；过程知识使用本次调查允许的知识截止时间。回测历史决策时应冻结知识截止时间；今天调查历史案例时可以使用今天已审阅的过程知识，但不能把这些知识回填成当年的可得事实。

新增测试验证真实训练损失下降、注意力梯度、保存重载、未知类别、标签字段隔离；检索测试覆盖范围隔离、未来版本过滤、替代版本、空结果、预算和参数越界、恶意文本不能用作事实引用，以及真实 ReAct 控制器的离线端到端路径。离线模型验证执行接线，不能当作真实 LLM 的检索收益。

该组件尚未接到页面默认主路径，也未填充经实际业务审阅的知识库；这是可运行能力基础，不是已经完成产品集成。尚未实现自动反思、记忆淘汰、向量/混合检索或有独立验证的持续改进。

离线演示：`scripts/run_project.ps1 -m app.cli.knowledge_demo --output runs/新的知识演示目录`。本轮五条手写机制题中，四条可回答题 recall@3=0.75，无答案题正确返回空；英文同义问题检索失败。三份文档取 top3 的结果很容易偏高，不能作为泛化成绩，故同时保留错误和候选列表。此实验没有调用真实 LLM。

## 本轮验证结果

- 全仓 `pytest tests -q -p no:cacheprovider --basetemp=.test-review-v3-unrestricted --tb=short`：**735通过，0失败，1条 Starlette/httpx 弃用警告，183.92秒**。
- 本轮模型训练、保存重载、开发日审核排序独立核对及三种子确认均已结束；源内成绩没有达到原模型，不发布替换。
- 默认 pytest 曾误扫描 tmp 受限目录，现以 pytest.ini 的 testpaths=tests 修复。默认沙箱临时目录重命名还遇到权限问题；改项目内临时目录后，HTTP测试仍在 Windows asyncio socketpair 初始化挂起。抓取栈后终止本轮挂起测试进程，使用获准的沙箱外执行完成上述全仓测试，没有通过跳过测试来隐藏问题。
- 代码差异空白检查通过。未调用付费模型，未新增远程部署，既有模型成绩与来源边界保留。

## 下一阶段验收

1. 固定一组需要程序知识、缺失信息处理和中途改计划的任务；金标及知识可得时间由宿主保存，不向模型泄漏。
2. 在相同工具、预算和题集上比较固定工作流 / ReAct / ReAct+检索；同时报正确率、漏查、不该执行却执行、花费和延迟。知识库变化必须有隔离的回归与未见题检验。
3. 将失败案例生成 lesson 候选，经过人工审阅与实验门槛再进入持久化库；比较提升前后，失败则保留旧版本。只有闭环实测有效后才能讲“受控持续改进”。
4. 增加历史序列模型与 TabM 等更强基线；先在开发集冻结训练协议，再寻求未见数据。保留所有失败结果；不要根据已见的2019调配方。
5. 最终面试叙事围绕“有限审核名额下，用可审计证据减少无效调查和错误结论”，实测 Agent 的增量。若固定代码同样好，就应诚实承认该子任务不需要模型。
