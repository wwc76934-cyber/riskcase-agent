# 欺诈主线真实模型功能验收：准备协议

2026-10-31。当前尚未授权发送本批。`prepare`只使用本机确定性控制客户端和真实stdio MCP；`run --live`必须取得单独批次授权。

目的：从“已接线的确定性流程”推进到真实模型对源交易工具、Skill和受控记忆的使用验收。不是新增欺诈标签准确率研究，也不是证明记忆能省人工。

输入为6A已冻结的4个IBM合成源神经告警，源行/用户/分数/时间与catalog绑定。它们是已观察的开发案例，本批是首次在此Harness欺诈入口做真实模型功能对照，不称独立留出。不会发送ULB真实来源数据或LongMemEval对话。

每案两组：同一技能、5项当前事实读取和相同验证器，一组无审阅记忆，一组可按工具读取此前同案的有限审阅记忆。共8次案件运行，每次最多6次模型请求，共48次；每次案件运行估算上限0.50元，但全批共享硬性本地账本上限2元，项目累计上限20元，不能把8×0.50作为批次额度。仍使用已有硅基流动受控客户端、项目费用账本和响应日志，不另建付费路径。离线预演24次模拟请求中，最大单请求保守预留0.207448元；原0.25单案预算可能加上前序已发生费用后阻塞，所以在真实发送前调整单案预留空间，全批上限不变。

记忆来源由本机确定性控制生成5项事实，经实验控制器检查并设置审阅状态，actor明确记为`experiment-controller-NOT-independent-human-review`；不是新的银行结案材料或真实分析师反馈。核查重点固定为授权缺口，不按模型输出调参或挑好例子。评测脚本不会伪装为用户的独立人工审阅。

输出：每组完成合同的案件数、是否读取Skill、当前事实引用、是否召回M、是否错误把M引用为E、保留3项外部证据缺口、真实请求/输入输出token/估算成本、首次失败及停止原因。两组不期待不同欺诈结论；必须重新读取当前事实。对照只能说明记忆增加的上下文/工具/费用与基本使用可靠性，不能证明因果效果或推荐默认启用LLM。

固定事实检查的确定性控制作为零模型成本基线单独报告。若LLM没有业务增益，产品默认仍用确定性核查；更开放的调查需获得真实原始资料和独立任务定义，不能靠这8次样本强行宣布Agent超过工作流。
