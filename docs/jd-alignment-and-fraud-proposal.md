## 最终产品建议：支付反欺诈调查与策略验证 Agent

目标用户：支付风险分析师或风险运营调查人员。目标任务：从一批预警开始，识别需要复核的模式，查证交易与历史行为，提出有依据的规则候选，在冻结数据上离线验证并提交人审。

用户输入示例：“调查这批预警中是否存在集中于某终端的异常交易。核对历史行为与数据质量；若发现稳定模式，给出一个规则候选并验证误报和新增捕获，不执行拦截。”例子中的终端字段只有数据确实提供时才可用。

执行闭环：

1. 导入经许可的交易数据，登记字段、标签、事件时间与标签可得时间；进行去重、缺失和时点检查。
2. 冻结一个可复现的规则或 ML 检测基线，产生告警及分数，建立 case。检测层与 Agent 独立。
3. Agent 查询交易、历史窗口、风险分群及解释摘要，按结果选择补查或结束；只用真实存在的主体/终端/设备字段，不制造关系。
4. 保存 case 证据：查询参数、原始记录 ID、窗口、样本量、特征与计算结果、冲突、尚缺资料。风险模式与事实分开。
5. 规则候选使用受限 JSON/DSL 表达，如支持字段上的条件组合和窗口统计；禁止任意 Python、任意 SQL 写入和直接线上动作。
6. 在开发/验证集迭代，在冻结保留集做最终验收；比较基线覆盖、增量捕获、重复捕获、误报、告警量和金额。标签不可见时不编造误报指标。
7. 输出调查简报、结构化 case、规则候选、验证报告及人工复核记录。人审采纳只产生本地版本，不自动封号、拒付、授信或部署策略。

“正常原因解释”是复核假设，不是模型定罪或自动结案依据。不得用事后欺诈标签指导模拟事前调查；标签只在授权评测阶段进入工具。

## 数据方案与验收风险

候选而非已选：

- [IBM TabFormer](https://github.com/IBM/TabFormer)：合成交易数据，可研究行为时序和调查链路；字段、规模与许可待下载前核验。不称真实银行流水或真实诈骗。
- [Fraud Detection Handbook](https://fraud-detection-handbook.github.io/fraud-detection-handbook/Chapter_3_GettingStarted/SimulatedDataset.html)：可复现模拟器，可构造已知模式和故障，用于工程金标准与学习。不能凭植入模式推断真实业务效果。
- [IEEE-CIS](https://www.kaggle.com/c/ieee-fraud-detection/data)：公开竞赛交易/身份数据候选，需确认账号、规则与使用范围；大量匿名特征可能限制自然语言调查和实体解释。不补造设备或现实身份。
- [Amazon Science FDB](https://github.com/amazon-science/fraud-dataset-benchmark)：公开数据加载、标准化切分和评测参考；每个源数据许可单独确认。

模拟数据可以验明工具和工作流；公开真实匿名数据可以测试模型与有限模式。二者指标分别报告，不混合生成“真实金融风控效果”。至少一个源上完整走通，再决定是否接第二源。

数据选型第一道门槛：实际可下载与许可、时间序列和标签解释、主体可关联性、字段可解释性、体量、单机处理成本。尚未核验这些条件，因此不承诺具体召回提升或最终数据集。

## 三层评测

1. 检测模型：PR-AUC、给定告警预算的 Precision/Recall、金额加权捕获等，报告样本数和假设；不以 Accuracy 作为主要成绩。
2. Agent：证据/查询正确、工具选择、缺口识别、完成率、成本/时延、权限；与固定调查脚本及给相同证据的模型总结比较。
3. 规则候选：冻结保留数据上是否提供可测增量及代价；保留失败候选，不反复看测试集挑规则。不将历史离线重放称为线上 A/B 或真实损失降低。

## 学习与实施顺序

金融基础和 Agent 同步推进：欺诈标签与误报成本 → 时点与窗口特征 → 检测和告警预算 → case 证据 → 动态调查 → 规则重放 → 持久任务与工程验收。

先冻结一个清晰任务，再做小规模数据可行性检查。尚未得到用户确认前，不改旧项目名或创建新业务系统；课程底座、Fake 和协议教学仍可复用，但不视为用户已掌握。

人民币 20 元模型预算保持不变。调查模型只接收必要摘要和限定记录，开发默认 Fake/HTTP Mock，先测真实单任务成本再定评测次数。
