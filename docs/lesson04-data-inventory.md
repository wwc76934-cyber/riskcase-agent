# 第四课：训练前，先看看数据靠不靠谱

本课做“数据剖析”，直白地说就是：**先数一数、分组看看、找出会影响实验的问题。**

## 一个具体例子

假设一份数据有一万笔交易，其中只有 10 笔欺诈。

一个程序全部回答“正常”，也会有 99.9% 准确率，但它一笔欺诈都没发现。因此，在看漂亮分数之前，必须先知道数据里的答案分布。

还要看看：交易覆盖哪些年份、有多少用户、有没有坏日期、哪些字段为空、记录是否按时间排好。

## 我们实际发现了什么

当前用的是 IBM 发布的合成信用卡数据，不是银行真实客户流水。固定文件全量检查发现：

| 问题 | 实测答案 | 为什么影响项目 |
|---|---:|---|
| 有多少交易 | 24,386,900 | 不能只靠几十条演示 |
| 有多少用户 | 2,000 | 论文描述不能代替本文件实测 |
| 有多少 Yes 标签 | 29,757，约 0.122% | 正常远多于欺诈，不能只看总准确率 |
| 2020 年这部分有多少 Yes | 0 | 不能单靠这部分检验欺诈召回 |
| 用户历史是否天然排好 | 不是 | 算历史之前要明确排序 |

**最后一年无正例**不是我们删掉了正例，也不代表现实那一年没有欺诈；它只是这个固定合成文件的情况。

## 这就是数据分析的用处

不是为了画几张好看的图，而是让发现改变决策：不能随便拿最后一年测试；不能按文件顺序算过去；不能把负金额和空白字段一律删掉。

数据没有证明提供设备、IP、真实人审记录。商户城市也不是持卡人的实时位置，所以不能假装已实现这些调查能力。
