# 日终告警分组：导航合同与验收

2026-10-31；执行完整队列分组和新源案例准备前固定。本轮输入是已观察的2018开发期冻结名单，不是新留出集；不读取标签或比较欺诈捕获率。

## 业务口径

- 输入仍是每天最多10笔交易的名单。按源事实版本、检测模型版本、源用户、源日期分组；不跨用户、版本或日期合并。
- 分组是审阅导航，不修改风险分数、原交易排序或入选成员，不补入排名11之后的交易。3342组不等于原预算变成每日10个案件。
- 每笔告警仍使用自己的交易时点截断历史。整个日终组次日日初才可得；不能把组内较晚交易塞进较早告警的事实证据。未知源时区继续标明。
- 每笔保留独立任务、报告、草稿、批准与模拟待办。没有“一键批准整个组”。新一天建立新组；再次核查同一告警建立新任务，保留旧记录，不覆盖原批准。
- 组本身不新增超时或自动关闭策略。执行超时、恢复与不确定响应沿用每笔任务的Harness合同。某一笔完成不使其他笔自动完成；没有外部结案，不标记整组欺诈或安全。
- 页面只显示已装载资料的分组，不暗示装载了全部3650笔。准备某组时，从已校验的完整名单逐笔导出该组全部成员，不能只保留最高分代表交易。

## 验收与不作的推断

1. 对完整冻结名单先核验来源和排序，再检查分组前后每个交易的字段完全相等，且没有重复或丢失。另测同分的并列排序。
2. 以成员最多的组作为多告警接线案例；若并列，按日期、原排名、组ID确定。选择不使用欺诈标签，不挑模型表现。
3. 每笔导出使用同一经过校验的源事实库及原神经分数；验证身份、截止、模型版本。执行确定性客户端和真实MCP，不读取密钥或调用LLM。
4. 页面展示组内各笔，分别核查并保留各自时间边界；API不提供组级批准。检查跨组过滤、窄屏和前端异常。

分组保留所有原入选交易只能证明队列覆盖不变，不能证明调查质量不降、合并后节省人工时间或减少模型调用。成员最多组也不代表3650笔都已完成MCP调查。人工时间与业务有效性仍需独立研究。
