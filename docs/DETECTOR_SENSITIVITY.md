# 预警分数如何连接到调查：只做能核对的输入敏感性

这个模块回答一个小而具体的问题：**保持同一冻结神经模型不变，只改一个原始输入，它输出的分数怎样变？**

例如，一笔金额12943（整数0.01源单位）的交易，把金额输入替换成该用户此前30天正金额的中位观测值2712，重新算分。它没有篡改源记录，也没有声称用户真的能重演一笔这样的交易。

这不是因果解释，不是已经证明可实现的反事实，也不判断欺诈。它可以帮助调查人员检查模型对哪些输入敏感、有没有与直觉相反的响应，以及哪些解释需要进一步验证。

## 三个预先固定的试验

| 试验 | 真正改动 | 依据与限制 |
|---|---|---|
| 历史正金额基准 | 仅将 `amount_cents` 替换成此前30天正金额的下中位观测值 | 必须有完整30天覆盖、正历史金额、本笔为正金额；不以均值抵销负金额 |
| 小时频次输入 | 仅将 `count_1h` 设为0 | 需要完整1小时覆盖；其他窗口计数和最近间隔保持不变，可能构成不一致的特征向量 |
| 商户新颖性输入 | 仅将 `merchant_seen_30d` 从0改成1 | 需要完整、非空30天历史；没有新增历史交易，不表示这家商户实际出现过 |

原值已经等于试验值时不重复计算。缺少覆盖、正金额或历史时，明确跳过对应试验。总共最多三个扰动，不能任意搜索到自己喜欢的分数。

“只改一个原始输入”不等于“神经网络内部只改一个数”。神经模型会重新计算自己的比例、交互等衍生特征，例如金额变化也会影响金额与历史均值之比。分差不能相加当成一套可分解贡献，也不能解释成某行为导致欺诈。

## 怎样保证解释的是这笔交易

调用者必须提供明确的冻结输入：

```json
{"transaction_id":"绑定交易ID","user_id":"绑定用户ID","event_time":"源本地时间","features":{"...":"精确的MODEL_COLUMNS，不能带标签或额外字段"}}
```

程序核对交易ID、用户和时点，再只读绑定的case快照。使用严格的 `[t-window,t)`：窗口起点包含，目标时点不包含，目标交易、同刻其他交易、未来和其他用户都不参与历史。

金额、小时、星期、渠道、MCC、窗口计数、有符号和、新商户标志和最近事件间隔，凡能从覆盖已证明的快照准确还原的，都必须与提供输入一致。计数还检查窗口单调性，标志与历史是否一致；无法核验的字段单列为缺口。

特别是**30天没有交易，不代表生命周期没有上一笔交易**。上一笔可能发生在更早以前，30天case看不到；程序不能把间隔偷偷设为空或0。调用者必须提供原来的冻结输入，并保留“快照无法核验”的说明。

`load_feature_input` 可从原冻结、无标签的特征数据库中只读这一笔。它检查特征库SHA256以及与case的事实/来源指纹一致性，查询同时绑定交易ID、用户、时点，不连接标签库。之后仍逐项对照case；它没有假装从不完整case重建了全特征。

## 模型来源与分数来源分开

本模块只加载自己生成的可信本地 `neural_v2` 模型。先用训练报告中已有的SHA256检查 `model.pt` 和 `preprocessor.joblib`，再加载；不能现场给任意文件算个哈希就宣称它可信。`joblib` 仍可能执行代码，因此必须显式使用可信本地模型，哈希本身不使陌生pickle安全。

支持1至3个不同seed模型，输出每个模型分数及等权平均。平均sigmoid仍是未校准排序分数，不能叫欺诈概率。

原case可能由旧树模型产生。因此结果同时保留“该冻结神经模型对原始输入的分数”和“案例原预警分数”，明确尚未核实为同一检测器。敏感性差值仅在同一神经模型内比较，不能用两种模型之间的分数差当成输入解释。

## 已实际运行的开发例子

使用原冻结特征中的源行20549941、用户1675、2018-01-02 13:26，以及第二版神经模型seed42/43/44。14项输入都能由绑定快照核对；没有读标签或2019记录。

| 输入 | 原值 → 试验值 | 三seed平均分数 | 相对原始输入分差 |
|---|---|---:|---:|
| 原始输入 | 无改动 | 0.06412171 | — |
| 本笔金额（0.01源单位） | 12943 → 2712 | 0.02423030 | −0.03989141 |
| 此前1小时笔数 | 1 → 0 | 0.08381210 | +0.01969039 |
| 30天内见过商户 | 0 → 1 | 0.01554077 | −0.04858094 |

把小时笔数设为0反而升分，说明不能先写“高频导致高风险”，再寻找解释去证明它。输入可能与其他固定统计矛盾，模型也有非线性交互；这些结果只是下一步调查线索。

原case树模型分数约0.80044031，不能和上面神经分数直接比较。完整逐seed分数、改动、输入、模型与解释代码指纹保留在 `runs/detector-explanation-v1-verified/`，证据ID为 `sensitivity-b45a9a18e255ce765d2e8b69`。这是一条复用开发案例，不是新增独立评测或真实业务效果。

## 运行与接入

```powershell
.\scripts\run_project.ps1 -m app.cli.explain_detector --case-manifest runs/mixed-stage-v1/cases/user-00/manifest.json --neural-run runs/neural-v2-development-01 --features-manifest data/features/features-b9692149f1c1/manifest.json --trust-local-models
```

命令新建运行目录，保存绑定输入、结构化解释、中文表格和文件指纹。不调用大模型或外部网络，不修改交易或模型。

主接口：

```python
bound_input, proof = load_feature_input(features_manifest, case_manifest)
model = FrozenNeuralEnsemble(models_from_neural_run(neural_run), trusted_local=True)
evidence = explain_case(case_manifest, bound_input, model,
                        model_metadata=model.metadata, input_provenance=proof)
```

Agent可把这个带证据ID的对象当作额外研究材料；它不会取得模型训练、文件写入、标签或金融执行能力。原有调查工具签名没有改动，最终UI和报告可独立展示这张表，不能自动把分差变成因果陈述或策略批准。

测试覆盖严格绑定、窗口边界、同刻/未来/跨用户拒绝、原输入不变、每次仅改一个原始列、精确分差、缺口跳过、非法分数、冻结特征单行读取、模型指纹和真实小型三seed模型保存重载。结果是可复核的局部诊断能力，不是已完成生产模型可解释性认证。
