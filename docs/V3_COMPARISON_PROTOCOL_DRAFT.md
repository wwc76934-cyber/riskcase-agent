# Gate 3 强对照协议草案

状态：设计草案，尚未冻结、实施或获得正式运行预算。6案交付开发预试不替代本协议。先完成协议可靠性开发和独立人员候选审查；冻结后不能根据评测结果改提示、基线、评分或挑选成功重跑。

## 要区分的能力

1. 语言理解增量：B4相对强B0，在完整且相同的可得资料上是否提高原话理解与严格业务质量。
2. 动态规划增量：B2相对强B1/B4，在同一实际获取成本和权限下是否提高关键证据获取或资源效率。
3. 记忆增量：B3相对B2，是否在未见家族上有独立改善。方法须仅来自开发集并经审阅；不因“读取了记忆”认定有收益。

B0为有来源溯源、修正/撤回处理、成本/时效策略的确定性工作流，不能用故意弱化的三个正则充数。基线不能导入参考模块，也不能按案件ID、评测家族或答案表分支。

B1获得全部预算允许、当前可得资料，保留一次性结构化报告加有界协议修复的强实现；若另比较二阶段输出，须单列协议差异与费用，不能把B1强制换成成本更高的弱版本。已知且已计费的格式失败可以按预声明上限修复；未知执行/费用不得重试。

B4只确定性抽取来源中已有的明确结构字段，将自然语言冲突判断交给模型。不得用宿主规则把客户语义先判好，再称LLM完成调查。

B2由模型选择当前目录中的下一份资料、声明待验证假设并按证据调整。宿主执行权限、时间和预算约束、不可变去重、终稿请求预留及来源验证，不能替模型猜测应该看哪个渠道或补出未知事实。T1/T2应保留前期假设及变更原因，不能把三个互不相干的一次性回答称为持续调查。

## 公平性与停止

各组使用同一运行世界、可用时间、查询费用和目标；都不能看参考和未来原件。B1也有预算内的合理资料获取策略，不因“全量超预算”直接判输。原件缓存、来源缺失、失败重试、模型修复、人工升级和宿主治理分别记账。

成本是模拟配额，不等同真实银行成本。正式协议需审查限制是否合理，并披露无法获取全部资料时各组的可行策略。产品不执行退款、冻结或最终欺诈认定；证据不足的人工升级可以安全但仍可能未完成业务任务，应分别计量。

## 评分与统计待冻结项

严格业务通过是预声明的全部必要条件，不由模型自己打分。同时保留交付成功、语义事实准确与证据支持、关键资料获取、错误关闭/不合理升级、T2终态、延迟/恢复、模型及工具请求和估算费用。成功交付后的质量另外报告，全部失败仍进入总体分母。人工负担仅在实际测量后报告。

以案件为配对单位，重复运行不能当成新增独立案例。建议至少三次预定随机重复；确定性B0可复用同一输出但明确不是三次独立观察。条件顺序应在案件/重复区组内随机化并留种子，不把供应商漂移与条件差异混在一起。

主对比是B4−B0、B2−B1/B4；B3−B2单列。按案件家族保留配对结构估计区间，报告家族数、案例数和重复数。当前8个评测候选家族很少，区间只描述此作者模拟任务域，不能推广到真实欺诈总体。区间算法、主要终点、多重对比处理、完整请求和费用上限须在正式运行前写入冻结协议；本草案不能冒充已完成预注册。

## 启用判据

只有独立任务上的业务质量或资源效率改善、可靠性交付及成本/安全约束共同满足，才建议候选路径启用。B4更好则选混合；B0更好则继续默认代码。Gate 4须等稳定Agent基线形成；错误/过期方法的宿主拒绝仅算治理，不算模型自主识别或自我进化。
