这是人为编造的八条数据：两项线索都是负数的四条，答案设为 0；两项都是正数的四条，答案设为 1。它只用于观察参数调整，不是我们的实际欺诈成绩。

你会看到学习前后每条数据的分数，以及损失变化。网络不是记住一句中文规则，而是调整内部矩阵和偏置，使输入更容易与训练答案对应。小例子学会，只能说明训练代码能学习一个简单模式，不能代替后面的时间验证。

## 2. 真正交易怎样进入网络

原始一笔交易有 14 个线索，例如金额、过去一小时交易数、商户是否出现过、支付渠道和商户类别。类别会展开成多个 0/1 列，缺失情况也可能增加提示列，所以变换后的输入列数 D 通常大于 14。

这些列整理成一个二维张量，可以先把“张量”理解为带有类型和维度的数值表。我们用 float32，表示每个数主要占 4 字节。框架还为它提供矩阵计算和自动求导。

一次取 2,048 笔，输入形状是 `[2048, D]`；每一行一笔交易，每一列一项数字线索。答案是 `[2048]`，每笔对应一个 0 或 1。最后不足一批也要训练，不能悄悄丢掉。

本次网络：

`输入 D 列 → 64 个隐藏单元 → ReLU / Dropout → 32 个隐藏单元 → ReLU / Dropout → 1 个输出`

因此第一层输出 `[2048,64]`，第二层 `[2048,32]`，最后整理为 `[2048]`。网络不能读取用户编号、交易编号或目标交易答案来预测。

**线性层**做矩阵乘法与加偏置；**ReLU**把负值变为 0，带来非线性，让多层网络能表达比单次线性打分更多的组合；**Dropout**在训练时随机丢弃一部分中间输出，降低对少数通路的依赖。它们都不保证未来更准，必须验证。

## 3. logits、sigmoid 和损失有什么区别

网络最后输出 logits，可以是 -3、0、2 等任意实数。sigmoid 把它映射到 0～1，例如 0 对应 0.5。我们用映射后的分数排序，但不把它当成已校准的现实欺诈概率。

训练使用 `BCEWithLogitsLoss`：它接收 logits，把 sigmoid 和二分类交叉熵合在一起计算，更稳定。**不要先手动 sigmoid，再把结果交给它。**

对于没有加权的单个样本：

`loss = -[y × log(p) + (1-y) × log(1-p)]`

答案 y=1，模型却给 p=0.01，惩罚很大；给 p=0.9，惩罚较小。损失是学习信号，不是最后业务成绩。

类别不平衡时，本轮对正例损失乘 `pos_weight = 训练负例数 / 训练正例数`。这个比率只从本阶段训练部分计算。验证损失继续使用训练时的权重，不拿验证答案重算权重。

此前 sklearn 的 balanced 会给两类都指定权重；这里 PyTorch 只放大正例项。相对重视程度可以一致，但绝对损失尺度不同，所以不能把两种框架的损失直接比较大小。跨时间重训后权重也会改变，同样应分别注明。

## 4. backward 到底计算了什么

先用只有一个参数的例子理解梯度。设输入 x=2、参数 w=0.5、没有偏置，那么 z=w×x=1，p≈0.731。若答案 y=0，当前分数显然偏高。

这个简单模型中，交叉熵对 w 的梯度为 `(p-y)×x ≈ 1.462`。如果用最朴素的梯度下降，学习率取 0.1：

`新 w = 旧 w - 学习率 × 梯度 ≈ 0.5 - 0.1×1.462 = 0.3538`

参数变小后输出分数也下降，更接近答案。梯度就是“参数往哪个方向、小幅改变多少，会怎样影响损失”的局部信息，不是模型解释的金融原因。

真正网络有许多层，PyTorch 的 autograd 根据前向计算关系，用链式法则算出各参数梯度；我们调用 `loss.backward()` 触发它。实际实验使用 AdamW，会结合梯度历史调整更新，并加入权重衰减，并不直接照搬上面的单参数更新公式。

## 5. 一个批次的五步代码

```python
optimizer.zero_grad(set_to_none=True)  # 清掉上一批梯度
logits = model(features)              # 前向：输入变成分数
loss = criterion(logits, targets)     # 与本批训练答案比较
loss.backward()                      # 自动求出各参数梯度
optimizer.step()                     # 根据梯度更新参数
```

`backward` 计算梯度，`step` 更新参数，两者不是一件事。PyTorch 默认会累加梯度，不清零会把多批梯度混在一起；有时这是刻意的梯度累积技术，但本轮没有使用，不能无意间漏掉清零。

当前 AdamW 学习率 0.001，weight_decay 0.0001。学习率控制更新尺度；权重衰减限制参数膨胀。参数在开跑前固定，不因看到 2018 年成绩就改。

程序还检查输入、损失、梯度和更新后的参数是否有限。出现 NaN 或无穷时应停止并记录失败，不能继续产出看起来正常的分数。

## 6. batch 和 epoch 为什么不是同一个东西

batch 是一次交给网络的数据；epoch 是把训练部分完整走过一遍。本轮选轮数阶段有 628,923 笔，批大小 2,048，一轮是 308 批，最后一批只有 187 笔。重训阶段有 841,892 笔，一轮 412 批，最后 164 笔。

DataLoader 负责分批和训练时打乱顺序。打乱只发生在已经确定的训练时期内部，不会把验证或未来交易混进训练。

这样既不用一次把所有样本塞进网络算梯度，也能持续调整参数。我们检查每轮计数，保证末批没有丢失。

## 7. 验证为什么要 eval 和 no_grad

```python
model.eval()
with torch.no_grad():
    logits = model(features)
```

`eval()` 改变 Dropout 等层的行为，本轮 Dropout 在验证时停用；它本身不关闭梯度计算。`no_grad()` 关闭这段计算的梯度记录；它本身不把 Dropout 切成验证模式。两者职责不同，都需要理解。

验证里不做 backward 或 step。每次训练开始则重新 `model.train()`。测试会检查：验证前后参数相同、同一输入的验证结果重复一致、没有新建参数梯度。

训练过程中记录两种损失：一是每批更新时的损失，含 Dropout 且参数不断变化；二是轮末固定参数、关闭 Dropout 后的训练集损失。与同轮验证损失对照时，后者更容易解释。

## 8. 怎样决定训练几轮

先用 2016～2017 上半年训练，在 2017 下半年计算 AP。最多 20 轮，若连续 4 轮未达到预先规定的改善幅度，就停止；保存 AP 最好的早期检查点，同分保留更早的。

这个内部验证只有 63 个正例，还集中于两个月，选中的轮数可能不稳定。我们如实记录，不声称找到了普遍最优训练时长。

轮数确定后，重新初始化网络、优化器和预处理，用完整 2016～2017 年训练同样轮数。此时没有沿用挑轮数阶段的权重。完成后才给 2018 年打分，并与首轮经典模型比较相同的每日审核预算。

2018 年已是看过的开发验证集，不能包装成全新的独立考试；2019 年本轮仍不评测。

## 9. 保存模型后，要证明它真的能用

保存 `state_dict` 就是保存各层学到的参数，还需要网络结构、输入字段和预处理，才能正确恢复。只留一个 `.pt` 文件而不记录这些信息，不是完整模型交付。

本轮保存：最佳选轮数检查点、重训模型、两套对应预处理、网络结构、逐轮指标、依赖与数据版本、2018 预测和审核名单。只加载自己生成的可信文件，参数使用 `weights_only=True` 读取；预处理 joblib 同样属于可信本地产物。

测试会让一组小数据学会简单模式，检查梯度与参数变化、验证不更新、固定种子复现、保存加载一致、异常数值中止。实际交易实验还会独立复算指标和审核名单。
