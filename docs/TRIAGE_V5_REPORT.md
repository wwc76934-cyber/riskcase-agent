# 阶段三：分步核查产品路径与 Agent 对照协议

2026-10-23。本阶段新增可运行的分步调查入口，并把“答案正确”“遵守停止条件”“工具调用量”分别测量。当前可用产品路径采用确定性代码；真实模型仍保留为实验路线，尚未证明增量。

## 新的实际功能

工作台调查方式新增“按优先级分步核查（免费）”。绑定研究口径为：

1. 读取绑定交易，检查此前1小时频次。
2. 只有结果为不支持时，才比较本笔正金额与30天历史正金额最大值。
3. 再次不支持时，才检查目标商户30天是否出现过。
4. 遇到支持线索或资料不足即停止；输出已经检查的完整前缀，包括负结果。未执行项明确没有结论。

这是一种事先声明的调查优先级，不是通用金融标准，不认定欺诈。目标是先找到需要继续人工处理的线索或数据缺口；需要完整三项分析的用户仍可使用原直接检查入口。

后端绑定 `first-lead-v1`，拒绝改写策略和 live 模式；界面也禁用该入口的付费模式。任务仍经过冻结输入、只读工具、证据引用、报告审阅与经验反馈流程。自建教学案例标识、事件时间边界及人工分数说明保留。

主要代码：`app/risk/adaptive_triage.py`、`app/service/triage.py`；API/任务存储/工作台增加 `triage` 类型。代码路径最多4次事实工具调用，零模型请求。知识材料只作参考，不能改变停止口径与事实结论。

## 对照设计

六个手写开发案例覆盖普通交易、金额变化、频次集中、历史覆盖缺失、非正金额和仅新商户。五个来自既有开发题，一项为本轮新增；不是未见独立测试集。金标仅保留在宿主评分端，不发给模型。

| 路线 | 行为 | 应观察的指标 |
|---|---|---|
| 固定全查代码 | 总取三项证据，再截取应报告的前缀 | 答案可正确，但可能违反早停口径、调用更多工具 |
| 分步代码 | 依据已获得结果选择下一步或停止 | 对照任何声称来自模型的规划收益 |
| ReAct | 相同事实工具、4次事实尝试、最多6次模型请求 | 答案、引用、调用顺序、停止位置、费用 |
| ReAct＋经验 | 在上述基础上增加最多2次可选过程检索 | 相同任务表现及额外检索成本；经验不能作事实引用 |

评分分别报告 `answer_correct` 与包含执行路径要求的 `task_passed`。拒绝的工具尝试也计入预算，不能只统计成功调用来隐藏越界。旧试跑最初的 task_passed 未包含早停要求，原始回执保留；`audited-results.json` 用修正口径重新计算，并保留 original_score，避免回写历史分数。

## 已验证的代码结果

| 路线 | 答案正确 | 完整符合顺序/停止合同 | 事实工具尝试 | 模型请求 |
|---|---:|---:|---:|---:|
| 固定全查 | 6/6 | 2/6 | 24 | 0 |
| 分步代码 | 6/6 | 6/6 | 18 | 0 |

本题集上事实工具调用减少25%。这是六个开发案例中的调用计数，不是数据库读量、生产延迟、人工效率或金融损失收益。CaseTools 初始化已读取投影数据，不能把少调用工具直接宣传成少读数据库。该节省由代码取得，没有归因给 Agent。

## 真实模型试跑：失败及修复

用户明确授权本阶段最多12组、最多估算2元。已执行6案例×2模型路线，共45次模型请求，本地 usage 费用估算合计 **0.473188元**，没有追加付费重跑。

两条模型路线均未形成通过验证的完整答案。失败原文现已保存，因此能够看到实际问题：模型输出曾使用 `status`、`checks`、`detail` 等字段，或在 JSON 外包代码围栏；部分组因保守费用预留达到预算而停止。

本次提示确实遗漏了完整输出字段合同。这是我在实验实现中的缺陷，已修复；**该试跑不具备评价模型或记忆优劣的条件**。不能据此宣传“代码优于所有 Agent”，也不能根据有记忆路线少两次事实调用就宣称记忆更好。两组都没有可验证正确答案，且存在提示缺陷与预算失败。

修复内容：

- 明确输出只能是 `findings`，每项只有 `check / assessment / evidence_ids`，不允许字段别名或说明字段。
- 新增统一的展示格式处理：接受严格 JSON，或仅包含一个完整 JSON 代码围栏；拒绝夹杂正文、多块代码、重复键和非有限数值。没有从任意文字中截取一段看起来正确的 JSON。
- 最多一次 schema 纠正，包含在6次请求总预算中，且纠正时禁用工具。保存首次原文、纠正原文和完整消息。已经符合字段合同却与证据矛盾的结论直接拒绝，不用重试“修成正确答案”。
- 旧经验小对照也使用该展示处理器。上阶段缺失的失败原文不补造；本阶段未使用新付费请求追补旧结果。
- 后续新运行冻结提示、源码快照和指纹；本次失败试跑的提示已在 protocol.json 保留，不能把当前修复后的提示冒充为当时使用的提示。

修正后的模型交互通过 Fake/Mock 测试，真实模型尚未重新验证。授权已经用于上述12组，本阶段结束前不新增实验组。

## 对面试叙事的影响

现在可以实际演示“后一步取证取决于前一步结果”，并展示负结果、数据缺口和停止依据；还可解释为什么必须同时比较全查代码与分步代码。工具调用节省不能自动记在 LLM 名下，memory 也不能凭存在就获得收益结论。

仍缺的核心证据是：修正协议后的真实模型端到端结果、更大且未参与设计的调查任务、需要多种证据来源与不确定选择的任务，以及真实使用者收益。当前只有三个有限检查和固定优先级，尚不足以证明开放任务规划能力。深度学习升级的独立泛化与更强方法对照也仍是后续工作。
