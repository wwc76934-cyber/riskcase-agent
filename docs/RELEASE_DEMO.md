# 一条命令：从深度学习预警到可审阅调查

这个演示包使用已经训练、冻结的三seed神经模型及其2018开发期分数，从真实IBM合成源选择案例，接到第二版调查计划和本地审阅页面。它不再只展示手工编写的演示交易。

在仓库根目录运行：

```powershell
.\scripts\run_project.ps1 -m app.cli.release_demo --output runs/release-demo-v1
```

目标目录必须不存在。失败或中断的目录不会被覆盖，也不会偷偷重跑付费请求；本命令本身完全不调用大模型。

## 命令实际做什么

1. 校验冻结模型报告、特征库、事实源和三个seed文件的SHA256；检查等权平均与保存的ensemble数组完全相同。
2. 只读取2018记录，按与训练相同的 `ORDER BY transaction_id` 排列。用三个冻结模型重新计算全部2018行，逐项核对保存分数，防止“数组长度相同但行序错了”。不连接标签数据库。
3. 按原实验相同的分数、固定tie hash和每日10笔规则排序。固定seed选择4个不同用户，每个取其最早进入名单的一笔；不根据标签、好看程度或模型是否解释顺利来挑。
4. 导出这4笔及各自严格截止时点以前的同用户历史，生成带模型来源、分数类型和排名的case。
5. 从冻结特征库读取绑定单行，核对快照可还原的模型输入，再产生最多三个单输入敏感性试验。
6. 在独立服务目录生成 `natural_v2` 离线计划，明确标为关键词脚本；模拟确认范围，使用确定性工具取证计算，独立源SQL核验报告。最后停在 `awaiting_review`，不会自动接受报告，也不会修改实际金融候选库。

每日前10笔是**日终批量审核名单**：直到当天结束才能确定全天排名。因此这些例子用于回顾式研究，不能声称交易发生时已经实时获得了该排名。调查工具仍严格限制在目标交易时点之前，不能把后续交易带进证据。

## 打开同一批报告

生成目录的README给出准确命令。默认路径为：

```powershell
.\scripts\run_project.ps1 -m app.cli.workbench --directory runs/release-demo-v1/service --catalog runs/release-demo-v1/catalog.json
```

打开 `http://127.0.0.1:8765`，从 `runs/release-demo-v1/service/auth.token` 读取本地访问令牌。不要把令牌当作模型API密钥或公开上传。

界面可查看已经生成的待审阅报告，也可对新注册case提交问题。默认不开启真实大模型。范围确认在准备包里是脚本模拟，不是实测人审；页面后来接受一份报告，也不等于批准风控规则。

## 结果在哪里

- `catalog.json`：可以直接交给现有workbench。
- `daily-review.json`、`selected-alerts.json`：无标签的完整日审核名单和代表案例。
- `alignment.json`：三seed全部2018行重新预测的最大差异与容差。
- `cases/.../sensitivity.json` 和中文表格：绑定输入、逐seed分数、单输入改动及缺口。
- `service/jobs/...`：离线计划、模拟确认记录、确定性调查报告、SQL核验。
- `cases.json`：案例、服务任务、报告与神经分数之间的配对索引。
- `manifest.json`：准备时的来源、代码、材料指纹及单独的可变服务库快照指纹。

准备完成后可只核对材料，不重新计算模型或请求API：

```powershell
.\scripts\run_project.ps1 -m app.cli.release_demo --verify runs/release-demo-v1
```

加 `--include-runtime-snapshot` 还会检查初始jobs.sqlite和auth.token快照。页面审阅会正常改变任务数据库，所以使用页面以后，初始数据库快照可能不同；这不表示报告材料被改动。密码值不进入清单，只记录文件指纹。

## 诚实的展示边界

这是2018合成开发数据上的项目展示，不是新用户泛化测试、真实银行业务或线上风控。神经排序分数不是已校准欺诈概率；输入敏感性不是因果或可实现反事实。原生敏感性模块对告警模型来源保守标记，本包额外核对同一冻结神经模型及重算分数，配对差异保存在cases.json。

本地 `runs/release-demo-v1` 已实际完成：422,088条2018记录、3个seed逐行重算最大差异均为0，3,650条日审核名单、4个不同用户case、4份独立源SQL复核报告，全部留在待审阅。103份准备材料以及初始服务库/令牌快照指纹复核通过，真实LLM请求0次。单case小批量重算相对保存的float32均值最大差异约5.96e-8，在事前1e-6容差内。

新增7项离线测试覆盖行序、均值、必须存在的SHA、只选2018、固定并列排序、真实case服务链、输出不覆盖和可变服务库快照。单元测试的轻量打分器不算真实神经模型效果；上面的实际演示另用了已冻结的三seed模型。

复现完整包需要本地已有冻结数据和模型；没有偷偷把大型数据、模型或密钥复制进Git。没有这些材料时，原来的自建fixture页面仍可用于验证安装和基本流程，但不能冒充这个神经模型合成源演示。
