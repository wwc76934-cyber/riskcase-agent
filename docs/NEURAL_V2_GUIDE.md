# 深度学习预警：从“换个网络”到完整实验

旧模型并不是没有运行成功，而是没有解决好业务问题：每天只能审核10笔时，它在2018开发数据中只找到42笔源欺诈标签，树模型找到95笔。旧MLP把3394个审核名额分给Online，而该渠道只有28个正例；Chip有564个正例，却只分到113个名额。

这轮先围绕这个已发现的问题做实验，而不是因为简历上想写Transformer就换Transformer。

## 一笔交易如何变成网络输入

仍然只读取既有14个时点字段，交易ID、用户ID、日期分区和欺诈标签不进入网络。标签只作为训练目标或离线评分依据。历史窗口已经排除当前交易、同刻其他交易和未来交易。

例如，本笔金额1000、此前30天平均签名金额100，与本笔金额1000、历史平均签名金额10000，应当有不同含义。新增“金额相对历史均值”的比例，让模型直接看到这种相对变化。这里的历史均值由**带正负号的历史金额和**计算，可能发生抵消，所以只作为数值特征，不能解释成真实消费均额或退款金额。

其他新增数值包括1小时相对24小时的交易密度、24小时和7天相对30天的活跃程度、小时与星期的循环编码。它们都由已有时点字段直接推导，没有计算用户未来全局统计，也没有读取标签做目标编码。

增强特征配方得到24个数值特征。每个数值再带一个缺失标记，因此数值张量是 `[批大小, 48]`。**最终选中的配方却没有保留这些新增派生特征**：它使用原来的12个数值及其缺失标记，形状为 `[批大小, 24]`；MCC单独成为类别张量 `[批大小, 1]`。这是消融后作出的选择，不能为了展示特征数量而强行保留无收益内容。原始渠道在最终配方中不输入网络，但在消融实验中保留，用来检查它是否诱导模型继续过分关注旧时期的Online模式。

## Embedding和残差网络到底做什么

MCC是一种类别，不能把5411解释成比4111“更大一千”。Embedding给每个训练中见过的类别一小组可训练数字；从未见过的MCC映射为固定未知项。类别词表只从训练数据建立。

数值先做带符号对数变换，再用训练期中位数和四分位距缩放，并限制极端值。验证期不能重新计算自己的缩放参数，否则会把未来分布偷偷交给预处理。

网络把数值与Embedding拼起来，经线性投影和若干非线性层，最后输出一个logit。残差版本在每个块中计算“原表示 + 新调整”，普通MLP消融则去掉这条跳跃连接。两种都实际训练，最终以预先规定的审核指标选优，不先假定残差一定更好。这里参考了表格深度学习研究中将ResNet类结构作为强基线的思路，但代码是本项目的轻量变体，**不是论文原模型的严格复现**。[论文与作者实现](https://github.com/yandex-research/rtdl-revisiting-models)

LayerNorm在一笔样本自身的隐藏维度上归一化；Dropout只在训练时随机屏蔽部分表示。验证与预测调用 `eval()`，关闭Dropout，并用 `no_grad()` 禁止梯度和参数更新。

## 为什么不再机械使用870倍正类权重

训练数据里正常记录远多于欺诈标签。旧MLP把正类权重设为负样本数除以正样本数，约870。这样可以让稀少正例产生更大的损失贡献，但不等于自动获得更好的每日前10名排序。

新实验比较权重1、20和100；同一条训练样本的正类损失分别得到不同放大。损失使用 `BCEWithLogitsLoss`，输入原始logit，内部完成数值稳定的二元交叉熵计算；不能先做Sigmoid再把结果当logit传进去。[PyTorch接口说明](https://docs.pytorch.org/docs/2.8/generated/torch.nn.BCEWithLogitsLoss.html)

每个批次都执行：清梯度 → 前向计算 → 计算损失 → 反向传播 → 检查并裁剪梯度 → AdamW更新。记录总行数、批次数和裁剪前最大梯度范数；末尾不足一个批大小的记录仍训练，不丢弃。

这些加权分数是排序分数，**不是经过校准的真实欺诈概率**。Sigmoid把数值压到0到1，不能单靠这个范围就称为概率。

## 这轮如何选模型

2016–2017用于训练，2018已经在过去多轮中看过，因此本轮明确把它当开发数据。固定6个配方，每个最多10轮：中等权重、无加权、高权重、保留渠道、去残差连接、去新增派生特征。每轮都保留曲线，不仅保存最好看的那轮。

选择顺序是：每日前10笔捕获的源欺诈标签数最多；并列时看AP；再并列取更早轮次和预先列出的配方顺序。之后固定配方和轮数，跑42、43、44三个随机种子，报告每个种子与平均分数集成。不能只挑其中最好的一次称为稳定提升。

同时训练一个使用同样增强数值、MCC且不含渠道的树模型。它沿用旧树模型的100轮、15叶和L2设置。这样可以检查，改善来自额外信息，还是网络在相似信息上确有帮助。旧MLP和旧树成绩也保留，不能删除失败历史。

每日前10笔是事后日终审核排序实验，不是实时拒付。AP衡量整个排序曲线，和每天前10笔不是同一个问题；AP更高却漏掉更多队首欺诈完全可能。业务只有有限审核名额时，不能看到某个次要指标漂亮，就临时替换主指标。

## 如何验证自己做对了

- 小数据确实学会一个可预测模式，而不只是代码运行结束。
- 同样种子重跑得到同样分数；验证不更新参数。
- 未知MCC与缺失值可处理；不把标签、用户ID或未来字段交给网络。
- 保存后重新加载，分数在预定浮点容差内一致。
- 用另一套排序实现和手工AP公式复算；并列分数也按照同一哈希规则处理。
- 最终2019结果由单独冻结的结项方案一次性验证，不拿它调配方或轮次。
