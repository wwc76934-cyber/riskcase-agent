## 用一个例子说明

你是分析师，每天只能检查10笔交易。检测模型给交易排序，挑出今天要看的名单。它回答“先看哪笔”，不能证明某人欺诈。

你打开其中一笔，问：“只查频次和新商户。”系统先把这句话转换成两项检查，展示具体时间窗口，让你确认。确认后，程序查询这笔交易之前的记录，计算一小时内笔数、30天是否见过该商户，写出数字、证据和缺口。你审阅报告。整个过程不会自动冻结账户。

如果调查让你想到一条规则，系统还要计算：每天同样只审核10笔，加入规则会多发现几笔、挤掉几笔、增加多少误报。我们的当前候选反而净少抓1笔，所以没有采用。能可靠否定一个坏建议，也是研究工具的价值。

## 三部分各做什么

| 部分 | 输入 | 做的事 | 输出 |
|---|---|---|---|
| 预警模型 | 本笔与之前历史生成的特征 | PyTorch等模型打分，按每天容量排序 | 优先审核名单；不是确定欺诈结论 |
| 调查Agent与工具 | 案例、你的问题、截止时间 | 模型理解范围；确认后代码查询和计算 | 有证据的报告，或资料不足/拒绝/失败 |
| 规则研究与审阅 | 一个有版本的受限规则候选 | 与原名单按同容量比较并保存材料 | 新增/挤出/净变化、待审阅记录 |

程序还负责保存状态、限制权限和费用，重启后恢复已保存的步骤；对结果不确定的付费请求停止重发。

### 没有源数据和模型的同学或面试官

Python3.12，仓库根目录：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-service.txt
.\.venv\Scripts\python.exe -B -m app.cli.workbench
```

浏览器打开 `http://127.0.0.1:8765`。页面访问令牌在 `runs/workbench-v1/auth.token`，只在本机读取，不发到聊天或Git。选择“普通历史”“新模式”或“历史不足”案例，先试直接勾选两项检查；再用离线自然语言“只查频次和新商户”，确认范围后查看报告。

这是明确标注的自建演示。离线自然语言用关键词脚本，不是真LLM；手工分数不是真神经模型。它的目的只是让新环境先跑通产品。

需要重新准备时指定一个不存在的新目录，不能覆盖旧运行；详见[整合演示](RELEASE_DEMO.md)。不要为了展示重跑最终2019评测或挑换更好看的seed。

## 先掌握的五个核心

1. **标签不是工具证据。** 标签用于训练/评测答案，Agent调查时不能偷看；真实标签什么时候确认未知，不能声称已做完整线上回放。
2. **相同审核容量才好比较。** 多发一万条预警可能多抓几笔，也可能让团队无法处理。看每天同样10笔的捕获与误报，不只看准确率。
3. **模型负责选择，工具负责事实。** JSON只是结构；合法JSON也可能查错范围。确认和数字核验解决不同问题。
4. **失败要保留。** 不能把第一次失败删掉、换题或换seed直到成功。开发集可改进，最终集开封后只能报告。
5. **恢复不是再问一次。** 已保存响应可回放；只知道请求发出、无法确认响应时停止，避免重复付费或副作用。
