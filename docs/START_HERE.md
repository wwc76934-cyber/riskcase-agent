# 先读这里：项目做成了什么，怎样验证

2026-10-31。RiskCase 当前主线是**事后批量欺诈告警调查工作台**：检测排序 → 同一交易的历史取证 → 分析师审阅 → 受控审阅记忆。目标是在有限审核容量下组织可复核线索，不凭异常分数认定欺诈，不自动冻结账户或退款。

## 从一个告警讲起

分析师每天审核10笔交易。冻结检测模型产生日终名单，每条告警保留交易ID、源数据和模型版本。调查层读取该交易之前的同用户历史，核查频次、金额和商户出现情况，并显示覆盖不足及待补材料。即使三项线索都不支持，也不能宣布交易安全：持卡人授权、认证日志和外部结案资料仍然缺失。

审阅通过的报告可以形成记忆候选。来源重算和内容绑定批准后，未来适用任务才能按主体、源事实版本及两个时间边界复用。记忆只提供核查重点，当前事实仍需重新取证；撤下影响未来任务，已冻结任务保留审计快照。

## 各部分的证据与边界

| 部分 | 已具备的证据 | 尚不能据此声称 |
|---|---|---|
| 检测 | IBM合成源的时间评测；另在ULB/Worldline公开匿名交易上重训并进行时序对照 | IBM模型已在真实银行泛化，或神经网络普遍胜过强树 |
| 调查 | 同一源告警接入真实MCP、版本化Skill、持久Harness和人工审批；四案确定性接线及真实模型修复回归两组各4/4 | 独立银行调查准确率或Agent业务收益 |
| 审阅记忆 | 候选、来源核验、发布/更新/撤下、隔离与冻结复用 | 自主学到欺诈规则，或将审阅摘要作为确认标签 |
| 检索 | LongMemEval-S全部500题公开检索对照，保留缺失证据与长上下文问题 | 答案准确率、欺诈业务收益或分析师节省时间 |
| 运行 | 本机32任务、2工作线程的实际MCP负载与恢复/审批检查 | 生产集群容量、真实模型网络延迟或机构认证 |

实现与结果见[本轮报告](STAGE6B_MEMORY_REPORT.md)，责任与后续验收见[业务方案](FRAUD_PRODUCT_PLAN.md)。当前三项固定核查有明确代码基线；动态Agent的必要性仍须用独立任务、相同事实权限与强简单方案的比较证明。

## 怎样运行和检查

- **本机已有IBM源数据和冻结演示包**：按[主线运行指南](FRAUD_WORKBENCH_QUICKSTART.md)准备新的欺诈调查目录，再启动工作台。主线页面是 `/investigations/page`。演示默认确定性客户端、真实MCP、零模型费用；完整记忆发布和撤下步骤也在该指南中。
- **从干净检出开始**：按[公开评测指南](PUBLIC_EVAL_QUICKSTART.md)下载固定来源并复现检测和检索实验。这条路径不依赖本机IBM权重或模型API密钥。Git中只有代码与汇总证据，原始数据、权重和运行数据库需要另行准备。
- **准备真实模型功能验收**：按[功能验收协议](FRAUD_LIVE_ACCEPTANCE_PROTOCOL.md)区分准备与发送。普通离线工作台不会领取live任务；发送需明确的本批授权并受批次和项目总账本约束。首次真实运行及同四案修复回归均已完成，见[真实模型验收报告](FRAUD_LIVE_ACCEPTANCE_REPORT.md)；原始失败单列，不把模拟回执当作模型成绩。
- **面试展示**：使用[当前面试手册](AGENT_INTERVIEW_PLAYBOOK.md)的业务讲述与七分钟演示，按[能力矩阵](AGENT_CAPABILITY_MATRIX.md)区分实现、实测和缺失。参考项目的借鉴与取舍见[记忆方案分析](REFERENCE_MEMORY_ANALYSIS.md)。

不要用未带源数据的默认手写演示替代冻结神经告警。不要将支付争议实验的6/6成绩用于反欺诈叙事。实际客户端类型、数据来源、实验条件和首次失败回执都应在展示时可查。

## 仍未完成的目标

已完成的同四案功能回归检验了当前工具与记忆合同；两组各4/4不能证明模型优于确定性取证、记忆提升业务质量或节省人工。独立调查任务、可靠外部反馈及真实分析师审阅时间仍缺失。[同用户同日导航分组](STAGE6D_GROUP_REPORT.md)已经落地并保留逐笔取证与审批，但合并调查的人工收益仍未证明；3650条交易审核名额不能换算成3650个独立案件。

这些是后续验收条件，不用增加组件或测试数替代。项目当前适合作为有可复核证据与明确局限的研究工程项目介绍，不宣称完成真实机构上线或端到端业务收益验证。
