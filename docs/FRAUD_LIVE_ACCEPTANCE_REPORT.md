## 首次失败与修复

首批用户00与03的无记忆任务各连续请求三次`load_skill`。Skill第一次已成功加载，但模型后续请求仍可看到该工具；系统提示也一直要求先加载Skill。第三次被既有无进展保护阻塞。

四个无记忆任务的首次请求内容指纹相同，却出现不同后续路径；不能把两个失败归因于案件事实差异。这里没有足够重复试验估计模型稳定性，也不能把首批2/4与4/4当作记忆的因果收益。

修复包含两个变化：

- 每次模型请求从检查点重建可用工具。`load_skill`参数只列尚未加载的冻结Skill；全部加载后移出菜单。其他工具与权限保持原合同，多Skill任务仍可加载剩余项。
- 提示显式列出已激活Skill和剩余预算。已完成激活后要求继续查当前证据；去Skill条件不再要求调用不存在的加载工具。宿主拒绝重新激活，即使模型无视菜单；原有尝试、请求及无进展上限仍保留。

先用明确标记的模拟客户端重现循环，再修复并通过90项受影响模块回归，覆盖持久恢复、检查点、记忆、原始案卷和审批。两组真实回归随后各4/4。菜单与状态提示同时变化，不能从本批分离各自贡献，更不能把一次回归写成普遍可靠性证明。

真实回归后另发现并修正离线`no_skill`代码基线仍尝试加载禁用Skill的问题：模拟客户端现在依据暴露的工具及当前证据推进。该补丁只影响确定性控制路径，随后30项相关回归通过（与前90项重叠，不相加）；不计作新的模型回归。真实调用时的精确`fraud.py`已单独保存，避免将后续文件版本混同为当时执行版本。

## 对照可比性与局限

两批的源快照、问题文本和Skill版本逐项相等。审阅记忆重新由相同确定性源事实生成，除源运行引用外的记忆正文相同，但记录ID、源报告引用和实际审阅时间更新。记忆来源的actor始终是实验控制器，不是独立分析师或银行结案。

回归中两组的行为线索判断一致。当前三项固定统计已有零模型成本的确定性基线；记忆内容又与固定授权缺口高度重叠。结果证明了限定工具调用与记忆读取流程可以完成，**尚未证明LLM比代码更值得使用，也未证明记忆提高质量或节省人工**。默认产品路径仍是确定性核查，真实模型路径按明确实验授权执行。

用户已明确当前没有可用的独立调查资料或风控评审人员。后续只能继续查找与主线相符、可合法使用的公开任务；真实业务价值仍需要可靠外部反馈及人工审阅成本对照。不能把这16次运行（同四案的两轮两条件）说成16个独立案例，也不应将固定事实验证通过率写为欺诈检测准确率。
