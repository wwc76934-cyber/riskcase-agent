# 支付欺诈调查：Agent价值对照报告

2026-11-02。**180个主模型条件和60个B0条件完整执行，60个记忆压力条件均有终态，其中54个至少发送一次模型请求、8个触发批次预算保护。** 全部首次失败保留；300个正式条件记录齐全不代表240个模型条件都完成了实际调用。冻结规则选择B0代码证据包，没有证明动态Agent或方法记忆的稳定增益。

## 研究问题与业务范围

业务链保持为检测排序、告警取证、分析师审阅。检测器不认定欺诈，调查Agent不退款、不冻结、不修改标签。研究问题是：在多来源声明、覆盖缺口、更正及规程变化中，动态调查和受审阅方法能否比强代码与完整资料综合增加质量，并值得其调用开销。

A是已有IBM合成交易及冻结模型投影；B是逐条声明独立模拟的调查原件；C是作者参考、关键事实和程序评分，仅供控制器。90案分30开发、40冻结、20挑战，含15个情景家族、50个主体和40组同A配对；开发、冻结和挑战按家族及主体隔离。180个A/B及C文件、来源SQL与时间边界已核对。**C独立于模型执行，不代表独立于作者或外部机构。**

模型只见A/B、当前工具结果、冻结Skill及指定的开发方法；ULB、LongMemEval文本和评分参考未发给供应商。后两者仍属于独立历史研究。

## 能力展示与收益结论分开

系统已实现案件/主体/时点绑定的两个官方SDK MCP进程、类型化只读工具、动态工具菜单、冻结Skill、持久假设计划、访问与费用预算、响应日志和租约恢复。终稿假设按模型实际提交归档，单列于模型主动请求的中途修订。宿主根据已读原件回填事件时间与A/B层级，不添加未读取资料。

有实际模型按原件修改计划、选择来源和改变建议的记录。例如world-057/058的B2同A配对均严格通过，建议与计划来源序列不同，但实际归一化取证路径没有变化；world-086/087的B3均严格通过且路径变化。**路径变化或一个成功例并不是增益证明。** 前一配对也未证明代码无法完成同一任务。

展示可选最早具有原件后主动修订的严格通过B2案例world-032，结合其初始假设、实际E/O引用、计划及最终报告讲解。它用于说明能力如何实现；群体效果仍由上表决定，不把展示案例当独立效果实验。
