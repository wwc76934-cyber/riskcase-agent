# 支付欺诈调查：本轮设计审查

本轮保留“检测模型排出待审核告警 → 调查员交叉取证 → 人工审阅”的单一业务链。认证与客户材料属于明确标注的独立模拟环境；历史退款差错研究不作为欺诈效果证据。主比较已完成并选择代码默认路径，见[完整报告](AGENT_VALUE_FINAL_REPORT.md)。以下区分设计能力与收益证据。

## 改进针对的具体问题

| 原问题 | 当前实现及其目的 |
|---|---|
| 三项固定统计可以直接写代码 | 保留固定核查，并增加读取全部资料的强代码B0；模型必须面对不同叙述、来源、版本和证据缺口，不用弱基线制造优势 |
| 加Agent后业务转成退款争议 | 主入口围绕欺诈告警、认证、设备、账户、客户声明和调查规程；退款组件折叠到历史研究区 |
| 调查资料看起来像真实IBM记录 | A使用已核验源交易及模型告警，B逐条声明独立模拟，C作者参考仅存在控制器；不把模拟解释成银行效果 |
| 所谓规划只是重复查询 | 初始假设在内容读取前记录，模型可选资料及查询；实际工具结果按标准对话返回，避免重复启动；最终假设和中途主动修订分别记录 |
| 引用错误与业务错误混在一起 | 模型选择来源及解释；代码根据已读原件回填事件时间和来源层级、去重排序。原始选择和宿主改动均保存；正确引用仍不代表解释正确 |
| 对照不给简单方案完整资料 | B1拥有全部当前可得A行与B原件；B2/B3也能直接批量读取。所有条件使用相同范围、原件和评分 |
| 经验只证明能写入数据库 | 候选绑定真实开发报告、来源重算和控制器事实反馈；冻结/挑战不反向学习；评估原始历史、受审阅方法、过时和错误方法 |
| 新协议改变导致旧记忆崩溃 | 新任务冻结自身输出协议；旧有限格式兼容只用于既有来源重验，引用、主体和时点检查不放宽 |
| 工具目录暴露不存在的能力 | 按已完成只读操作、已知资料、激活技能的实际资源更新菜单；不存在的技能资源不提供给模型 |
| 费用异常或响应丢失后盲重试 | 原项目账本、请求预约、响应日志和租约合用；原始响应在校验前留存对外内容与usage，省略思维链；未知费用停止并保留占用 |

最终假设入审计来自模型实际提交内容，并不伪造一次工具请求或中间推理。代码不能为模型补出未读取资料；虚构来源仍被拒绝。源证据E、结构化主张O和方法M保持不同作用。

## 已知限制及面试时应如何解释

- **数据仍是受控研究环境。** A是IBM合成交易，B和C由作者生成，90案按15个家族拆分且主体隔离；这不等于独立机构标注。机械源SQL核对也不能认证所有调查语义。
- **评分只覆盖有限、明确的主张。** Q及各分项在运行前固定，摘要全文、所有假设含义和处置合理性未由专家全面核验。引用、版本号和时间线有效不能包装成“报告完全正确”。
- **Agent不预设获胜。** 数据量和语言机制有限时，强代码或一次性LLM可能更稳、更便宜。默认方案遵循预注册规则，不能只挑一个成功演示。
- **任务仍有有限状态和短资料的限制。** 当前每案只提供少量已注册来源，事实类型、建议动作和调查目标范围有限；没有以任意长文档、未知工具、临时需求变更或真实机构的持续到件验证开放环境能力。资料可得时间和更正版本得到约束，但当前比较是在各案固定调查时点执行，不是跨多个时点的在线到件实验。
- **Q不等于最优取证策略。** 关键主张覆盖与完整报告质量偏向组织齐全的证据包；模拟访问成本和轨迹指标补充这部分信息，但尚未校准“某份资料是否值得读取”的实际业务效用。不能从较短路径或单次路径差异直接推出更合理的调查。
- **路径差异没有重复采样的因果保证。** 每个案件/条件只有一次模型运行。即使同A配对的读取次序不同，也可能包含模型随机性；只有结合来源覆盖、事实与建议结果才有解释价值。最终假设归档本身不能证明模型在调查中主动改道。
- **模型与预算限定结论范围。** 本轮只有一个供应商模型、每案6次请求和固定输出上限；失败也计入比较，但不能据此推断所有模型或更大预算下Agent的普遍优劣。
- **没有真实人效或损失指标。** 访问开销是模拟单位，不是实际调查费用、预期信息价值或风控损失。未测分析师时间，不能宣称节省百分比。
- **方法复用不等于模型自进化。** 当前是有限错误类别、受控方法模板和可撤下版本的反馈流程，没有自动训练检测器、学习新业务规则或更改案件事实。
- **回溯研究的两种时间要分开。** 案卷事件/可得时间来自研究源，方法审阅在2026年；通用方法用于回溯评测，不冒充2018年银行当时可得知识。
- **MCP与权限的实现范围有限。** 使用官方SDK的本地独立stdio服务、类型合同和案件绑定；不宣称已经实现远程企业身份、跨租户权限或生产规模治理。
- **费用是本地估算。** 已知usage、未知预约、额外保守占用分别披露；云模型别名与缓存、延迟和输出存在波动，提供商账单仍是实际收费依据。
- **人工审阅是产品行为。** 报告形成待审阅草稿，五项确认和当前内容哈希批准后才能发到本机模拟队列，没有资金、账户或标签写入工具。

## 不再采用的叙事

不写“神经网络发现欺诈后，Agent证明并处理退款”；不写“实现MCP/RAG/Memory所以具有业务价值”；不把脚本探针写成模型自主规划；不把宿主TTL拒绝写成模型识别过时知识；不把缓存的旧响应离线重验写成新的模型成绩。

全体主比较支持代码默认路径；压力条件另披露预算和操作失败，负结果与未验证事项全部保留。

## 与公开Agent评测方法对照

2026-11-01核对以下原论文摘要，作为当前实现的边界审查；没有据此改动已冻结实验，也没有宣称复现这些基准。

[ToolSandbox](https://arxiv.org/abs/2408.04682)将有状态执行、工具间依赖、信息不足及任意轨迹上的中间/最终里程碑纳入评测。对照这一设计，本项目需要把初始计划、实际读到原件后的主动修订和终稿归档分开，不能把最终结构化报告等同于多步规划可靠。当前没有完整的交互用户模拟器。

[τ-bench](https://arxiv.org/abs/2406.12045)通过对话后的数据库终态检查目标，并用多次试验衡量一致性。对应到本项目，本地工单收据和内容绑定审批比“模型说已提交”更可靠；但本轮每案/条件只有一次模型抽样，不能报告多次连续成功率，也不能把人工待审阅状态当成业务已结案。

[τ^τ-Bench](https://arxiv.org/abs/2609.04611)把面向业务记录、客户需求、既有代码、生产API及成本/模型限制交付Agent作为构建任务，再对留出模拟用户评测。它提示我们，组件能运行只是交付的一部分，还应检查继承业务事实、资源约束和真实需求；这是本文从摘要作出的工程推论。本项目使用作者模拟记录、单模型和本地服务，不能借用该论文的生产场景或成绩作为自己的证据。
