# 第九课：模型换到下一段时间，还能不能用

先看一个实际问题：上一批树模型在训练集上的 AP 约 0.79，换到 2018 年只有约 0.016。不能因为训练成绩好就满意，也不能直接认定“模型不够复杂，需要神经网络”。我们先安排几个有明确问题的对照。

## 1. 时间验证是什么

想象用前一年的交易教模型，下一年的交易当练习考试。模型在考试之前看不到答案，填补值、类别列表等预处理也不能从考试数据重新学习。

本轮只使用原来的 2016～2017 年训练部分，进一步分两次：

| 次数 | 用来学习 | 用来检查 |
|---|---|---|
| 第一次 | 2016 全年 | 2017 上半年 |
| 第二次 | 2016 全年 + 2017 上半年 | 2017 下半年 |

第二次允许把第一次检查的时期纳入过去的学习数据，因为这些交易在第二次考试开始前已经发生。这是回顾性时间实验；真实系统能否当时拿到这些标签，仍未知。我们没有把它说成已验证的线上重训。

每次都新建模型和预处理，再 fit；不能拿已经用过 2017 年答案训练的旧模型来考 2017 年。两次考试范围互不重叠，开始时刻包含、结束时刻不包含。

2018 年已经被我们看过成绩，属于开发验证；这次不再用它挑配置。2019 年最终检测测试本轮继续不评测。

## 2. 为什么没有用随机划分

如果把几年的交易混起来随机分训练和验证，模型可能在学习中看到较晚时期的风险模式，再去判断较早时期，无法回答“学完过去，面对未来会怎样”。

随机划分并非永远错误，但它回答的是另一个问题。支付风险会随时间变化，我们优先检查时间迁移。同一用户跨时间出现是当前业务设定，不等于新用户泛化已得到证明。

## 3. 数据先告诉了我们一个麻烦

只检查本轮候选时间段的行数和正例后发现：

- 2016 上半年：207,394 笔，476 笔欺诈标签。
- 2016 下半年：211,974 笔，428 笔欺诈标签。
- 2017 上半年：209,555 笔，**0 笔欺诈标签**。
- 2017 下半年：212,969 笔，**63 笔欺诈标签**。

我们在配置中登记这个发现，并保留上半年这一折。它不能用 AP 或召回率比较抓欺诈能力：没有正例，分母和“把正例排前面”的对象都不存在。报告写 null（没有可用数值），而不是写 0 分，也不把这一折悄悄删掉。

每天强制选 10 笔时，全是正常交易的时期必然全部选错。这主要揭示“固定满额审核”在该时期的代价，不能据此判断哪个模型完全没有判别能力。以后如果允许低风险日不满额审核，需要另行制定阈值策略和验证，不能在此轮临时改变规则。

## 4. 五个对照，每个只问有限的问题

| 对照 | 与参照的差别 | 想检查什么 |
|---|---|---|
| 逻辑回归原配置 | 较简单的加权模型 | 简单模型的时间表现 |
| 树模型原配置 | 当前树参照 | 同一模型在更早时间的表现 |
| 树模型去掉渠道 | 不给模型 channel，其他设置一致 | 显式依赖渠道是否有害 |
| 树模型加强约束 | 更少叶子、更大叶子最小样本、更强 L2 | 减少记忆训练细节是否有帮助 |
| 树模型不加类别权重 | 仅把 balanced 改为不加权 | 重视少数类的办法是否适合当前审核目标 |

去掉渠道叫特征消融：撤掉一个输入，看看结果怎么变。即使变好了，也只能支持“在本轮数据和配置下，移除该字段有帮助”，不能证明渠道永远没用；其他字段还可能间接反映渠道。

加强约束这一组同时改变三个参数，只能比较一套约束策略，不能分别认定哪个参数起作用。增加这组的目的不是寻找漂亮数字，而是检查一个可解释的方向。

类别权重不会凭空增加新欺诈信息。它改变损失的重视程度，可能增加召回，也可能让太多正常交易挤进高分区。最终仍用同样的每日 10 笔和 AP 比较，不能只看训练损失。

## 5. 怎样避免边看结果边改实验

先保存这两个时间窗、五种配置、种子、预算和代码版本，再开始训练。保存每组模型、分数、每日名单、训练 AP、验证 AP、分月和分渠道结果。

所有结果都留下，包括变差的、没有正例的。一次实验中没有正例的一折，不能在另一折有正例后就当作完成了两个有效的正例泛化检验。63 笔正例也可能集中于少数用户或时间，不能当作大量独立欺诈事件。

本批只是诊断，不自动选“冠军模型”，也不拿开发结果当最终验收。在完成这些检查之前，不能用更复杂网络掩盖训练与未来表现之间的差距。

## 6. 这与 Agent 有什么关系

检测器若把很多正常交易排前，Agent 就会花时间调查这些正常交易。Agent 应能查出初始怀疑缺少证据，而不是替分数编故事。但调查解释也不能反过来冒充检测器性能提升。

所以我们分别检查：模型把名额分给谁、工具查到了什么、Agent 的结论是否被工具结果支持。当前这一课负责第一件事，后面再连接后两件。

## 7. 代码和运行

`config/temporal-experiment-v1.json` 是实验安排；`app/risk/temporal_experiment.py` 管时间和对照；`app/cli/train_temporal.py` 负责运行和保存。

```powershell
.\.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider tests/test_temporal_experiment.py
.\.venv\Scripts\python.exe -B -m app.cli.train_temporal
```

训练命令会新建独立运行目录，完整运行本轮 10 次训练，不覆盖上批结果。模型和预测使用本机忽略目录，训练不花 LLM API 费用。一般先读本批结果，再决定是否需要自己重训；不用反复运行来凑次数。
