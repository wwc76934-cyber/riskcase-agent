旧 Gate 3 状态为 `WAIVED_BY_USER_FOR_RESEARCH_CONTINUATION`。旧可靠性指标、401/30014 失败和费用占用按原记录保存。当前产品默认 B0。

## 接口与执行边界

`Gate4Policy` 固定服务商、官方端点、Model ID、JSON 输出模式、费率快照、请求和时间上限。`Gate4ProviderClient.chat(messages, tools)` 把主机的抽取、报告或一次性综合合同封装为 JSON Schema。显式冻结的 JSON Object 模式仍由相同的主机合同校验。工具请求单独发送 Function Calling 声明，不和 Schema 强制输出混用。

硅基流动和火山方舟普通在线推理使用独立端点和思考参数。方舟凭据从本机 `ARK_API_KEY` 读取，端点固定在 `/api/v3/chat/completions`。硅基流动凭据来自 `SILICONFLOW_API_KEY` 或项目安全存储。旧 SiliconFlowClient 与历史试验配置沿用原实现。

每个候选只使用一个固定策略。候选控制器创建独立执行目录，SQLite 记录一次性启动和所有消费预留。请求返回后检查模型身份与 Token 用量，保存供应商返回的模型名和可用的系统指纹。缺失指纹表示版本证据不足，目录别名不能视为不可变快照。超时、HTTP 拒绝、模型身份变动和用量缺失会阻止后续请求，未知用量保留 0.50 元占用。空响应或可计费的格式异常由既有调查合同处理。

模型回复先进入既有记录器与分阶段日志。存档保留业务响应、调用、模型和用量，省略推理文本并清除凭据。已保存的模型响应由现有日志核对并重放。未知执行不重新发起网络请求，整批实测入口只接受同一个冻结计划的一次启动。证据获取、引用、时间窗、权限和评分仍由原有流程处理。

## 验证与推进

开发案使用三阶段模拟回呼场景。T1 主回呼不可得，替代渠道提供目标交易的客户声明，T2 再到达正式更正。两家适配器均用本机真实 MCP 与各自的模拟 HTTP 经过这一流程。真实候选测试先从硅基流动开始，使用独立批准、费用和结果。后续正式 B1、B4、B2 使用同一模型、推理参数和合同，并沿用冻结的四组配对计划。

## 等价 Schema 和方舟备选

两款硅基流动候选出现同类字段遗漏后，新增显式选择的等价线格式。共享对象的必填字段和额外属性约束分配到每个假设分支，分支的状态与最少证据数量照常约束。主机消息和最终校验沿用原 Schema。旧与新布局在两家协议的本机 MCP 完整轨迹及异常回归中共通过 68 项测试。三份原报告合同的 2,160 个边界样本在改写前后的接受结果一致。

方舟普通 API Lite 已准备候选提案，使用同一模拟案、等价严格 Schema 和 4,096 输出 Token。最多 12 次请求，已知费用保守上界 0.479232 元，含一次未知费用占用共 0.979232 元。该候选需要本机普通 API 凭据和独立批次授权。提案 SHA256 为 8ea6a7628f81e9d9e48e1a9af831873d76d3de0c6984eb336d7b6d5563c63958。
