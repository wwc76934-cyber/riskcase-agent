# 第八课：让模型从交易中学习，而不是替模型手写全部规则

先记住三个分工：**程序计算交易线索，机器学习模型给交易排序，Agent 调工具调查排序靠前的交易。** 我们现在完成中间这一块。训练模型不需要调用大模型 API。

## 1. 一笔交易怎样进入训练

假设某笔交易金额是 100，过去一小时发生了 4 笔交易，这个商户过去 30 天没出现过。这些是输入 X。数据另有一个“是否欺诈”的标记，例如 1，这个是训练答案 y。

规则由我们写：“过去一小时超过 3 笔，而且商户陌生，就加分。”模型则看许多历史的 X 和 y，调整自己的参数，学习哪些线索组合更能区分两类交易。输入中没有姓名或用户编号，也没有目标交易的答案。

**训练时允许用训练集答案来学习；预测时不能把答案交给模型。** 验证程序在预测结束后拿验证集答案算成绩。以后 Agent 查案的工具也不能读取答案文件。

本次模型使用金额、时间、过去交易次数和金额、距上一笔的间隔、商户是否出现过、支付渠道和商户类别等 14 个字段。它们来自已经检查过时间边界的特征快照。

## 2. 为什么先训练这两个模型

**逻辑回归：先学一套可以检查的加权打分。** 可以把它想成：金额线索乘一个权重，频次乘另一个权重，再加上渠道等线索，得到总分。权重来自训练，不是手填。

稍深入一点：先算 z = w₁x₁ + … + wₙxₙ + b，再用 sigmoid(z) = 1 / (1 + exp(-z)) 把它变到 0～1。训练要让欺诈交易的分数变大、正常交易的分数变小。二分类交叉熵为：

`L = -[y × log(p) + (1-y) × log(1-p)]`

例如答案 y=1，预测 p=0.01，会受到很大的惩罚；预测 p=0.9，惩罚小。优化器不断调整 w 和 b，降低所有训练样本的平均损失。正则化还会惩罚过大的权重，避免过度依赖某些线索。当前 C=1，C 越小通常表示正则化越强。

它的限制是：经过预处理后，主要学习加法关系。例如“某个渠道下，金额和频次共同变化才危险”的复杂组合，未必能直接学好。系数也只是相关关系，不是欺诈原因。

**梯度提升树：逐轮补上当前模型没学好的组合。** 一棵小树可以先判断渠道，再判断金额或频次；后续树根据当前损失的梯度继续修正分数。它不是把若干完全独立的树简单投票。本次使用 sklearn 的直方图梯度提升树，预先固定 100 轮、每棵树最多 15 个叶子。

先有简单模型，再有能学非线性组合的模型，才能判断更复杂的结构到底带来了多少收益。

## 3. 类别不平衡：为什么不能只看准确率

训练集有 841,892 笔交易，其中 967 笔标为欺诈。全部猜正常，也会得到很高的准确率，但一笔欺诈都抓不到。

本轮不复制少数样本、不做 SMOTE，先用类别权重：

`某类的权重 = 总样本数 / (2 × 该类样本数)`

这样每一笔少数类交易对损失的影响更大。它让模型重视少数类，**不保证实际召回率更高，更不保证低误报**。这些仍要在验证集测。

权重还改变了训练目标，所以输出 0.8 暂时只能当排序分数，不能解释成“真实欺诈概率为 80%”。概率校准需要另做实验，不能通过改名字就得到。

## 4. 数据预处理也是模型的一部分

金额和次数的数值范围差别很大。逻辑回归先对部分连续字段做带符号的 log(1+绝对值)，压缩极大值；负金额保留负号。缺失的交易间隔用**训练集**中位数填补，并另加“原来是否缺失”的提示，随后标准化。

渠道、商户类别是类别，不能假定类别编号 20 比 10 危险一倍。逻辑回归把它们变成独立的 0/1 列；树模型把它们明确标为类别，让模型按类别处理。验证阶段出现训练中没有的类别，也有预定处理方式。

最关键的边界：**填补值、均值、标准差、类别列表都只从训练集学习。** 验证集只能经过已经学好的转换，不能重新 fit。我们把转换和分类器放进同一个 Pipeline，保存和加载时一起使用，避免漏掉步骤。

## 5. 我们怎样做一次可信的实验

1. 固定数据版本和分区：2016～2017 年训练，2018 年验证，2019 年最终测试本轮不读。
2. 开跑之前保存模型参数、输入字段、随机种子、依赖版本、代码版本和文件指纹。
3. 只在训练集 fit。记录训练损失、训练 AP、训练耗时、迭代次数和收敛警告。
4. 在验证集生成分数，与已经冻结的规则使用同一排序与审核办法。
5. 保存模型、预测分数和每日审核名单，便于重新核算。不能因为结果不好就删除这次实验。

这次每个模型先跑一个预先声明的配置，不根据本轮验证结果反复修改。以后系统调参应使用更早的时间分区做滚动验证，并完整记录尝试；最终测试继续保留。固定种子有助于复现，不等于已经完成多种子稳定性研究。

## 6. 成绩怎样读

**每日只审核 10 笔：** 每天按分数取前 10 笔，一年最多审核 3,650 笔。谁在同样工作量下找到的欺诈更多，谁对这个审核任务更有帮助。这里是一天结束后的回放排序，还不是实时拦截。

**AP（平均精确率）：** 看模型在整个排序中能否把正例放到前面。计算上是在召回率提高的各个位置，对精确率作加权平均；不是把准确率平均一下，也不是任意画一条 PR 曲线后用梯形法求面积。我们同时保留 ROC-AUC，但不靠一个好看的 AUC 宣称业务有效。

还要分别检查不同渠道、训练中出现过与没出现过的用户、有无近期历史的交易。某小组只有几笔欺诈时，不能凭一次高分下稳定结论。分组检查沿用全局每日 10 笔的名单，不能每组重新发 10 个名额。

训练成绩很好、验证明显下降，可能是过拟合，也可能存在时间分布变化；需要继续分析，不能只凭一个差值定原因。我们使用合成数据，当前成绩不能外推成真实机构的欺诈识别效果。

## 7. 下一步怎样学习 PyTorch，而不只是换一个模型名

下一批建立一个小型多层感知机（MLP），沿用相同数据与审核预算。我们会亲手走通：

- Dataset / DataLoader：把输入和训练答案分批送给模型；打乱只用于训练批次，不改变时间分区。
- 张量和前向计算：输入经过线性层、激活函数，输出未经过 sigmoid 的分数 logits。
- BCEWithLogitsLoss：把 sigmoid 与二分类损失合在一起，更稳定；类别权重只根据训练集计算。
- `zero_grad → backward → step`：清掉上批梯度、计算当前梯度、更新参数；解释每步漏掉会怎样。
- `train / eval` 与 `no_grad`：区分训练和验证行为，验证时不更新参数。
- 每轮训练曲线、预先规定的停止办法、最佳检查点、重新加载后的预测一致性。

我们会让它接受同样的评测，再决定是否值得保留。学会框架与模型胜出是两回事。图神经网络需要可靠的节点、边、时间和训练切分；序列网络需要明确的历史序列。先证明这些信息对错误分析有帮助，再安排扩展。
