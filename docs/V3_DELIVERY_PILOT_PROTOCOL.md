# V3 交付可靠性开发预试

状态：待新授权。准备、回放和Mock HTTP不是付费模型实验，也不是Agent价值验收。旧90案、300条件及所有失败记录保持不变。

## 范围与冻结

仅选择6个新开发案，避开40个评测候选和有成本取证家族，隔离检查交付协议；每案预定重复2次，每次T0/T1/T2，共12案次、36阶段、最多72次请求。每阶段最多2次，分别抽取结构化事实、生成报告；失败不自动重试。重复是预先安排的独立运行，不能替代失败重跑。

每阶段发送全部当时可得的自建模拟资料及来源约束。受控短引用由宿主映射到实际读到的来源ID、行号和完整原文；宿主不补推理结论。来源说法与最终欺诈事实严格分开。

运行前冻结数据、36份输入、参考、提示构造、相关源码、依赖与账本路径。源码另存快照；任何指纹变化均拒绝继续。实际授权必须绑定提案文件SHA256；旧授权不适用。参考只在模型调用结束后用于评分，模型请求不含答案或分组信息。

## 可靠性与故障处理

两阶段之间持久保存原响应、已抽取事实、费用与代次。租约心跳维持执行权；响应返回后再次检查截止时间。输出文件丢失但数据库已完成时，仅重新导出，不重发请求。终态失败也不能通过重启恢复成新的付费尝试。

结果分别记录来源、模型协议、供应商、预算和执行异常；引用有效不代表语义正确。超时、未知费用或未知执行状态立即停止批次。只有逐笔审阅并为该案补足保守风险占用后，才允许考虑继续其他预定案件；原请求仍不得自动重发。供应商账单优先于本地估算。

全部36阶段均保留分母：至少33/36交付、至少10/12案次三个时点均交付，T1/T2目标支付客户说法至少20/24正确。报告总体与成功交付后的质量、请求/费用、延迟及恢复次数。T0不进入后两时点的正确性门槛。
