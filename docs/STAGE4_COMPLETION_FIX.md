# 冻结V1之后的完成条件修复

本文件是新运行合同 `evidence-v2-plans-advisory` 的说明，不改写 `STAGE4_PROTOCOL.md`、冻结V1源码或真实模型结果。

V1真实调用揭示了两个宿主问题：初始待办是“Select an applicable skill”，去掉Skill的条件仍残留它；宿主把模型生成的自由文本待办当作任务完成的硬性谓词。模型即使读齐原件、给出受支持结论，仍可能因复制了这项旧待办而失败。原始评分在拒绝前也没有保存已解析提议，使“没有保存提议”容易被误读成“模型没有正确答案”。

修复内容：

- 初始计划为空，宿主必需条件由实际Skill加载状态、E证据、结构结论、必要原件及缺失项规则判断。
- 自由文本计划不再是硬性完成条件；待办和未知项原样保留并生成审阅警示，报告仍进入待人工审阅状态。
- 在进行宿主完成校验前保存已解析提议，使错误结论和未满足前置条件都可审计。
- 页面展示未关闭计划提醒，工单审批仍绑定报告哈希。没有放松事实校验、工具权限或资金操作限制。

这改变了完成合同，所以不能把V1失败数直接改为成功，也不能拿原回答离线解析数当新版真实通过率。`runs/stage4-live-v1-audit/` 只做原文诊断：确认哪些答案本来就能被事实校验支持、哪些答案确实违反历史覆盖优先级。新版只做离线回归、真实MCP和浏览器验证；本阶段12次案件授权已全部使用，未继续付费。

此外，本批模型没有调用知识检索工具，不能声称完成了知识内容增益的因果验证；这说明当前规程/Skill/经验重合且工具使用缺乏激励，不能通过强制调用工具来伪造收益。真实模型下一批必须是另行授权、重新冻结的评测，不能把同三案调参后成绩包装成独立提升。
