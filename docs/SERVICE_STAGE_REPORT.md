## 现在多了什么实际能力

过去是“运行一次命令，等它结束”。现在可以提交任务ID、查状态、取报告、取消任务；接口进程与工作进程独立，任务保存在SQLite。调查仍使用既有受限工具、确定性数字计算与答案核验。

| 验收点 | 证据 |
|---|---|
| 本机HTTP服务 | FastAPI/Uvicorn实际启动，鉴权后提交、查询、下载、重复提交、取消 |
| 输入边界 | 静态案例ID、严格Schema、8KB请求体限制，拒绝重复JSON键/非有限值、任意路径与未知字段 |
| 重复提交 | 相同幂等键/输入只建立一个任务；改变输入返回409 |
| 持久执行 | SQLite事务领取、租约和代数检查；旧工作进程不能发布结果 |
| 安全恢复 | 响应先落盘，重启后校验请求摘要再回放；不重发已保存的模型请求 |
| 不确定请求 | 只有请求意图或调用异常时停止，不假定未计费，不自动重试 |
| 取消 | 排队任务不执行；运行中响应可保存，但取消优先于成功发布 |
| 报告审阅 | 绑定版本与材料摘要，过期审阅拒绝；仅接受/拒绝研究报告 |
| 工程复现 | 全新Python环境安装、依赖一致性检查、服务测试通过；已配置离线CI |

## 测试与故障演示

全仓 **487项通过**，本阶段新增33项服务/进程测试。另建全新Python 3.12环境，仅安装 `requirements-service.txt`，33项服务测试全部通过，`pip check` 未发现依赖冲突。完整ML/DL环境的重建不在这次干净服务环境验收内。

进程测试真正执行了退出：保存第2次响应后直接结束工作进程；任务保持运行状态，租约到期后启动另一进程。新进程回放2次响应，仅执行剩余2次脚本请求，最后进入待审阅。HTTP Mock另核对预算账本总条目为4，回放没有新增计费预留，第7次预留被拒绝。

测试还覆盖并发领取、并发重复提交、保存响应期间收到取消、发布前取消胜出、过期工作进程写入、请求摘要变化、响应日志/案例/报告被改动，以及跨重启的180秒期限。

最后补充一条真实客户端路径的HTTP Mock测试：首次执行后模拟过去171秒，再恢复任务；后续HTTP读取超时必须不超过原剩余9秒，不能因新建客户端重获45/180秒预算。未发送外部请求，恢复后的总预算预留仍为4条。

实际IBM合成开发案例也运行了同样的直接退出/恢复演示：2代工作进程、2次回放、恢复后2次新脚本请求，0次真实模型调用。最终3份观察、45条案例投影记录通过独立原始SQL复核，未读取欺诈标签。

全仓运行存在两条非失败警告：Starlette仍支持但已弃用的HTTPX TestClient适配，以及旧环境joblib不能读取物理核数、改用逻辑核。干净服务环境只有前一条警告。
