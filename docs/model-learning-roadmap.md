## 时间验证如何做

当前 2018 年成绩已看过，它是开发验证集，不能再次包装成全新独立验证。下一轮在 2016～2017 年内部按时间建立更早训练、更晚验证；先统计各窗口正例与覆盖，再固定窗口。比较原始输入和去掉渠道输入、较强正则化、类别权重的少量预先规定选项，记录全部结果。不要拿 2019 年判断哪组参数值得选。

上述首轮已执行：保留 2017 上半年无正例时间折，下半年仅 63 正例且集中于两个月；去掉渠道有所改善，但不足以选择最终模型。随后按 `config/mlp-experiment-v1.json` 完成 MLP 首轮，没有改变时间窗寻找好成绩。

如果较晚窗口正例过少，应如实减少结论强度或调整开发协议并登记，不能通过反复挑窗口寻找漂亮分数。模型与预处理都要在每个折的训练部分重新 fit。允许使用截至交易时已发生的无标签历史，不允许使用该时刻以后交易或待判答案。

研究成果是“发现什么变化、用什么实验检查、哪些证据仍不足”，不是保证 AP 上升。第一次两模型不调参的结果永久保留。

## PyTorch 要做到什么程度

本节首版现已落地：选中第 3 轮、从头重训，在 2018 年捕获 42 笔、未超过树模型的 95 笔。后续保留以下学习与改进标准，不因结果较弱删除该次实验。

先使用相同的表格线索做 MLP，明确预处理只 fit 训练部分。网络层数、隐藏宽度、学习率、批大小、最大轮数、早停指标与耐心值在训练前固定。若用较晚的训练期窗口早停，则 2018 年只用于该轮方案的外部开发评测；看到 2018 年结果后的再次改动必须记为新开发尝试。

每轮记录训练损失、内部验证损失和 AP，并注明损失是否加权，避免把不同权重下的数值直接比较。学习 `BCEWithLogitsLoss` 与类别权重、Adam/AdamW 参数更新、梯度清零、Dropout 在训练与验证时的差别。最后重新加载最佳检查点预测，与树模型比较同样的日审核预算、AP、误报分组、训练和推理成本。

不要求手写自动微分引擎，但要能解释一个批次的输入维度、输出维度、损失如何变成梯度、哪些参数发生更新。GPU 不是起步前提，先评估本机 CPU 的训练成本；不默认下载大模型或购买算力。

## 更复杂模型何时有理由加入

- **LightGBM / XGBoost：** 当前树基线出现可定位的训练效率或建模限制时，选一个有明确目的的对照；不同时扫大量库。
- **序列模型：** 错误分析表明事件先后关系有用，而窗口统计无法表达时，先构造严格截止时间的历史序列；再比较小型序列模型。不能只把当前一行改名为序列。
- **GNN：** 需要可解释的账户/商户关系，以及不会跨时间泄漏的图构建与采样。源内商户 ID 并非唯一现实门店，不能把 ID 共现直接解释成真实团伙。先比图统计特征，后讨论神经网络。
- **异常检测 / VAE：** 适合另问“偏离已知正常模式吗”，不等同于“是否欺诈”。要检查正常训练数据是否混有未知欺诈，并与相同任务下的简单方法比较。

先把 MLP 的完整训练过程学懂，再由证据决定后续模型，保留产品调查与规则验证的开发时间。最终可展示数据分析、规范实验、框架运用和工具 Agent 四项能力，而不是只能展示训练 API 调用。
