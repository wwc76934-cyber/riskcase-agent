# 面试讲述与追问材料

状态：2026-11-02已完成主对照和压力条件终态整理。动态Agent及方法记忆没有稳定收益证据，默认代码。见[完整结果](AGENT_VALUE_FINAL_REPORT.md)及[演示](AGENT_VALUE_DEMO.md)。

## 两分钟主线

我做的是支付欺诈告警调查系统：检测模型决定哪些交易进入人工审核名单，调查层负责组织证据和下一步核查建议，不自动认定欺诈或处理资金。

项目最初只有三个固定统计指标，直接代码更合适。我保留强代码基线，把研究问题改成认证日志、设备与联系渠道、客户声明、版本化规程之间的语义和时间关系。模型需要区分认证成功与真实授权，处理更正、资料不完整和未授权外部指令。

我实现了案件范围绑定的MCP工具、冻结的Skill、持久化假设与响应日志，以及受审阅方法的发布撤下。模型选择资料和解释，宿主控制范围、预算、来源引用与人工批准。终稿假设捕获和调查中主动改道分别计数。

我用30开发、40冻结、20挑战案例比较强代码、完整资料综合及格式修复LLM、动态Agent和带方法记忆的Agent；有单独的原始历史及错误/过时方法条件。所有首次失败保留，C层参考不进入模型，最终依据质量和成本决定是否启用动态路径。

实际60案严格通过为代码46、完整资料LLM14、动态Agent9、带方法Agent14，主模型条件180次均保留首次结果。动态路径没有可靠增益，所以默认采用代码；压力条件受预算和执行失败干扰，不能夸大记忆效果。这个项目展示的是如何构建、约束并评估Agent，以及何时不应部署它。

## 高频追问

**为什么不是固定流程？**
统计、排序、引用元数据和权限由代码做。模型承担非结构化声明理解、假设和反证组织、在资料约束下选择下一步。是否值得多步调用由B0/B1/B2对照回答，而不是凭任务名称判断。

**MCP有什么实际作用？**
两个独立stdio服务通过官方SDK提供交易与调查资料；工具有输入输出类型、只读权限、案件/主体/截止时点和费用控制。MCP负责互操作，权限仍归宿主，不把协议本身当安全边界。

**Skill是否只是另一段Prompt？**
内容本身是过程指引；工程价值在于版本冻结、资源边界和任务快照。新调查Skill只提供确实存在的资源，不会因为文字要求就授予工具权限。不宣称本轮单Skill等于复杂自主技能发现。

**Harness具体解决什么？**
任务状态、工具调用、响应落盘、租约代次、预算预约、上下文恢复与审阅提交。已用真实进程退出验证保存响应可回放恢复，新增客户端请求为0；这是离线恢复证据，不是一次新的模型能力成绩。

**引用正确是否等于结论正确？**
不等于。E证明读取了哪份原件；O是模型解释，需C参考或人工复核。代码会回填原始事件时间与来源层级，但不会把认证成功翻译成持卡人授权，也不会给模型补读未请求原件。

**Memory怎样形成，怎么避免自说自话？**
真实开发报告由控制器的预定义事实标准评估，归因时同时检查未读来源；候选绑定源报告、反馈和原件重算，再经明确发布。参考由作者定义，不冒充外部专家。新案例不复用源主体或目标交易；比较的是受控方法迁移，不是自主训练。

**为什么没有把RAG塞进每一步？**
当前单案只有少量版本化原件，直接读取是强简单方案。旧检索与LongMemEval研究保留为独立材料，不拿检索命中率冒充欺诈调查收益。检索规模和来源权限有需要时才增加复杂度。

**为什么时间线交给代码？**
选择相关事件可能需要理解，抄写时间、判断来源层级、去重和排序不应该耗费模型可靠性。原始模型选择和宿主变换都保留，覆盖评分衡量事件选择，不把排序算成推理能力。

**这个项目有什么不能证明？**
不能证明真实银行欺诈捕获、人工节省、生产安全认证或普遍Agent优势。IBM源本来是合成交易，新增调查资料是独立模拟；有限谓词评分不覆盖全部自由文本语义。
