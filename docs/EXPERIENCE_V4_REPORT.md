# 阶段二：工作台经验检索与受控反馈闭环

2026-10-23。本阶段把上一轮独立的知识工具接入实际任务与工作台，并实现有来源、有评测、有版本约束的候选经验入库。它证明经验生命周期可以运行，尚不证明真实模型调查能力提升。

## 已交付的用户流程

1. 提交调查时冻结当前已审阅经验的最新可用版本。任务保存完整知识内容与指纹；随后入库新经验不会改变已提交任务，包括尚未执行的任务。
2. 调查材料中附 `knowledge.json`，页面用可读文本展示过程参考、引用及来源。当前经验库搜索与任务冻结材料分开显示，轮询不会用旧快照覆盖当前搜索结果。
3. 混合调查与商户研究的 Agent 可以调用 `search_reviewed_knowledge`；自然语言确认后的确定性执行路径仅附过程参考，不让经验文本改变数字或已确认范围。知识查询不会增加交易访问范围，也不能生成可被事实校验器接受的 K 类交易证据。
4. 分析师拒绝报告后，可以选择历史覆盖、正金额比较或商户历史，填写失败反馈及建议经验。后端核对当前报告拒绝状态、结果 hash 与报告材料指纹，候选绑定该来源；仅拒绝计划或尚未拒绝的报告不能作为来源。
5. 候选运行预先声明的过程检索回归集：两个题组均须有改善，且任何原本正确题都不得退步。未评测、不通过、评测指纹不匹配、语料或题集已变化，均不能入库。
6. 分析师核对内容后点击“审阅通过并入库”。单次 SQLite 事务同时写入经验版本与候选状态；相同评测重复确认保持幂等。新任务可检索它，旧任务仍保留原语料。

`scope` 固定为本地研究工作台，模型不能选择其他范围或写记忆。本地访问令牌持有人是审阅者；这不是企业身份系统。反馈为分析师提交，不是已经实现了模型自主反思或自动诊断错误。

## 实现与接口

- `app/service/experience.py`：候选、来源绑定、检索评测、过期评测阻断、事务入库及任务材料导出。
- `app/tools/knowledge_tools.py`：知识快照、最新版选择、词法检索与 ReAct 工具。快照仅包含每个身份的最新可用版本，避免无效历史版本不断扩大任务输入。
- `app/service/runtime.py`：提交时冻结知识；处理任务时导出参考材料并提供检索工具；原任务日志与租约机制继续适用。
- `app/service/api.py`：所有知识读写接口均使用既有本地 Bearer 边界。候选不能由模型工具写入。
- `app/service/workbench.py`：展示来源和内容、候选审阅、评测摘要、明确入库动作；不把原始 JSON/hash 堆给最终用户。
- `config/knowledge-regression-v1.json`：公开的10道开发机制题，中文与英文题分组；不是未见测试集。

接口为 `/knowledge/search`、`/knowledge/candidates`、`/knowledge/candidates/{id}`、`.../evaluate`、`.../promote`。入库必须提交当前评测 hash，并重新核验反馈来源与语料基线。

幂等边界：同一提交键且知识库未变时重复提交返回原任务；知识库发生变化后继续复用旧提交键会冲突，调用者应查看原任务或为新知识版本创建新提交。不会静默把旧任务切换到新语料。

## 实测结果与失败

### 离线闭环与检索门槛

完整执行“调查→模拟分析师拒绝→候选→评测→入库→新任务”。手写覆盖经验加入后，10题 top1 检索/拒答正确数从4变为6；两个题组各从2/5变为3/5，原本正确题没有退步，故满足门槛。其余金额、商户题仍失败，不隐藏未建设的知识。

这些题公开，候选直接包含相应关键词，空库对照也很弱。**4→6只能说明门槛和机制接通，不能宣传为语义泛化或 Agent 推理提升。** 模拟反馈所指报告不代表模型真的犯错；离线演示明确标注为人工机制材料。

反例测试验证：无增益的经验、污染无答案题的经验、并发入库后已过期的评测均被拒绝；第二版本能够替代旧版，排队中的旧任务不读新经验；知识引用不能作为交易事实引用。

### 真实模型小对照

经用户明确授权，在同样提示、预算与4个自建问题上运行空库/入库后两组，共8组、16次真实请求。只发送过程问题和手写经验，不发送真实个人交易数据。

**8组均在严格 JSON 解析阶段失败，未形成有效的答案质量对照。** 请求成功返回与完整任务成功不同，不能拿检索命中证明回答正确。全部失败结果和费用回执保留。

本轮还发现实验脚本仅在解析成功后保存回答原文，导致首次运行缺少失败原文，无法独立判定具体输出格式原因。这是实验记录缺陷，已修复为解析前保存原文与消息，并补充 Mock 回归；没有补造原始文本，也没有追加付费重跑。后续提示明确写出 JSON 首尾字符与禁止 Markdown，尚无新的真实调用验证该修订。

费用按项目冻结费率与平台 usage 的本地估算合计 **0.049384元**，低于本次授权最多估算2元。无未知费用请求；这不是平台账单对账。失败前置审批已在用户明确授权后解除，本阶段没有待授权的费用操作。

### 测试与浏览器

- 全仓回归 **741通过，0失败**，192.11秒；有1条既有 Starlette/httpx 弃用警告。
- 后续补充版本快照及失败原文留存测试，并修正页面后，针对性回归 **17通过**。后续没有重新把它称为“全仓743通过”。
- 真实无头浏览器通过：拒绝报告→保存候选→运行回归→人工入库→当前经验检索；无页面异常、无外部浏览器请求，390px窄屏无横向溢出。
- 浏览器首次断言早于异步材料加载而失败，原回执保留；修正等待条件后通过。随后把原始 JSON 改成面向审阅者的摘要，并再次通过浏览器检查，截图已人工查看。
- Windows沙箱内 asyncio 的既有环境限制沿用上阶段处理方式：测试服务与浏览器在获准的沙箱外运行。未通过删测试或禁用权限校验来获得通过结果。

机器回执与内容指纹见 [experience-v4-results.json](experience-v4-results.json)。原始材料分别在 `runs/experience-v4-stage-01/`、`runs/experience-v4-live-01/` 与 `runs/experience-browser-v4-02/`。

## 运行与演示

使用原本的本地工作台命令即可看到知识与经验面板：

```powershell
.\scripts\run_project.ps1 -m app.cli.workbench
```

首次库为空。选择一条报告，拒绝后填写反馈与建议，运行检索回归，再审阅入库；不能把“拒绝”当作事实错误的自动证明。

独立复现免费机制演示：

```powershell
.\scripts\run_project.ps1 -m app.cli.experience_demo --output runs/新的经验演示目录
```

该命令不调用真实模型。`--live` 会发送过程文本并收费；本轮真实实验已结束，不应为获取漂亮数字无条件重跑。

## 面试中可讲与不可讲

可以用具体失败和边界解释 memory：对话缓存与长期经验不同；长期开库不是全部塞进上下文；知识可得时间与交易事件时间不同；当前版本、任务快照、来源和审阅是不同合同。能够实际演示更新后的经验只影响新任务、过期评测不能入库、RAG 内容不能替代事实。

不能称“自进化已经提高智能”。当前是分析师反馈驱动的经验迭代，检索门槛无法判断语义真伪，文本甚至可能在指标不退步时包含错误内容，仍依赖人工核对。当前门槛还不能批准不改变检索成绩的纯内容纠错；需要独立语义/任务评价后再扩展该路径。

没有向量检索、reranker、学习式记忆筛选、自动遗忘或完整知识回滚产品流程。主自然语言流程仍是范围分类与确定性执行。下一步核心应是修好可审计的真实模型评测、设计需要逐步决策的调查任务，并测量检索、记忆与固定流程的端到端增量，而不是继续增加名词。
