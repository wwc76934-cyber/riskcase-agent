## 时间、身份与标签

发布九列无用户ID、会话ID或绝对交易时间；整数index不是可验证用户身份或时间。times作为动作间隔解释来自论文与代码，不能把其累加值当跨交易日历时间。没有label_available_at、报告日或结案日；不能构造每日Top10或严格时间外推，也无法证明train/test用户互斥。

作者说明样本来自一家欧洲银行，收集期2020-02至10月；先抽无已报告欺诈用户、以至少12笔过滤，再追加欺诈相关用户。该按全观察期标签与活跃度选人方法改变人口/类别构成；不能把样本比例解释为真实银行总体欺诈率。论文摘要的人数与正文“2000＋97”口径需保留差异，发布文件无法重建真实实体数。

正例由员工确认；作者明确承认存在漏报/未报告欺诈。标签0不等于经调查证明正常，101不是完备的真实欺诈总量。标签延迟、负例成熟窗口未知。不得给现有0标签擅自补确认日期，或把所有未报告当可靠负例。

原论文60/20/20分层及Monte Carlo重复划分未声明按用户分组。可存在同用户行为、共享序列及时间近邻跨集合的关联风险；这是风险审查，不是已证实某条测试样本泄漏。词表TF-IDF应仅拟合训练池。发布RFM和时间量的生成是否完全as-of、标准化/异常分数是否可重建，当前不能从原始日志独立验证。

## 初筛输入合同

动作只允许截至目标交易请求时已经发生的事件；末尾动作若包含响应结果/成功状态，须先有词典与采集时点证据，否则剔除或限制为事后分类。Amount是请求金额候选；execution_time和总完成时长默认排除，因为可能到响应后才可知。四个频率特征仅作为发布快照探索性对照，未证实合法历史生成前不得宣称实时可部署。is_fraud、由它生成的Transaction Type、序号、拆分标记、事后结案文本都不得入模。

作者notebook确实构造Transaction Type标签字符串，且times预处理与总时长存在单位换算需要独立核对；绝不能把notebook新增列全量选进特征。词典翻译只能描述已知API操作，不能把/cards/fetchcards解释成“盗卡”，或擅自添加设备异常、持卡人未授权、账户接管结论。

## 第一轮六问的结论

1. 有真实银行来源及真实操作序列的发表证据，发布字节可审计；**目前不满足本项目训练准入**，许可及可信分组/时间评测仍有缺口。
2. 行为是否超越RFM：尚未在本研究验证，不能拿论文结果充当本轮增量；方案见BASELINE_PROTOCOL.md。
3. 普通NLP基线必须很强：按原文纳入1—3gram TF-IDF、SVM，以及TF-IDF＋RFM的LR；不以随机小网络作为唯一参考。具体性能须本轮重算，当前没有成绩。
4. LLM可能提供稀少事件间的概念共享，但这是待检验假说；同文本TF-IDF、事件Embedding、随机冻结、词典置乱及顺序对照是必要排除项。
5. 101正例只支持有界探索：60/20/20约61/20/20，测试多捕获1条约改变5个百分点Recall；以20正例捕获10条为例Wilson95%约[0.30,0.70]。重复seed不是新增正例，重复划分也不是独立复现。缺用户ID时逐行bootstrap不能替代用户簇不确定性。
6. 优先寻求作者明确数据许可与保留稳定匿名用户键/绝对时间的合规版本；IEEE-CIS仍需官方权限与字段可解释性审核。MS-FFSD沿用V2.1标签派生文本风险，不自动准入。可用明确模拟的银行操作流验证机制，但不能称真实数据收益。没有已经核验、同等严谨且更适合语义的直接替代品，不为继续训练而随意换源。
