# 原始案卷 V3：失败驱动修复与复验合同

本协议晚于 V2 真实实验，不能替换原协议或改写原始分数。

## V2实测暴露的问题

全部资料输入：24/24事实值正确、5/6决策正确，但只有9/24主张包含原先约定的完整来源行，6案全项均未通过。动态取证：6案全部在工具预算耗尽时停止，没有最终答案；少读资料不能算效率收益。31次真实请求估算0.806532元，项目累计估算10.949564元，12案批次已经用完。

## V3改动

1. 原件目录显式标注来源角色，支持按身份映射、清算、退款操作、退款台账过滤；不会提前给出数值或结论。Skill要求先关联支付编号，再查资金原件，避免物流/费用附件和重复搜索消耗预算。
2. 引用完整性从评测隐藏要求提升为公开宿主合同：扣款笔数需身份映射+清算，净额需清算+退款台账，退款状态需操作记录+退款台账，覆盖需清算。检查来源类型不能证明行的语义，仍然需要原文审阅。
3. 可信规程目录附加一个有限一致性检查 `net-restored-v1`，绑定政策正文哈希：覆盖完整、无声明缺口且净额等于分析师提供的订单金额时，核对所提行动是否与“净额已恢复”条款一致。不是通用规则执行器，不执行文本代码，不认证模型提取的金额正确。
4. 最多一次显式草稿校验反馈，指出缺少来源角色或规程一致性问题；不返回金标准或正确事实值。原始草稿与问题均记录，模型负责修订。该次请求计入原6次上限，不能在预算外重试。需分别报告首次草稿及最终结果。
5. 原始案卷工具预算耗尽时，取消尚未开始的动作并禁用后续工具，在剩余模型预算内给一次最终汇总机会；不越过工具上限，也不凭空补证据。不足则请求资料或失败。
6. 新产品入口 `DossierService` 对小案卷默认使用全部资料路径；动态路径需明确选择。两组复验仍保留同样预算和校验，不能为动态组增加资源。

## 复验范围和判定

继续使用原6个已观察案例×2路径，事实原文和金标准不改，只增补公开来源角色、订单输入及规程校验元数据。这是**已观察案例的修复回归**，不是独立泛化测试。

保留原5/6全项通过、事实值至少90%、不得关闭覆盖缺失、规程反事实对正确的演示门槛。引用完整性不得靠宿主伪造模型引用；模型必须实际输出来源和行号。首次草稿、一次反馈后的成绩、模型次数/费用/延迟分别记录。任何反馈不能替代人工语义确认。

新的付费批次需要新授权：最多12案、72次模型请求、估算2元，继续受项目20元总账限制。旧批次尚余的金额不是继续请求的权限。先完成离线及真实MCP校验，再申请并执行。若未达标，不把目标标记达成。
