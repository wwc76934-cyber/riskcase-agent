## 数据与评测合同

- A层来自已核验IBM合成交易及原检测输出，检测权重和既有最终评测不变。B层必须逐条标记独立模拟来源；不能称设备/客服资料来自IBM。
- B层每份原件有来源ID、主体/交易键、事件时间、available_at、来源类型、覆盖与版本。案件调查as_of与原交易事实截止分开：后来可得的客户反馈可以用于事后调查，但不能冒称交易发生时已知。
- C层保持在控制器侧；运行时快照不含情景家族、预期结论、关键证据列表或评分权重。工具不能通过路径参数读取评分文件。
- 案例的差异必须来自不同证据组合、语义机制、叙述格式、时间关系或适用规程，不能只换ID/金额。冻结/挑战结果不得反向用于修改当前提示或案例。
- B0执行充分的确定性证据包和保守规则。B1读取全部当前可用且获授权原件；B2/B3具有同样访问能力，不能靠扣留B1材料制造优势。资料逐步到达时，各组在同一可得时间接收同批资料，更新成本全部记录。
- 评分允许合理的不同取证顺序。路径响应性作为单独指标，不能强迫唯一“正确”轨迹。引用有效不等于语义正确；认证成功与客户否认也不必然是逻辑矛盾。
- 综合Q及权重在运行前冻结，同时公开各分项、安全错误、成本和延迟。空缺、失败、预算耗尽计入分母。
- 没有独立专家时，反馈注明程序事实标准或开发者审阅，不包装成外部专家。没有实际分析师对照时不报告节省人时。
- 记忆使用单独的新案例；同时报告适用经验迁移、重复错误、错误污染与过时拒绝。程序发布校验通过和模型读取成功不是增益指标。
