## 当前最容易被追问的缺口

- **Agent必要性还不充分。** 研究规程小且确定，代码可以覆盖；即使真实模型通过也不代表值得使用。下一轮价值验证应引入真实分析师的问题和资料分布，比较任务质量、耗时与审阅负担。
- **原始资料分布仍窄。** 旧路径预结构化程度高；新路径确实读原文并提取金额/状态，但材料仍是作者构造的短文本，尚未覆盖不同机构格式、OCR、自然语言歧义、长账单和真实专家诊断。
- **经验空间过窄。** 当前只允许三条核查方法重排，容易验证但无法覆盖开放知识演进。扩展需要来源质量、语义回归、过期策略与人工审阅，不是直接允许模型写Skill。
- **知识与事实有重合。** 目前规程、Skill、经验存在冗余；消融要判断是否增加成本却没有增益。不能因为组件齐全就认定每个组件应默认开启。
- **语义仍需人工核对。** 新案卷已用结构化主张替代自由摘要，宿主检查来源角色、完整台账及有限一致性；这不证明主张从原文正确推导。旧路径自由摘要也仍可能失实，不能让另一个模型打一分就宣称已解决。
- **真实部署条件欠缺。** 单机SQLite、可信本地技能、同一访问令牌、模拟工单尚不足以覆盖企业租户、秘密管理、远程授权、访问撤销、容量与延迟SLA。
- **模型与数据泛化欠缺。** 检索阈值已看过开发题，风险检测2019已观察，本轮场景由开发者按既有规程生成。未来进展需要新的评测条件，不靠更换命名或多报测试数。

优先顺序应由证据决定：先找到固定流程确实处理不好的任务，再扩大Agent决策空间；同时把有害输出和不可恢复状态压住。图框架、更多Agent、向量数据库和更新模型只有在解决明确瓶颈时才值得加入。
