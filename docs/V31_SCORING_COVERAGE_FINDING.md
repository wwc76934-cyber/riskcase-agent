# 参考覆盖与模型事实错误不能混同

2026-11-04，检查当前真实复验的已保存结果时发现。当前批次仍执行原冻结评分，**不改代码、不改参考、不重写任何原始分数**；本记录只是另存诊断。当前交付/客户状态准入阈值不受此发现改变。

`v3_score.score_stage` 的作者参考只列认证及客户授权观察。模型合同却也允许规程版本、客户撤回、设备或账户等谓词。当前实现将任何不在 `expected_observations` 中的事实视为不正确，再用“全部事实均正确”决定严格通过。这会把“参考未覆盖”与“事实已被反证”混成一类。

具体例子：开发案 `v3-10476d72a749a8ba01` 的第二次重复T1，原评分为4事实/2正确、严格未通过。F1认证成功、F2客户未知均匹配；F4规程版本1由实际所选规程来源的版本元数据直接组装，却由于参考没有policy_version观察而被列入wrong_fact_ids。F3 customer_retraction=unresolved同样没有参考键，但它是否应当输出仍需单独判断，不能借此自动认定正确。

因此当前 `fact_accuracy_given_report` 应准确称为**有限作者参考匹配率**，不能宣称是全谓词事实正确率。当前严格成绩按原定义如实保留，但不能把该成绩中的每个失败都解释成LLM业务推理错误。也不能删除额外事实或临时扩充答案使本轮“胜出”。

后续新版本评分须在新实验之前冻结：

1. 区分参考内匹配、参考内矛盾、参考未覆盖、确定性来源元数据验证、结构来源失败。
2. 对未覆盖事实保留逐项人工/语义待审状态，不能默认正确，也不能一律叫错误。
3. 分开任务范围的严格通过与全报告所有断言的语义正确性；后者未审阅时不得宣布通过。
4. 给policy_version等确定性字段单列来源一致性，不把宿主复制元数据算成LLM语义能力。
5. 继续将未交付、跨交易、未读来源、越时点、缺关键证据及危险建议计入相应全样本失败；不得以缩小评分范围掩盖这些错误。

旧90案、原V3预试、类型化修复及本批V3.1的原成绩全部保留。未来若离线重评分，必须另存实现/参考版本、逐项变化及新旧对照，不能替换原成绩或称独立新实验。
