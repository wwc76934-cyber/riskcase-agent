# 第十七课：让模型提议，程序验证，审批另外负责

本批已实际跑通：**已验证调查 → 模型选择候选模板 → 证据校验 → 生成受限规则 → 冻结 → 开发集回放**。密钥从 Windows 专用条目自动读取，两次真实操作都没有要求重新输入。

先理解三个角色：模型负责提议，程序负责计算和检查，人负责决定是否采纳。现在前两部分已连接；人工审阅仍只是“未批准”状态，没有完整审批功能。

## 1. 先补做了正常场景对照

开发题 normal_seen 中，交易金额没超过历史最大值，商户此前见过，一小时也不频繁。固定流程和真实模型均正确回答三项，不把模型预警分数当作欺诈证据。

两边都查询 4 次。固定流程没有模型请求；Agent 使用 3 次 API 请求，本轮估算 0.036092 元。这个单题不能证明模型的成本或查询优势。它是手工开发题，不是独立保留成绩。

运行目录：`runs/comparison-live-v1-7ca925d807d2`，材料、答案、引用与 usage 估算复核通过。

## 2. 模型现在可以提出什么

我们把此前已经验收的一笔 IBM 合成交易调查交给模型，允许它从有支持证据的模板中选择、组合，或者输出 abstain（不提规则）。模型拿不到原始标签、开发回放成绩和标准答案。

例如，它看到本笔 803.34 高于过去最大正金额 488.48，同时该商户近期没有出现过。可供考虑的模板包括：

- 全局大额模板：金额大于冻结的训练集阈值 32990，即 329.90 个源单位。
- 未出现商户模板：三十天覆盖完整、有用户历史、该商户没有出现。

这里有一个容易混淆的地方：**本笔超过个人历史最大值，不等于“全局金额阈值有效”。** 前者只支持提出一条怀疑，后者的阈值来自过去训练数据，是否有群体收益仍必须回放。这两个比较不能偷换。

模型只输出 decision、template_ids 和 evidence_ids。程序核查所选模板是否确实提供过，每个模板是否引用支持证据，再生成真正的规则 JSON。任意标签字段、SQL、额外参数、伪造引用、超过四个条件或部署指令都不能通过。

这仍然是模板选择与组合，不是自由发现新风控策略。普通代码也能组合模板，所以这条链路接通还不足以证明模型不可替代。后续要靠更丰富的任务和严格对照检验。

## 3. 真实调用发生过一次失败

首次候选运行 `runs/proposal-live-v1-263f5f2ee526` 被拒绝，没有回放。模型的 JSON 内容合规，但外面包了一个 Markdown 代码框。原始失败记录保留，没有改成成功。

随后补了接口格式适配：只有整个回答恰好是一个完整 json 代码框，才去掉外壳；带其他说明文字的回答仍拒绝。去掉外壳以后，完整的模板、引用和规则校验照常执行。保留原始回答，并记录 single_json_markdown_fence，不额外请求模型来纠正格式。

修复通过测试后，另做一次单请求验证。两个运行各只有一个请求，没有自动重试，也没有把开发集标签结果反馈给模型反复优化规则。

## 5. 当前模型有没有“看结果再修改规则”

没有。模型只收到已经验收的调查证据和可选模板；开发集标签由独立评测程序打开，回放指标保存在工作流结果中，没有再次发给模型。这避免这一版不受控地试很多规则、挑出漂亮的开发成绩。

因此现在不能声称模型已经能解释群体回放代价或自动优化策略。下一步先补候选版本、审批记录和材料一致性，再逐步增加有预算的多任务评测。允许模型读取聚合评测结果时，也需要记录它已经见过哪些开发反馈，不能再拿这些任务充当独立考试。
