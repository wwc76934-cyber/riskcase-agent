# 第四阶段评测合同（运行前固定）

目的：测量证据调查的正确性、完成可靠性、工具成本及组件增量；同时说明当前项目的工程边界。不能以脚本或检索成绩替代真实Agent成绩。

## 场景与分组

60个自建合成场景：12个场景家族，每家族5个变体；按家族分为20个开发、20个回归、20个冻结审计场景。家族不跨组，快照和答案单独保存；答案仅供评分器使用。冻结审计是运行前固定的内部审计，作者了解业务规则，不称外部独立测试或未知分布泛化。

覆盖单次/多次清算、商户佐证/反驳、历史与清算缺口、处置缺失、时间边界、旧版本干扰、提示注入和多条件优先级。旧阶段已观察资料不重新命名为留出。

## 对照与消融

| 条件 | 说明 |
|---|---|
| fixed_code | 固定查全部来源，代码按证据判定；非模型 |
| basic_agent | 同一个模型，通过基础工具循环取证；无Skill、跨案知识或持久调查Harness |
| full_agent | 同一个模型，实际Skill/Harness/知识工具路径 |
| no_skill | 仅去掉Skill正文、目录、加载工具与加载前置条件；保留其他治理 |
| no_knowledge | 仅去掉知识/经验工具及其内容；保留Skill和Harness |

离线60场景先用明确标记的代码客户端对所有路径做合同验收，批量场景使用与MCP共用的工具源适配器，不能称60次真实MCP互操作或模型能力评测。另运行真实stdio协议抽验和进程故障检查。组件消融不会关闭权限、审批、事实校验或预算。

真实模型批次计划：从冻结审计组的“注入干扰商户反驳、历史缺失与重复授权并存、商户确认与多笔清算冲突”各取第一个变体。三案×四个模型条件，共12次案件运行；每次最多6请求、12次工具尝试，最多72请求。相同模型/温度/快照/结论合同；按轮换顺序运行条件。选择在观察其运行结果前固定，失败不替换案例。

这只能提供3个配对案例的描述性对照，不能作统计性优越结论。真实模型需要用户对本阶段单独授权：最多估算2元，仍受项目20元总账限制；项目当前估算累计8.973584元。材料只包含合成案例、规程和已审阅通用经验。预算/网络结果不明时停止后续调用；已完成与失败原文均保留，不自动重跑失败。

## 指标与冻结规则

- 结构结论、必要原件覆盖、引用有效、缺失项、宿主验证通过分别记录；成功要求全部通过。
- 统计全部运行，失败不能从分母移除；同时保留被宿主拒绝的模型原始提议。
- 事实工具与宿主工具次数分开；记录请求、时间、费用、拒绝调用、重放与恢复。
- 文本摘要只列复核状态及明确发现的问题，不自动认证语义正确。
- 保存每次请求/响应、模型用量、源文件哈希、场景哈希、工具轨迹。基础循环也保存请求，不只保存最终回答。
- 开始冻结审计后不调参；发现实现缺陷时保留原结果，修复另开协议版本，不能覆盖实验。
- 故障合同包括未知工具/越界、超时/超长结果、日志损坏、响应不明、中断恢复、旧worker fencing与重复提交；不声称远程企业认证或真实外部系统 exactly-once。

交付：评测命令、机器结果与可读报告、场景清单和版本锁、面试讲述与尖锐追问、从预警到审阅和故障恢复的演示路线、真实能力与未实现边界清单。此前深度学习源内实验继续引用原报告，不重算已经看过的2019为未见测试，也不把检索编码器包装成风险检测升级。
