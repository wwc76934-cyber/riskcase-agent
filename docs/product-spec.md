## 产品问题

目标用户提案：做初步公司研究的研究助理，需要把财务变化和管理层披露连接起来，并核查依据。尚未完成真实用户访谈，效率收益属于待验证假设。

目标工作：给定公司、两个报告期、资料截止日和研究问题，定位年报财务事实，检查口径，计算变化，寻找披露解释，输出可以复核的研究底稿。人工复核应能直接找到原文、输入事实和公式；证据不足时保留缺口。

产品边界：第一版支持满足既定输入条件的 A 股非金融企业中文文本型年度报告。扫描件、银行/保险的专用财务口径先返回不支持或人工处理提示。支持边界由文档验收确定，不承诺全市场任意 PDF 通用解析。

宁德时代仅为开发样本，不允许在业务逻辑、提示词或财务字段映射中硬编码该公司及其结论。

参考项目核查与路线选择见 [参考项目评估](reference-project-review.md)。推荐独立实现证据驱动的基本面研究 Agent，以 Dexter 研究循环、TradingAgents 状态与流程、FinanceBench 证据标注为设计参考。冻结最终排期前先验证第二种年报格式的解析、自动事实提取与真实任务成本；不将公开项目 README 声明当作已复核性能。

## 产品级用户任务

1. 财务变化核查：收入、成本、归母净利润、经营现金流等基础事实；同比、综合毛利率及其百分点变化等确定性指标。指标数量在数据可靠性通过后增加。
2. 经营解释研究：对“利润与收入变化为什么不同”等问题检索经营分析和相关附注，区分计算可见变化、公司披露解释、模型假设与证据缺失。
3. 证据追问：用户问某结论依据、口径或更正情况，系统在同一 run 的事实和证据中定位或补充检索；无法回答时明确说明。

财务数值与引用验证是强制步骤，不能由 Agent 自行跳过。不把相关披露直接当成已证明的因果关系。

## 输入、执行与交付

CLI 输入公司标识、两个年度、截止日与问题。支持显式导入官方 PDF，随后建设单一来源的资料获取适配器：下载限定到登记的来源，失败时保留诊断和导入入口。真实下载、离线回放和人工资料导入分别标记。

链路：获取与登记 → 解析并保留页码 → 分章节检索 → 候选事实提取 → 单位/期间/口径核查 → 确定性计算 → 补充证据检索 → 结构化分析 → 验证 → 渲染。

输出：研究简报、结构化事实与计算、原文定位、证据缺口、验证结果、运行轨迹。保存 run_id、配置、资料哈希、解析器/提示词/公式版本、调用和费用记录；提供同快照重算和失败诊断入口。模型文本可能不逐字一致。

人工标注的金标准和模型运行输入隔离。初期辅助输入必须标为人工参与；最终自动提取质量须单独评测，不能用人工录入结果代替。

## Agent 的实际职责

模型在受限工具之间选择下一步：搜索哪个章节、请求哪些事实、使用哪些已实现指标、是否需要进一步检索、何时因缺证据结束。工具入口以受控文档/事实 ID 为主，不暴露任意命令。

例如初次检索未找到现金流变动解释，可以改写关键词并查现金流附注；遇到两期数值冲突，可以核查上一期比较数据及重述说明。这些自适应步骤是待实现和待评测能力。

保留固定工作流基线，使用相同文档、模型、工具与预算条件比较。不能仅因为存在工具调用就主张 Agent 比固定流程更好；若未获收益，报告结果并保留适合固定流程的任务设计。

## 成为完整项目的验收门槛

| 门槛 | 证据 |
|---|---|
| 跨公司可用 | 3–5 家公司、至少两个行业、各两期报告；至少一家冻结为保留样本，不为它修改提示词或解析规则 |
| 真实数据链路 | 来源、披露日、获取时间、原始哈希、版本与页码；一个获取适配器及离线回放；记录许可范围 |
| 数字可信 | 每个输出数字能回到事实与公式；期间、单位、合并范围、重述、零/负基数测试；自动抽取单独核验 |
| 结论可核查 | 区分事实、公司披露与推断；对关键解释人工评估引用支持和无依据推断 |
| 可恢复和可诊断 | 网络失败、损坏文件、坏参数、迭代/工具/时间预算、有限重试、取消和结构化日志；文档指令不能越过权限 |
| 有评测 | 按公司/文档或证据簇划分开发和保留集；约 40–60 题；原始成功数/总数、失败例、时延、成本与基线比较 |
| 有使用价值证据 | 同一问题人工与系统辅助各完成一次，记录耗时、修订与错误；条件允许时由另一位使用者试用。单人测量只作探索证据 |
| 可交接 | 新环境安装、离线演示、自动测试/CI、架构与决策记录、示例报告、运行与失败说明、课程来源与贡献边界 |

这些是目标，不是当前能力或结果。3–5 家和小型评测只能支持有限范围结论，不能证明全市场覆盖。

## 实施顺序与止损

1. 保留已完成的独立基线与协议教学；下一批建立通用文档/证据/事实模型，并跑一个指标。
2. 完成宁德时代纵向链路，接入第二家公司，暴露解析和口径差异；这只是内部里程碑。
3. 完成自适应检索与计算工具、报告验证、运行状态与资源限制。
4. 冻结核心规则，再引入保留公司与评测，建立使用价值和基线对比证据。
5. 整理 CI、复现、演示和面试材料。若自动解析进度不足，收缩声明的文档支持范围，不能静默用人工答案维持成功演示。

估计投入讨论区间为 60–80 或 80–120 小时，不是完成保证；实际排期取决于解析难度、学习速度和资料可得性。保持每个知识批次讲解、用户运行、复述、测试和提交的节奏。

20 元真实模型预算继续有效。开发使用 Fake/HTTP Mock；扩大的离线评测集不等于全部完成真实模型评测。先按实际 usage 和单价测算，再确定能执行的真实评测数量，明确区分离线工程测试与真实模型结果。

## 不作为质量替代物

不以多 Agent、向量数据库、Web 前端、交易执行或模块数量作为验收标准。若引入新技术，需指出已遇到的瓶颈以及与简单方案的比较结果。

面试中可以讨论项目意义、设计和局限。目标是让回答有证据，而不是保证没有人质疑。简历只写实际完成、测量和理解的能力。
