## 排序与缺失

- 全文件有效相邻记录时间倒退 5,789 次；同一用户在源读取顺序中时间倒退 3,935 次；用户没有跨多个不连续块重新出现。
- 这些计数不证明记录错误，也不直接证明具体的卡内排序；但足以否定“文件天然按用户时间排好”的假设。后续将实体与事件时间显式排序，跨卡汇总时尤其注意。
- Errors? 空白 23,998,469 行、Merchant State 空白 2,720,821 行、Zip 空白 2,878,135 行。尚未逐项验证缺失原因，不把它们统一填 0，也不因这些可选字段为空删除记录。
- 负金额不能直接称为退款，空 Errors? 不能直接称为坏数据；要分别核验字段语义。

## 本批没有完成的检查

业务重复、商户键与位置一致性、金额分位数和长尾、缺失分群、逐字段预测时点可得性、标签确认与入库时间、真实数据外部验证。本批不输出“数据完全干净”或“已经可以上线”。

## 下一批开发合同

1. 先固定不使用欺诈标签的用户抽取规则、时间边界和历史预热区间；不能根据本报告的正例用户名单挑样本。若正例不足，扩大整体范围。
2. 在该样本中保留完整源内历史，检查业务重复候选、卡与商户字段语义、缺失及金额分布。重复候选先报告，不盲目删除同金额同时间的合法重复消费。
3. 冻结训练/验证/保留时间段及指标口径。避免把 2020 无正例段用作唯一检测测试；本轮全源标签计数用于适用性验收，后续不反复窥探保留集调参。
4. 在训练/开发部分分析特征与标签关系，再建设窗口特征与规则、逻辑回归、一个树模型。Errors? 暂不进入初始授权前模型；Agent 不读取目标标签。
