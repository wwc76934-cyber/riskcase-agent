# 第五阶段：原始案卷与可验证价值

2026-10-30。目标是补足 Agent 必要性、原文理解、规程检索实际参与和可审阅输出；不以组件数或单元测试数验收。

## 任务与范围

从订单、收据、支付映射、清算原始行、退款邮件及独立退款台账，提取实际入账次数、净扣款、退款状态和覆盖范围；按事件日期适用规程给出调查建议。原始文本没有 `verdict`、`history_complete`、`settled_debits` 等预计算答案字段。客服/商户声明可能与独立记录冲突。

12例均为作者自建合成材料：6例开发，6例预先固定的内部审计。后六例改用叙述式金额和状态，仍共享业务家族，**不是外部标注、独立留出或真实客户收益证据**。相同事实/不同渠道规程的成对案例检验是否实际使用规程；不跨分组拆开该对。

## 公平比较

- `all_context`：宿主确定性读取所有可用原件及适用规程，加载同一Skill，一次性供模型判断；没有刻意降低质量的提示或不完整资料。
- `adaptive`：同一模型/Skill/输出合同/审阅标准，由模型搜索、阅读、追踪引用并检索规程。
- 两组均最多6次模型请求、12次工具尝试、30KB上下文；输出最多1024 tokens。所有有效资料在全部上下文组的预算内，不人为撑爆基线。
- 不强求复杂方案获胜。若简单方案更好，小案卷默认选简单方案；只有实测收益支持时才推荐动态调查。

事实、规程的作用分开：工具仅执行权限、范围、时间版本过滤及原文检索；宿主验证引用存在、行范围、值类型、声明不完整时不得关闭。宿主**不持有金标准，不认证模型对原文的语义理解**。无自由摘要，审阅页直接展示结构主张和原文。人工审批仍是外部动作的前提。

## 预先固定的评分与门槛

逐案检查四项事实值、每项必要原文行、适用规程、缺口和最终决策，拒绝/格式错误/超预算均保留在分母。记录模型调用、费用、原件读取、检索次数、耗时。原文行数仅是审阅负担代理，不能换算节省人工时间。

候选演示验收：6例真实模型至少5例完全通过；不得将覆盖不完整的案例建议关闭；事实值正确率至少90%；政策反事实对两例均正确。若任一条件不满足，结果仍为开发中的调查助手，不宣称可靠。

Agent增益另行判断：动态组在不降低任务质量的条件下，减少原件读取至少20%，同时完整报告增加的模型请求/费用/延迟。仅减少读取不足以宣称整体更高效；若静态组更便宜或更可靠，明确推荐静态路径用于小案卷。无法凭6例推断总体统计优势。

## 实验治理

离线使用明确标注的 `gold_assisted_contract_fixture_NOT_PERFORMANCE`，只检验接线、合同和故障，不作为任何准确率。先进行真实MCP协议验证，再申请具体付费批次：6个固定内部审计案例×2条件，最多12次案件运行、72次模型请求、合计最多估算2元，受项目20元总账限制。此前授权已用完。
