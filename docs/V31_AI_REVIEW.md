# 40案AI作者复审记录

2026-11-04，用户提出由开发Agent代为审阅。本记录是同一开发Agent的作者复审，**不是独立人员审查、不是专家真值、不是盲标注**。没有填写人工身份声明，没有导出伪造的人工通过回执。原版数据、参考、评分和历次失败均不修改。

范围为v4候选40案，数据指纹 `f8af041607e6f3c94c6f689f0f00f7db0f4ca18cf6876c73f3242fbd37a89329`，审阅包指纹 `6cebf83ff80c3281096d457f9973afb2b177bb8a64b3dd16749ea2418090dc5d`。逐案阅读客户及账户原文、三个时点的目标声明参考、取证依赖、费用、延迟、关键来源；另外核对全部认证/规程文本及公共建议/停止规则。没有将评测候选发送硅基流动，没有新增模型调用。

结论：这些材料适合作为作者构建的语义和协议测试，**不建议直接用来宣布Agent业务价值成立**。逐案状态判断大部分有原文依据，但任务机制和业务验收过窄。后续不得把这次已读、可能用于修改的材料称为未见盲测。

## 跨案例问题

1. **动态规划收益辨识不足。** 前30案全部所需原件免费、没有查询依赖；大部分是两段客户声明的解释。强B1/B4足以处理并不是缺陷，问题是不能用这些任务的结果单独证明多步规划增益。后10案只有一次账户查询和二选一渠道，仍主要是单次语义选路。
2. **截止机制没有对应业务约束。** 全40案均为 `[20,20,20]` 分钟窗口。最后10案每个回访均6分钟、账户查询1分钟、预算15，两个回访各8使错误分支主要由费用约束产生。最后5案虽然叫deadline_and_unavailability，正文提到截止或未到件，但来源没有独立过期时刻或不同查询窗口；未完成回访被写成可读取的结果原件。通用world确实能拦超窗，但本家族没有构造可辨识的截止实验。
3. **身份和认证覆盖单一。** 全40案认证原文都是同一 `challenge_result=success` 模板；规程同文。不能证明失败认证、不可得认证或规程冲突处理。部分“经核验本人”直接写成叙述，缺少可复核核验事件。
4. **建议/停止评分区分度不足。** 120阶段的允许动作、禁止动作、停止和重开规则完全相同，广泛允许人工复核、补件、查账户、核规程、核渠道等。可以验证越权动作约束，不能据此验证建议是否切中业务、升级是否必要或节省多少人工。
5. **证据来源角色过粗。** 某些customer原件实际上是客服工单、设备日志转述或“尚未完成核验”的状态通知。需要分清原始持卡人陈述、转述记录、联络状态和身份验证事件；不能凭source_type就当本人声明。
6. **闭环范围须写清。** 标签是“当时取得的来源如何表述目标支付”，不是“支付是否确实获授权”或“是否欺诈”。禁止金融执行合理，但若最终状态永远只有收集/人工复核，不能称已证明自动欺诈调查闭环。

## 后续处理边界

- 不以作者复审文件调用人工通过接口，不改变40案的独立审阅状态。
- 当前6案V3.1真实交付复验与这些候选分离，保持原冻结及授权；本复审不得改其输入、提示或评分。
- 原v4保留；如果修改任务机制，建立新版本，记录差异与指纹，并明确已观察/已修改，不能覆盖旧参考后称独立留出提升。
- 优先补可执行的来源过期/窗口、真实缺件状态与目标事件、分来源身份核验、具体停止和升级参考。是否需要动态Agent仍由强B0/B1/B4/B2对照决定，不通过复杂化流程预定胜者。
- 用户如选择仅做AI审阅的模拟工程实验，需要明确采用这种较弱证据口径；原PRD的独立人员门禁尚未达成，不能悄然移除。
