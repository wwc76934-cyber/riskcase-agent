# 决策记录：小案卷默认全部资料输入，动态取证保留为显式选项

状态：已采用。日期：2026-10-30。

## 问题

原始案卷中既有订单到支付的映射，也有清算、退款台账和不相关附件。让模型逐步选工具可以减少原件读取，但每个选择步骤也增加模型调用、延迟与失败机会。组件数量不是选型理由。

## 已观测证据

V2的同六案对照中，全部资料组24项事实值均正确，但有引用缺口和一次规程错误；动态组全部在预算耗尽时中止，花费还高于简单路径。V3因此公开来源角色与引用合同，并保留与简单路径相同的资源限制。具体V3结果以 `STAGE5_REPORT.md` 为准，不预填成功数字。

## 选择

`DossierService` 默认 `all_context`。适合原件数量和内容都可落在现有预算内的小案卷：宿主确定性取齐可用原件，模型理解非结构化内容并输出主张，宿主校验结构与有限的一致性条件，人工核对语义再批准工单。

`adaptive` 由调用者明确选择，用来验证按身份关联、来源角色和新读到的引用逐步取证。少读原件必须与完成质量、模型费用、延迟一起报告；不能把减少读取等同于总效率提升。

超出上下文或来源预算时明确拒绝，不自动把未经评测的长文档压缩、更多检索或更多请求当作安全回退。当前只有短文本记录；大文件、OCR、开放文档解析、更多来源和真实访问成本须另做评测后再决定默认策略。

## 职责分工

- 模型：理解文本、关联支付引用、抽取主张、选择需要的资料、输出相关原文行。
- 可信宿主：范围/时间/版本过滤、MCP与工具合同、预算、来源角色完整性、有限规则一致性检查、日志与恢复、内容绑定审批。
- 人：核对原文是否支持主张、金额语义与规程适用，以及是否批准模拟工单。

来源角色不是语义证明。`net-restored-v1`只检查模型自述净额与分析师输入及注册规程是否一致，不能证明那个净额真实。显式草稿反馈最多一次并计入预算；不会借评测金标准替模型生成正确答案。

## 面试时的解释

这个取舍体现的不是“Agent循环一定优于工作流”，而是根据实测为任务选择执行方式。系统的共同价值是原文理解、可核对输出、持久执行与受控副作用；动态规划的价值必须另有证据。不能把一次合成回归的结果推广为生产收益或长任务能力。
