# V3.1 支付欺诈调查取证模拟

这套环境用于比较同一条支付欺诈告警上的取证策略。告警、资料、查询结果和费用单位均由作者模拟。它接入本机 MCP，复用相同的来源权限、作业租约、阶段推进和审计合同。

## 取证约束

- T0/T1/T2 由宿主推进。模型无法提前读取后续资料，也不能修改时间、预算和查询结果。
- 每阶段有模拟查询时间窗，全案共享取证额度。批量查询按提交顺序执行，原件必须在到期前返回。窗口、额度及依赖在提交时校验。
- 查询能成功返回原件，也可能返回过期或不可用。后两类有状态回执，但无法形成原件行号或来源事件引用。重复读取复用原结果，进程重启时按记录验证查询时间、成本与原件指纹。
- 持卡人声明、第三方转述与联系状态在来源合同中分开。第三方转述可保留为未确定信息，无法支持明确授权或否认。认证成功仍只属于认证事实。

## 对照设计

B0 与 B4 使用同一确定性取证。B1 在资料可全部取得时读取全部资料，在存在实际时间或预算限制时允许一次批量选择。B2 在相同约束下按工具返回更新假设和后续查询，并保存每次计划、目的和实际结果。资料不可用时，B2 可以改查替代来源。B3 等稳定 B2 后另行启动。

新任务至少覆盖三类变化。逐步补件要让后来更正改变之后的调查建议。语义任务要区分相关支付、引语主体和否定范围。成本任务要存在两步以上的决策分支，包含查询后才可知的缺失或失效。冻结前用离线路径证明关键证据在预算内可达，并保留一个自然但资源效果更差的替代路径。按案件家族、主体和文本模板分离开发与评测。

参考在工具和模型边界之外保存。对每阶段分别记录可见资料、实际可取得的原件、条件结论、必要反证、预期缺口和允许的动作。评分应区分到期前可取得但遗漏的资料、已查询不可用的资料，以及当时尚未到达的资料。报价、分钟、模型延迟和人工审阅时间分别报告。

当前交付为取证环境与开发回归。正式案例版本、评分合同和配对实验仍须冻结。研究采用用户批准的 AI 作者审阅模拟口径，暂未获得人工审阅耗时、独立业务审核或真实欺诈效果的数据。

两个开发夹具共用同类案件机制。核验回呼成功时，下一步查询商户分笔入账，厘清预授权和实际扣款。核验回呼无法取得时，下一步改查应用内核验回执。六个模拟费用单位不足以同时取得所有付费资料。脚本客户端通过本机 MCP 触发两种查询路径并留存实际结果，强 B0 在相同约束下也可以达到对应资料。这两例用于证明机制可执行，正式效果仍由后续冻结对照衡量。
