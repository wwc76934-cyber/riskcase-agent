# RiskCase 系统学习手册：从项目结果走向个人能力

本手册以当前代码与结项材料为依据，重新组织学习顺序。旧 lesson 保留为开发历史，不直接当作现状说明。本文中的练习是学习任务，不表示已经完成或获得新的实验结果。

## 一、课程目标与教学方式

最终要形成四种可展示能力：把业务问题转为可计算问题；写出并核验数据与模型代码；解释 Agent 的职责与失败；用实验支持产品取舍。

每课沿用同一结构：业务问题 → 小例子 → 精确定义 → 项目代码 → 自己动手 → 错误分析 → 面试追问。术语在解决具体问题时引入，不要求先背完整名词表。

“学会”的标准有四层：能复述、能手算、能修改、能举证。读懂一段说明只完成第一层。面试前应至少有一份独立完成的分析或代码改动。

## 三、第一课：把业务问题写成可计算的问题

### 1. 项目中的三类任务

检测模型回答“有限名额先看谁”；调查流程回答“这笔交易的历史事实是什么”；规则研究回答“换一部分名单是否值得”。三个问题分别需要排序评测、证据核验、同容量政策对比，不能用一个准确率概括。

例如调查金额突增时，模型分数可以帮助选案例；真正的历史最高金额必须由截止时间前的数据算出；调查发现的候选规则仍须比较挤出损失。模型分数、调查事实、政策收益属于不同层次。

### 2. 从实际数字建立分母意识

结项报告记录：2019年423,189笔交易，523个源正标签；每天审核10笔，共3,650笔；神经集成捕获99个。

由此可以推导：TP=99，FP=3,551，FN=424，TN=419,115。Precision=99/3650≈2.71%；Recall=99/523≈18.93%。这里的正标签是合成源标签，不是现实损失。

若全部预测正常，Accuracy=(423189-523)/423189≈99.876%，却一笔正例也不捕获。这说明指标必须服务决策。每日10笔是资源合同，不是模型天然属性。项目采用日终批量 top10；当日未来交易未到达时，不能知道最终全天排名。

可写成：对每天 d 的交易集 D_d，按分数与固定并列规则取 S_d=TopK(D_d,10)，主指标 TP@daily10=Σ_d Σ_(i∈S_d)y_i。不能把全年分数最高的3,650笔替代它，因为全年选取可能把名额集中在少数日期。

### 3. AP与队首捕获的区别

AP概括全排序的查准率—召回率表现；本项目日top10只关心每天队首有限名额。两种指标的排序范围和关注位置不同。开发实验中保留渠道配方AP为0.028533，但捕获75；最终获选配方对应最好轮次AP为0.023281，却捕获129。主指标必须在看结果前确定。

加权BCE是训练用的可微目标，TP@daily10是选择用的业务指标。二者不必同向，训练损失下降不保证队首捕获增加。后续学习正类权重时，需要回到这个区别。

### 4. 怎样看提升与不确定性

最终神经集成捕获99，旧MLP10，匹配输入强树94。旧MLP对比支持相对弱基线的大幅改善；强树对比更接近“采用神经方案有多少额外收益”。99比94多5，不足以单独证明稳定优越。文档记录按天重采样差异区间[-11,21]，跨0；这表示该评估方式下差异仍有不确定性，不能解释为真实差异必在区间内。

多项组件同时变化时，不能把全部提升归给残差结构。证明单组件贡献要尽量固定其余条件；当前六配方不是对所有因素的完整交叉实验。

### 5. 规则价值体现为替换收益

2018开发期纯DL捕获122，规则保留20%名额捕获121。候选新纳入的名单带来5个正例，但替换掉的名单损失6个，净收益-1。比较必须固定每天10笔，否则扩容与方法变化混在一起。

“新增5个”只描述收益一侧。分析师应同时报告新增、挤出、净变化、误报与分组影响。当前实验支持不采用此候选；它不证明所有候选都无效，也不证明在其他容量下结果相同。

### 6. 第一课练习与参考答案

教学数据：审核容量100笔，A捕获20，B捕获25；B新增8个正例、挤出3个。已知全年总正例50个。

练习：计算A/B查准率和召回率；解释为什么B多捕获5；说明还需要什么才能证明B更值得部署。

答案：A查准率20%、召回40%；B查准率25%、召回50%；净增加8-3=5。还需检查是否同一评测时期和容量分配、是否事先固定方案、时间/实体依赖、分组退化、误报处理成本，以及在新数据上的有效性。单次计数不能证明稳定收益。若现实目标是损失而非笔数，还需要可信损失与处置成本数据，不能拿交易金额直接替代。

## 四、第二课预告：数据分析的完整推理链

推荐分析表包含：分析单位、样本范围、时间口径、分母、统计量、异常解释、验证办法、决策影响。每次发现都按“事实→假设→验证→动作”记录。

以旧MLP在2018年将3,394/3,650个名额分给Online为例：这是名额分布事实；“渠道主导导致错配”是假设；需要同时看渠道正例、各渠道捕获、分数分布、时间变化与去渠道对照。最终配方去掉渠道不等于一般业务中渠道有害，也不等于渠道差异已有因果解释。

可用初级SQL核验一条时点统计，表名和时间表示须按实际数据合同替换：

```sql
SELECT COUNT(*) AS count_1h
FROM transactions
WHERE user_id = :user_id
  AND event_time >= :window_start
  AND event_time < :case_time;
```

这里使用半开区间[t-1h,t)。相同时间的其他记录也排除，因为没有更细先后顺序。实际features.py先对整组同刻交易产出特征，再整组入窗口，保证文件顺序不会伪造先后关系。

## 五、后续知识的边界与延伸

Agent主课先掌握本项目已有的受控规划、工具合同、语义评测、预算、状态与恢复。再延伸检索增强、长期记忆、协议化工具、多Agent协作等主题。每个延伸都要回答解决什么缺口、如何评测、增加何种成本；未实现内容不得写为既有项目成果。

涉及“当前前沿”的课程应在讲授时核对官方资料与论文，标明日期；本手册没有把未核实的新框架或流行术语作为推荐。现有代码含feature_transformer分支，也不能据此把最终交付模型称为Transformer，最终主模型以冻结报告为准。

训练数据841,892笔与features.py中更广的原始特征集合，也不能直接推导最终网络的输入数量。应跟踪numeric_frame、配方配置和预处理输出：最终为12个数值及12个缺失指示，MCC单独嵌入。学习代码应沿实际调用路径核对，避免只看常量或类名。

## 六、建立自己的能力证据

建议每课保留一页学习记录：自己的解释、手算或SQL、代码定位、一次改动、实际结果、仍然不懂的问题。所有练习用新目录和小数据，不改冻结产物，不用已开封2019继续选模型。

最终面试材料应包含三个独立作品：一次有分母和分组对照的数据分析；一次能讲清输入、梯度、验证和重载的PyTorch实现；一次有原始请求、失败原因与改进方案的Agent错误复盘。证据的意义是展示本人能推理和操作，而不是重复结项文档里的数字。
