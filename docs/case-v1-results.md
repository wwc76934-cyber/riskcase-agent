检测器、调查工具、判断依据与报告校验分别保留，避免把分类模型的分数直接扩写成无证据故事。

## 哪些事情由代码约束

- 当前交易、用户和截止时间在模型调用前绑定。模型只能选择 1、24、168、720 小时，不能指定另一个用户、未来时点、路径或 SQL。
- 汇总使用完整允许窗口；预览最多 3 条，不拿预览数量冒充总数。
- 最终只能提交三项预定义检查的结构化结论：支持、不支持、资料不足。它们是线索核查，不是通用根因分析或欺诈判决。
- 报告引用必须来自本次真实工具回执；错误窗口、伪造引用、与数字不符的判断、额外自由结论会被拒绝。
- 中文数字由代码从已核对结果填入；不接受模型自由添加金额、币种、风险概率或损失。
- 默认最多 6 次工具尝试、8 次客户端轮次，每轮最多 3 个工具请求。无效尝试也计预算；协议错误和迭代上限不会发布成功报告。
- 查询/消息轨迹记录请求、回执与依据，没有获取或保存所谓完整模型内部思考链。

这些约束位于本地代码和工具接口。case 投影进一步减少可见记录，但仍不等于生产进程隔离、身份鉴权或多租户权限系统；证据哈希也不等于签名或不可篡改存储。

## 怎样核验

**全仓 207 个测试通过，本批新增 32 项。** 主要覆盖：

- 当前/同刻/未来排除、窗口开始包含、其他用户隔离、无标签表。
- 整数金额净和、负数保留、预览截断时全量汇总、金额两位小数显示。
- 时间和用户参数绕过、任意文件/SQL 工具、非法 JSON、重复键、布尔与 NaN 参数拒绝。
- 调用预算、错误终态、投影改变拒绝、伪造引用与不受支持的结论拒绝。
- 两种后续查询路径、资料缺口、真实工具结果进入消息历史。
- 显式指定硅基流动兼容地址的 HTTP Mock；没有真实网络调用或真实密钥。

独立复核脚本从原研究事实库重新执行 SQL，检查 case 精确包含哪些行，再核对所有工具的窗口、次数、金额、商户和预览。**45 条投影记录、4 次 Observation 全部一致**，报告也与校验结果一致。复核没有打开标签库或评测最终测试案例。

这证明事实和实现一致，不是 LLM 任务准确率、业务效率或真实欺诈事实证明。测试数也不代表测试了 207 起欺诈案件。
