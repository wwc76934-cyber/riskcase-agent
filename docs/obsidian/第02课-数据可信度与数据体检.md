# 第02课｜数据可信度与数据体检

上一课：[[第01课-业务问题与评估指标]]

## 本课核心

先确定“一行代表什么、字段代表什么、什么时间可得、样本代表谁”，再进行清洗与建模。数据可信度必须相对于具体任务判断。

## 四层可信度

| 层次 | 要验证什么 | 仍不能证明什么 |
|---|---|---|
| 来源完整 | 固定来源、版本、文件哈希 | 真实代表性、逐条业务正确 |
| 结构有效 | 列、必填、时间、金额、标签是否合法 | 合法值一定符合业务事实 |
| 语义与时点 | 实体键、字段含义、预测时是否可得 | 未核实的字段可以安全入模 |
| 任务适用 | 正例、时间覆盖、实体覆盖、目标场景 | 合成集成绩等于现实效果 |

## 三个数据范围不要混淆

- 全量源：24,386,900行、2,000用户、29,757正标签；用于全量剖析。
- 研究快照：1,723,101行，含预热35,932行；固定抽取500个ID，其中408人在范围内有记录。
- 训练/开发/最终测试：841,892 / 422,088 / 423,189行；正标签967 / 683 / 523。

训练、开发、测试分别覆盖2016–2017、2018、2019。固定身份群不等于各期都活跃，也不等于用户完全隔离。

## 一行与实体键

一行是一条源交易记录，不等于一个独立欺诈案件，也不自动等于唯一业务事件。

- 卡键使用(User, Card)，卡编号只在用户内部解释。
- 行号是物理引用，不能证明业务唯一。
- 商户标识不自动等于一家实体门店。
- MCC是类别，数字外观不代表连续数值距离。

## 四类易误处理数据

1. 负金额：全量1,244,683行；保留符号，语义未核实，不能直接命名为退款或全部删除。
2. 空Errors?：全量23,998,469行；不自动等于损坏。该字段可得时点未确证，初始授权前检测暂不使用。
3. 重复候选：快照17组、各2条；无业务交易号，保留候选，不把同字段记录直接认定为脏数据。
4. 时间倒退：全量同用户读取顺序倒退3,935次；须显式按实体和事件时间排序，不能依赖CSV顺序。

## 缺失率分析

$$缺失率=\frac{该范围该字段缺失行数}{该范围总行数}$$

除总体缺失率，还应按渠道、月份、用户等分组，并同时报告样本量。分组关系可提示语义差异，不能直接证明原因。缺失和0不等价，未知历史间隔不能填成0秒。

## 时间与泄漏

事件时间：交易何时发生；入库时间：系统何时获得记录；标签确认时间：何时知道结果。

只保证event_time早于预测时点，不保证当时系统真的可获得数据。项目缺少完整入库与标签确认时间，因此是有边界的回顾性时间实验。

历史窗口[t-w,t)，排除本笔、同刻其他交易和未来。预处理参数只从训练期拟合。此前已发生且可观察的开发/测试期交易可以构成之后交易的历史，但不能用其未来记录或标签拟合模型。

## 时间分布与适用性

源文件2020仅到2月28日，正标签为0。召回率分母为0，应为未定义/null，不能填成0或100%。不能由此断言现实安全。年度正例比例变化是观察结果，不能直接认定为真实欺诈趋势或概念漂移原因。

训练金额：中位29.24，p95=143.79，p99=321.60，最大5,155.36（源单位）。超过p99说明相对该分布少见，不证明欺诈；这些统计不使用开发/测试数据拟合。

## 数据质量报告模板

每项发现都写：范围/分母 → 观察事实 → 候选解释 → 验证方法 → 处理决定 → 剩余限制。

例：商户对应多地点 → 可能涉及连锁、线上或源语义 → 按渠道/MCC/时间检查并核实文档 → 暂不建立唯一门店字典 → 仍不能推断持卡人位置。

## 代码入口

- `app/risk/profiling.py::profile_rows`：流式统计、必需字段/时间/金额/标签检查、分组对账。
- `app/risk/data_contract.py`：字段合同。
- `app/risk/features.py::iter_history_features`：排序约束、窗口和同刻处理。
- `scripts/inspect_cohort_quality.py`：快照质量核验。

流式统计不用保存所有行，但用户/商户去重集合等仍占内存；不能称严格O(1)空间。Decimal用于金额解析，避免直接用二进制浮点表达十进制金额引入的问题。

## 面试可用表达

> 我把数据验收拆成来源、结构、语义时点与任务适用性。先确定分析单位和联合键，再检查分组缺失、重复候选与时间排序。对未知语义保留记录和限制，不把所有异常直接删除。所有清洗决定都说明它怎样影响模型或调查结论。

## 练习与参考

1. 同一用户、卡、分钟、金额、商户有两行，能直接删一行吗？不能；可能是真实多笔、重试或重复采集，需要业务ID与状态等证据。
2. 2020召回率应记0吗？不应；该段无正例，分母为0。
3. 测试用户训练期未出现，是否证明当时没有历史？不能；可能验证期出现，也可能测试期已有更早记录。
4. 商户在多个城市出现，是否证明客户跨城？不能；商户地点不等于客户位置。
