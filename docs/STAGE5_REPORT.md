# 第五阶段：原始案卷调查与价值验证

2026-10-30。**本阶段的工程与限定演示验收已完成：V4两条真实模型路径均6/6全项通过，首次草稿即通过。** V2、V3失败原样保留；六案已经用于修复，不能把最终成绩当独立泛化或生产收益证明。项目现在有可复核的原始案卷调查与审阅闭环，以及接收新合成案卷的独立产品入口。

## 修复的核心问题

原路径通过工具直接返回重复授权、完整性、商户处置等语义字段，固定规则足以处理。新路径提供原始清算记录、支付/订单映射、退款操作记录、独立退款台账、商户邮件与适用规程；模型必须阅读原文、区分实际入账与失败重试、排队退款与已入账退款，并引用用于计算的行。

同一事实对应两种渠道规程，可以分别要求等待排队退款或立即升级调查。规程依发布截止时间、事件日期生效窗口、渠道、版本和撤回状态过滤，不能拿最新但尚未生效的版本回答历史案件。此处检验的是规程信息必要性，不宣称向量检索算法增益。

## 没有为Agent制造一个弱对手

`all_context` 确定性读取所有8份有效案件原件、同一Skill和适用规程，再交给同一模型；`adaptive` 由模型搜索、选择原件和追踪引用。两组使用相同输出、审阅、模型及费用限制。8份资料可以完整放入共同上下文预算，未刻意让简单方案溢出。

只有实测支持，才宣称动态取证减少了哪些成本。若一次性输入更便宜、更准确，就应作为小案卷默认路径；不为保留Agent名称而牺牲质量。

## 输出和审批边界

- 取消新路径的自由文本总结；输出扣款笔数、净扣款分、退款状态、覆盖范围四项主张，以及适用规程、建议和缺失资料。
- 每项主张定位到原始文档行；审阅页在数值旁显示原文，而非只给一个无法判断含义的引用编号。
- 宿主检查引用/行号/类型和声明缺口的内部一致性，明确返回 `semantic_validation=false`。它不从隐藏标注推导答案，也不把存在引用说成已经证明语义。
- 批准工单前，后端要求审阅者明确确认四项事实、规程、缺口均已核对；确认与当前草稿及报告哈希绑定，改稿使旧批准失效。这是可审计的人工确认，不能保证人真的认真阅读。
- 复用原Harness、真实MCP网关、工具预算、响应日志、租约、检查点和模拟工单，未另造一个无恢复能力的聊天脚本。
