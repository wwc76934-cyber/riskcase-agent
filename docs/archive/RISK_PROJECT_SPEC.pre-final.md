# RiskCase Agent：支付反欺诈调查与规则验证

更新：2026-10-18。当前执行方向；数据源与指标阈值以 G0/后续验收为准。完成程度和剩余验收统一见 [项目总进度](PROJECT_STATUS.md)，初学者入口见 [项目地图](START_HERE.md)。此聊天只负责风控，TradingAgents 由用户的其他 Agent 负责，不发送协作消息或修改其仓库。本科项目不作为前提。

工作名 RiskCase Agent；仓库目录暂保留 `financial-report-agent` 以保持已建立环境与来源记录，尚未重命名。旧年报与其他方向文档仅为发现过程记录，不作为当前开发规格。

## 产品问题和用户

支付风险分析师需要从预警出发查证交易、历史行为与商户模式，形成可复核 case，并知道规则候选在历史数据上的新增捕获与代价。业务价值假设是减少机械查询、证据整理和规则试验时间；还没有真实用户效率测量。

最终交付是一套可运行的调查与验证工作台，包括数据/检测、Agent 调查、类型化规则重放、人工复核、持久状态和证据包。当前检测首轮、受限调查、模板提议、开发回放、本地审阅和离线演示已接通。已有首条源内真实模型调查及 9 项手工开发任务，其中 4 项真实模型与固定流程对照通过；独立保留评测、Agent 收益和真实业务适用性尚未完成。

## 首条端到端任务

输入：数据快照 ID、告警批次 ID、调查截止时间、受支持问题和查询预算，例如“核查这些预警的金额/频次及商户集中情况，对照用户过去行为；证据支持时提出一条规则候选，验证新增捕获和误报”。

执行：读取真实记录 → 只用截止时间以前的历史做统计 → 对比正常历史及异常分群 → 需要时补查 → 结构化记录证据与缺口 → 在开发集形成受限规则候选 → 人工审阅候选 → 冻结后在保留集验证 → 导出 case 和验证包。

输出：调查简报、可追溯 Evidence JSON、查询轨迹、规则 JSON、验证结果、资料缺口、人审状态和运行 manifest。无需证据支持时可输出“不支持该怀疑/资料不足”，不是必须发现欺诈。

## 最终 V1 范围

- 一类支付交易反欺诈，支持用户/卡/商户的已有真实字段；至少两条不同补查路径。
- 必须完成可复现的数据剖析、特征工程，以及规则、逻辑回归、一个树模型的对照；进入训练前须通过建模样本验收。经典模型、时间验证和一个 PyTorch MLP 首轮已完成；MLP 未超过树模型，见 [模型学习路线](model-learning-roadmap.md)。分数来自代码，启发式分数/模型分数/概率各自注明。GNN、VAE 仅在具体问题和比较证据支持时扩展。
- 三类调查任务：用户历史异常、商户集中模式、预警误报/资料缺口核查。
- 一种受限规则 DSL：允许字段、比较与预定义窗口聚合；独立规则验证与留出重放。
- 一个工具型调查 Agent；工作流和证据验证由代码约束，不能跳过。
- CLI 先行；最终提供任务 API 与简洁审阅入口，持久状态、后台作业、恢复和取消。
- 版本、预算、权限、日志、审计检查、CI、安装与恢复文档、可复现演示和保留任务评测。

数据质量目标：合成数据用于可控调查任务与工程故障验证，同时争取一个经许可的真实匿名交易集验证其可支持的检测/统计任务。两类结果分开。真实源若无法取得或不可解释，应在 G0 决策时明确降为“合成业务环境工程原型”，重新讨论是否满足用户的项目目标，不能默默保留真实业务表述。

非目标：理赔、征信/舆情/投诉集成、AML 定罪、自动封号/拒付/冻结、真实策略部署、全域风险平台、多 Agent 数量指标。历史记录的人工审阅和候选采纳为本地状态，不能宣称现实处置效果。

## 模块边界

| 模块 | 输入/输出 | 失败处理 |
|---|---|---|
| Data/Feature | 原始快照 → 标准交易、隔离标签、历史特征 | 类型/重复/单位/时点不满足时拒绝或列缺口 |
| Detector | 版本化规则/模型与特征 → 告警 | 版本和配置缺失时不生成伪分数 |
| Case Store | 告警/人工问题 → case 与状态 | 事务、幂等键、版本检查 |
| Investigator | case、工具 Schema、预算 → 工具调用和候选结论 | 无证据、超时、预算、取消均有明确终态 |
| Evidence Validator | 结论/证据引用 → 验证结果 | 缺引用或数值不符，报告标为未通过 |
| Rule Evaluator | 已审阅候选、冻结样本 → 增量/代价报告 | 不访问保留集调参，标签不成熟则相关指标未知 |
| Review/Audit | 身份、case/规则版本、验证包 → 审阅与采纳记录 | 防旧版本批准、重复动作、越权和未完成验证 |

证据应带 transaction_id、快照、时点、窗口、查询/公式版本；金额去重且币种显式。原始标签与未来记录不进入调查 Agent 工具，评测工具独立授权。模型出站为受限记录与摘要，不外发凭据。

RAG 只在有经核验的历史 case 后按需要引入；政策检查针对项目自定义并版本化的操作规则，不称法规合规结论。MCP 以后用于确有外部调用需要的工具，不把本地函数包装命名成已经接入银行。

## 阶段和验收

| 阶段 | 用户可见成果 | 测试/验收证据 | 学习目标 |
|---|---|---|---|
| G0 数据验收（已开始） | 探测命令、数据合同、可支持任务与限制 | 来源、许可状态、字段剖析、跨用户/时间样本、标签可得性；不满足不能进入建模承诺 | 欺诈标签、实体键、采样、事件时间与信息可得时间 |
| G1 检测与查询底座 | 导入样本、历史查询、基线告警 | 独立计算、重复/金额/窗口/未来数据测试，时间切分 manifest | SQL/数据处理、窗口特征、误报与告警预算 |
| G2 单 Agent 调查 | 自然语言调查，至少两条不同补查路径与缺口终态 | Fake、HTTP Mock、工具参数/权限、证据正确率，少量显式 live 冒烟 | JSON/消息、ReAct、工具结果、验证与预算 |
| G3 规则验证与审阅 | 候选 DSL、离线增量验证、审阅版本 | 边界/联合覆盖测试、开发和保留隔离、旧批准/重复写入测试 | PR-AUC/Precision/Recall、增量、选择偏差、人工责任 |
| G4 工程和交付 | 任务 API、状态恢复、审阅入口、CI、演示与评测报告 | 中断/恢复/取消/超时/幂等、任务集、成本/时延、基线对比 | 状态机、事务、后台作业、日志和工程取舍 |

每阶段拆成小批次：目标/数据流说明 → 最小实现与直接知识讲解 → 验证 → 同步进展 → 测试、文档和提交。用户最新要求直接推进、不再提问，后续不以问答或复述作为进入下一批的条件。工时按数据与实际节奏更新，不保证四周完成所有目标。

## 评测合同

检测：PR-AUC、固定告警预算下的 Precision/Recall、金额覆盖，记录定义/样本与不确定性，不以总体 Accuracy 主导。

Agent：先建约 30–50 个有金标准证据或检查项的任务，含正例、正常反例、缺字段、未来数据诱导、越权和工具失败；按用户/时间块或模式簇隔离开发与保留。规模为计划，真实模型执行量受预算约束。Fake 只证明控制流程，不计真实任务准确率。

对照：固定调查流程、取得相同证据的模型总结、工具型 Agent；比较证据支持、任务完成、查询数、成本与时延。不用不同的数据访问能力制造优势。

规则：只在开发/验证集探索，保留集最终复核；明确基线并集、增量真阳性、增量误报及告警量；不得从涉及金额直接推算实际损失减少。离线结果不称线上 A/B。

质量底线：不输出无引用数字；缺口显式；不读取未来标签；危险动作不可执行；失败不得标成功；原始材料可复现。业务效果阈值在基线后事前冻结，不为好看而回调门槛。

预算：人民币 20 元维持不变，默认 Fake/HTTP Mock；先测单次 live usage 再选评测数量。不因增加学习工时默认增加费用。2026-10-18 当前累计 24 次请求，账本占用估算 0.412520 元，含一笔 0.089120 元未知费用预留；不能当作实际平台扣费。
