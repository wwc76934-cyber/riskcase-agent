# 第二批：数据合同、信息时间和跨用户取样

目标：把外部 CSV 变成定义清楚的交易事实与独立标签，能说明样本支持什么、不能支持什么。这是未来 Agent 工具的输入边界。本批没有模型训练、欺诈结论或业务 Agent。

## 先理解四个风控概念

**交易（Transaction）**是发生的事件，如某用户某时在某商户交易了某金额。异常金额或负数不自动等于欺诈；负数可以对应冲正等情况，具体语义要看数据字典。本批只保留它，不自行判定。

**标签（Label）**是评测时的结果变量。外部源的 `Is Fraud?` 被转成独立的 `EvaluationLabel`，不是交易的一个可直接交给模型的特征。若 Agent 在调查时看到了事后答案，得到的高准确率没有对应的事前识别意义。

**事件时间（event_time）**是交易发生时间。**标签可得时间（available_at）**是有条件知道结果的时间。一个简化假设：交易在 10 月 1 日发生，10 月 10 日才确认欺诈；模拟 10 月 2 日调查时，不能读到 10 月 10 日的确认结果。这个例子是教学假设，不是对本数据确认流程的描述。

**告警（Alert）**是检测规则/模型要求进一步调查的对象，不等于确认欺诈。本批还不构造告警；下一阶段检测层将有版本和阈值。

## 输入、输出和失败

```text
官方合成 CSV（只读压缩流）
  → 检查必需字段
  → parse_tabformer_row（类型、金额、时间和标签校验）
  → Transaction + EvaluationLabel（两个对象，通过 ID 配对）
  → 每用户蓄水池取样
  → 事件时间过滤与字段白名单
  → agent-view.jsonl / evaluation-labels.jsonl / manifest.json
```

`agent-view.jsonl` 不含标签、隐藏答案或原始额外字段。`evaluation-labels.jsonl` 保存独立的标签和未知的确认时间。`manifest.json` 保存来源、参数、计数、输出文件哈希与限制；未来也不能把整个 manifest 无选择地塞给 Agent。

缺必需列时停止；坏时间、坏金额、未知标签进入拒收计数，不把未知标签转成正常。网络失败或预算用尽时，manifest 为 failed，命令非零退出，不报告验收成功。

注意：两个文件放在同一个目录并不是权限隔离。后续 Investigator 只能调用受控工具，评测工具不能注册给它；不能让 BasicTools 直接暴露整个数据目录。

## 代码里值得掌握的设计

1. `@dataclass(frozen=True)`：把已解析事实视为不可随手修改的对象；`__post_init__` 集中检查不变量。它不等于数据库不可篡改或运行权限控制。
2. `Decimal`：金额用十进制数表示，JSON 中以字符串保存，避免二进制浮点与序列化丢失精度。本批没有证明币种，因此 `currency=unspecified`。
3. `datetime`：源只有本地日历字段，时区未知。保留 `source_local_unspecified`，不擅自转成北京时间或 UTC；带 UTC 时区的截止时间将被拒绝，避免错误比较。
4. `transaction_id=source_id#row=N`：提供固定快照中的物理行定位，N 在过滤和取样之前分配。这不是业务唯一交易号，不能因此宣称已经完成业务去重。
5. `agent_record()`：显式字段白名单，不通过 `dict(raw_row)` 把标签和未知字段一起复制。未来工具 Observation 应来自这种受控序列化结果。
6. 当前 `as_of` 过滤为 `event_time <= cutoff`，允许查询焦点交易本身。计算历史特征时则需要另外规定窗口及是否排除当前交易，不能把这两个任务混在一起。

## 为什么使用每用户蓄水池

直接读文件前缀可能一直是同一用户。此次扫描前 200,000 条，观察到 15 个用户，从最先遇到的 8 个用户各保留至多 32 条。

蓄水池算法：前 k 条先保留，第 n 条到来时从 0 到 n-1 随机选择位置，若位置小于 k 就替换。这样可以在不保存完整历史的情况下，让所扫描用户的后期记录也有入选机会。固定 seed 让相同输入顺序下的选择可重复；每个用户独立随机状态。

它只是调查材料的发现性取样：前 8 个用户有选择偏差，扫描前缀也有覆盖偏差；每用户等配额改变了用户权重，不能直接估计总体欺诈率。抽样后历史不完整，不能用这 32 条计算“过去 24 小时总交易次数”。下一批应保留选定用户/商户的完整时间窗来做此类统计。

## 实测验收

使用 `--scan-rows 200000 --users 8 --per-user 32 --seed 42 --as-of 2019-12-31T23:59:59`：

- 扫描及合同通过 200,000 条，拒收 0；仅表示已实现字段校验通过，未验证所有业务语义。
- 15 个用户被观察到，8 个用户各取 32 条，共 256 条。
- 样本日期 2000-10-19 至 2020-02-28；截止时间过滤后事实视图 218 条，未来 38 条不进入该视图。
- 全部 256 条标签中仅 1 条正例。不代表总体比例，也不足以评测欺诈召回。
- 增加 17 个测试，含金额/时间/字段、标签泄漏、卡标识作用域、错配标签、取样配额、复现和产物字节哈希；全仓共 66 测试通过。
- 两次相同配置真实扫描的样本内容哈希相同；运行 ID 和耗时本就会不同。
- 标签确认时间仍未知。事件时间过滤不能证明数据入库、特征或标签当时可得。

G0 仍然部分通过：全量哈希、使用范围、完整历史窗口、标签可得性、真实匿名源仍有待验收。本批不训练模型、不查询 API Key、不调用 LLM，模型费 0 元。

## 你自己运行

在本仓库根目录 PowerShell：

```powershell
.\.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider tests/test_risk_data.py
.\.venv\Scripts\python.exe -B -m app.cli.data_gate --scan-rows 200000 --users 8 --per-user 32 --seed 42 --as-of 2019-12-31T23:59:59
```

第二条联网读取有界官方合成数据流，通常十几秒，网络耗时可能不同；不调用付费模型。每次写入新的忽略目录，最后输出 `output_directory`。只需先看 manifest，无需打开标签逐条分析。

读代码顺序：`data_contract.py` 中两个类与 `parse_tabformer_row` → `agent_record` 和 `visible_agent_records` → `sampling.py` → 最后再看 CLI。今天不需要一次读完网络代码。
