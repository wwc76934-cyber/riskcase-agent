# 第五批：固定样本、时间切分与数据质量

本批把全源数据变成一份可以反复使用的研究快照。尚不训练模型，也不向真实模型发送记录。

## 实验先固定，结果后查看

合同位于 `config/cohort-v1.json`，在源扫描前提交：从完整源的用户 ID 目录中，以 SHA256(seed + NUL + user_id) 升序选前 500 人。标签不参与用户选择，输入顺序变化也不会改变结果。不是直接取文件前 500 人，更不是取欺诈最多的用户。

用户目录有单独哈希；重生成全量 profile 时可用 `--inventory` 指定新文件，但目录与源归档必须匹配，不能借更换报告静默换人。

| 时间范围（左闭右开） | 用途 |
|---|---|
| 2015-12-01 至 2016-01-01 | 历史预热，不作为训练目标 |
| 2016-01-01 至 2018-01-01 | 训练与开发分析 |
| 2018-01-01 至 2019-01-01 | 验证：以后选择模型和阈值 |
| 2019-01-01 至 2020-01-01 | 最终测试：模型与阈值冻结后评测 |

原始场景假设是同一批客户后续交易的事件时间回顾性实验，不是专门设计的新客户泛化实验，也不等于已验证真实线上时点数据可得。实际构建发现各段活跃用户不完全相同；应区分训练期见过/未见过的用户，并按当前交易时点检查可用历史。全源适用性剖析已查看各年标签总数；这里不声称测试集任何信息都从未被查看。

源内保留该用户群在范围内的全部交易，不能逐笔随机抽样后再计算窗口。按用户/时间建索引；将来构建特征时显式按时间处理，同一时刻的交易不得互相看作此前历史。

## 为什么要预热

教学例：要判断 1 月 1 日的交易是否短期高频，就要查 12 月的记录。如果仅下载 1 月数据，第一天的“过去交易数为 0”可能只是历史没取到。

本合同保留 31 天预热，可为训练开始时最长 30 天窗口提供源内覆盖。查询比预热更早的窗口必须承认覆盖不足。源内完整不代表现实世界完整。

## 质量检查及边界

- 事实和标签分别写入 facts.sqlite 与 evaluation-labels.sqlite；标签确认时间为 NULL，不伪造时间。
- User 与 Card 组成卡键；保留物理行号和源引用。金额以 Decimal 解析，另保存整数的 0.01 源单位用于精确排序统计，不擅自称为美元或人民币。
- 金额分位数只从训练期取。采用 nearest-rank：排序后取第 ceil(p × n) 项。例如三笔金额 -1.01、0、10.01，p50 为 0，p95 为 10.01。不把测试金额纳入预处理参数。
- 同用户/卡、时间、金额、商户、渠道和地区等观测字段相同，列为重复候选。标签不参与重复键，原记录不删除；没有业务交易号就不能认定为脏数据。
- 各段仅检查正负例数量是否够做起步实验，预先固定每个训练/验证/测试段至少 30 正例、100 负例。这是操作门槛，不是统计功效或独立案件数保证。
- 空 Errors? 不直接认作坏数据；Errors? 不保存到模型事实库，初始授权前检测暂不用它。MCC 等字段为原始字符串，语义与位置一致性仍待核实。

## 程序的数据流

已核验归档 + 全量身份目录 + 固定合同 → 完整扫描 CSV → 用户和时间范围筛选 → 标准交易及精确金额 → 分离事实/标签 → 索引、训练金额统计、重复候选 → 构建报告与文件哈希。

只有完整 CSV EOF、源行数与 inventory 一致、事实/标签/分段计数对账通过后，才发布 research_snapshot_built。该状态只说明快照已构建，不表示业务质量全部通过；class_counts_sufficient 单独报告。中途失败保留 failed 报告，不把残留数据库当成可用快照。

## 运行与查看

在项目根目录 PowerShell：

```powershell
.\.venv\Scripts\python.exe -B -m app.cli.build_cohort
.\.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider tests/test_risk_cohort.py
```

原始数据和派生快照不提交 Git。命令无网络调用，每次新建目录。控制台打印输出目录，目录内 frozen-plan.json 保存实际用户和代码/源版本，build-report.json 保存结果。

如果全量 profile 是自己重生成的，使用 `--inventory <本地profile.json路径>`；用户目录哈希一致才允许使用。不要为了凑指标更改 seed 或时间边界；需要改实验时另立新版本并说明原因。

## Agent 知识：可复现快照为什么重要

同一个调查问题，如果工具底层数据变了，结论变化就不能简单归因于模型。快照 ID、查询时间、工具版本和证据引用，让我们区分“模型变了”“数据变了”与“计算口径变了”。本批快照尚未接入调查 Agent；后续通过受限适配器接入，不把标签库或任意 SQL 交给模型。
