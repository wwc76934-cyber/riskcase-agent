# 第6A阶段：纠正业务断层并接通检测告警

2026-10-31。**只完成业务主线接通与离线执行验收；真实数据、Agent额外收益和产品目标仍未达成。** 后续验收以 [业务方案](FRAUD_PRODUCT_PLAN.md) 为准。

## 发现与修正

第五阶段本质上核查重复扣款与退款到账，不能证明欺诈；新页面又只接受手写case编号，与已有神经模型预警无关。之前把此局部验收作为整体产品提升，标准过低。现将项目定位收敛为“事后批量欺诈告警调查工作台”，退款模块保留为独立实验，原文与评分未改写。

新入口直接读取已有的检测案件投影，保留交易ID、用户、事件截止、模型版本、排序分数和来源哈希。复用原 `CaseTools` 的统计与边界检查，以新MCP合同暴露目标交易、历史统计、商户记录及项目自建研究口径。没有把负金额解释成退款，没有新增虚构客户邮件或认证记录。

这些三项行为检查只是确定性基线，不能证明需要Agent。下一阶段必须找到真实分析师的问题与资料分布，再比较代码证据包、一次性模型分析和动态取证。继续添加组件不能替代该验证。

## 业务合同

- 同一告警贯穿检测、案件和工具；当前只接受2018开发范围的已注册本地模型投影。
- 原日审核名单是一天结束后形成，页面单列名单可得时间；事实仍限定在目标交易时点，源入库时间未知，不声称实时可得。
- 输出三项行为线索及引用，不输出“正常交易”“确认欺诈”或“退款完成”。资料不足时请求记录，否则交给分析师审阅；未发现这三类线索也不自动关闭。
- 授权、设备认证、外部结案证据始终标记为缺失。项目研究口径不伪装成银行SOP。
- 新主线固定独立Skill、清空旧争议知识与经验；拒绝从欺诈任务产生清算/商户解释经验候选。人工批准须确认线索、范围与缺口，仍只提交本地模拟工单。

四个原先无标签选择的源案例经两个真实MCP进程进入相同Harness，各进行5次事实/规程工具调用和1次Skill加载，全部停在 `awaiting_review`。客户端为 `deterministic_fact_baseline_NOT_LLM`，不是调用模型，不能记为新Agent成功率。回执位于 `runs/stage6a-fraud-bridge-v1/summary.json`；可携带的汇总见 `stage6a-results.json`。

## 验证与保留边界

第一次测试命令引用了不存在的测试文件，没有执行测试；修正命令后40项通过。随后覆盖新边界、共享统计、Harness、原案卷、RAG/经验与MCP的141项回归通过（129.93秒），保留既有Starlette弃用警告。不同测试批次不相加冒充全仓成绩。额外恢复/冻结测试首次因MCP将注入终止包装为异常组而断言失败；校正测试以核对实际终止原因后，新边界15项全部通过，确认保存响应后恢复重放一次、没有重复请求。失败回执保留，未改生产代码绕过测试。

新入口浏览器验证：从注册神经告警发起任务、真实MCP取证、源身份/时间/分数与证据缺口显示、未确认时拒绝批准、内容绑定审批和模拟提交；禁止外部请求。旧工作台的原始失败及未关闭计划仍能显示。首版页面暴露大段JSON影响审阅，已改为中文线索与统计摘要，原字段留在可展开证据中。

本轮大模型请求0次，估算新增费用0元，原项目估算累计13.048320元不变。未经新批次授权不复用历史剩余额度。

## 仍未完成

当前训练和调查源仍为IBM合成数据，4个源案例属于开发展示。真实电商来源的获取/条款/字段/时序审计、独立调查任务、真实分析师收益、聚案后的容量与召回、并发吞吐均未完成。当前页面接受的来源是本地注册投影，哈希证明文件对应关系，不是银行来源认证或恶意本地管理员防护。
