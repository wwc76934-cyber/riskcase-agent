# 一次调查的面试演示

这个演示说明系统怎样执行和约束模型。它不证明Agent优于代码：选用的world-032在B0、B1、B2中均严格通过。群体结论以[完整报告](AGENT_VALUE_FINAL_REPORT.md)为准。

## 三分钟顺序

1. 先展示告警绑定：目标交易、用户、历史事实截止与调查资料可得截止分开。A来自IBM合成交易；设备、账户、客户及规程B原件明确标注独立模拟。隐藏参考C不进入工具。
2. 展示实际B2轨迹，而非重新调用模型。初始计划涵盖认证、设备、账户、客户、商户、规程及历史方法来源；真实读取了其中六种原件。取得原件后，有一次模型主动提交的中途修订，计划重点改为客户、账户及认证。终稿假设归档单独计数，不算中途改道。
3. 打开E来源引用与O主张。E证明读了什么，O记录怎样解释；系统不会因为认证成功就认定客户授权。时间与来源层级由宿主从已读原件回填，原模型填写和变换记录仍保留。
4. 展示终稿中的补证和人工建议：请求客户材料、核验联系渠道。停止理由是足以提交人工审阅，不是已确认欺诈或已安全结案。
5. 在独立工作台生成免费代码证据包，完成五项审阅、批准当前内容、提交本地模拟工单，再重复提交验证相同收据。此操作展示审批及幂等性；页面明确显示代码客户端，不能把它说成现场真实模型调查。

## 可复核材料

正式结果中的B2记录位于本机`runs/agent-value-upgrade-v1/phases/main-01/`，按`case_id=world-032`和`condition=B2`定位。对应服务检查点保存假设版本、工具结果、原始终稿及宿主变换；模型请求和去除思维链的对外响应保存在该任务的`model-records/`目录。

交付便携包的`demo-trace.json`只包含该次实际执行的路径类型、计划来源序列与修订计数，不包含原始交易或案卷文本。它是作者导出的摘要，不是提供商签名；文件一致性由`python scripts/verify_agent_value_evidence.py`检查。

新工作台的启动与复核步骤见[运行指南](AGENT_VALUE_REPRODUCE.md)。没有本机IBM数据和研究包时，先运行离线合同/MCP测试与便携汇总核验；不能把安装夹具冒充原模型告警。

## 面试官追问时直接回答

“这条轨迹证明模型能够按实际观测提交计划修订，但同一案件代码也能完成。是否值得部署多步Agent，由完整强对照而不是这一个演示决定。项目的工程成果包括来源与时间约束、可恢复执行、费用未知时停止、方法版本治理和逐项人工批准；这些与Agent收益是两类证据。”
