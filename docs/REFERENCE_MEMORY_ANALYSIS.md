# 参考材料评审与本项目采用方案

2026-10-31。用户提供的是《让 Agent 学会记忆，并在对话中自我进化》15页材料的二次整理，原图正文和参考文献有不可辨认部分。以下评的是可辨认的设计思路，不能替该项目证明实现质量、实验数据或金融收益。优先保持欺诈告警主线，不迁移成信贷审批产品。

## 值得采用的优势

1. 记忆与业务时间线结合：在案件进入、核查、人工审阅、后续结果到达时分别使用。我们对应的是告警、调查、审阅、外部结案；最后一类目前缺数据，不能用模型总结代替。
2. 写入、检索、更新、遗忘是完整生命周期。相比把历史聊天塞进向量库，显式操作、冲突、版本和失效更容易审计。
3. 反馈先成为候选，再验证并发布。重复错误、工具验证和人工纠正能提供线索，模型自评不构成外部正确性证明。
4. 将记忆技术指标和业务收益分开。检索召回提高不能直接写成欺诈识别提高；我们必须同时保留简单流程对照和错误复用成本。
5. 分期推进，避免一上来做自动改规则。现有预算、冻结输入、任务恢复和内容绑定审批可以作为基础，无须重新造一个平台。

## 必须修正或不能照搬的地方

- CoALA不是“四级情景/程序/语义/反思”的逐字分类。论文区分工作记忆与长期记忆，长期记忆含情景、语义、程序；反思可视为产生新内容的操作，不必再建第四套数据库。[CoALA原文](https://arxiv.org/abs/2309.02427)
- Ebbinghaus不能直接给金融事实设遗忘阈值。事实保留取决于来源、时间、业务适用和授权；低访问量不等于过时。
- 违约或欺诈结果不是单一因果标签，存在确认延迟、政策变化和选择偏差。坏结果不能自动推导某条规则有错，更不能从一案推广到所有用户。
- 记忆相似不等于同一主体、同一事件或有权访问。必须先按主体/任务/时间/状态过滤，再做检索排序；不能依靠prompt补救越界召回。
- DELETE在本地研究版本表示撤下可检索条目，不等于隐私合规的物理擦除；审计和已冻结上下文另有保留边界，不能声称完成所有删除义务。
- 双闸门必须是可执行的证据检查与人工内容批准。模型写两次“检查通过”不是双重控制。

## 五类方案的取舍（研究思想，不声称采用其当前SDK）

| 来源 | 采用的思想 | 当前不引入的复杂度 |
|---|---|---|
| [MemGPT](https://arxiv.org/abs/2310.08560) | 有限工作上下文、持久记忆、显式按需读取 | 不开放模型任意改写系统上下文与执行循环 |
| [Mem0](https://arxiv.org/abs/2504.19413) | 抽取候选、去重、显式新增/更新/撤下/不操作 | 不让相似度或LLM单独决定金融事实覆盖；不冒充已集成其实现 |
| [Zep](https://arxiv.org/abs/2501.13956) | 事件时间与记录可得时间分离、历史关系版本 | 当前实体关系有限，不为图谱名称部署图数据库 |
| [A-MEM](https://arxiv.org/abs/2502.12110) | 来源笔记与关联链接、关联可追溯 | 语义关联不是事实；不允许自动关联跨客户私有案件 |
| [MemoryOS](https://arxiv.org/abs/2506.06326) | 分层保留、容量管理、从短期交互整理长期内容 | 不照搬个性化对话的升降级阈值到风控结论 |

框架论文各自的准确率和成本数字不可直接比较，也不作为我们的成绩。没有同一模型、数据、预算的复现，不宣布谁最优。

## 对应到当前代码的具体改进

| 参考流程 | 我们的实现目标 | 验收 |
|---|---|---|
| 情景记忆 | 从已完成、已明确审阅的欺诈任务提取结构化核查记录；绑定源报告/主体/事件截止 | 不复制自由文本断言成案件事实；跨主体、未来记录不可召回 |
| 语义记忆 | 研究口径/字段含义/版本化规程 | 标明自建研究规则，不冒充银行制度；资料时间与任务范围匹配 |
| 程序记忆 | 冻结Skill与受审阅的有限调查建议 | 不能授予工具权限或改变资金动作；所有更改可回退 |
| 反思 | 结构化反馈及失败信号形成候选 | 模型建议与人工纠正分开，候选不能直接检索使用 |
| ADD/UPDATE/DELETE/NOOP | 内容指纹、期望版本、撤下墓碑、审计事件 | 重试幂等、并发冲突、重复条目不膨胀 |
| 按需检索 | 固定到任务提交时的记忆快照；M记忆引用不等于E事实 | 恢复稳定、无相关记忆明确返回空、不能从旧记忆关闭新告警 |
| 双闸门 | 源报告/范围/结构校验 + 内容绑定人工发布 | 未审阅条目、变更过的源报告、过期条目不能发布或被召回 |
| 双层评估 | 公开记忆基准协议 + 本项目业务生命周期合同；真实模型比较另行冻结 | 工程测试、检索命中、答案正确率、人工收益分别报告 |

## 原论文与评测适用性

[Reflexion](https://arxiv.org/abs/2303.11366)使用语言反馈和情景记忆改进后续尝试，不等于更新模型权重；我们借鉴反馈回路，结果仍需外部检查。

[LoCoMo](https://snap-research.github.io/locomo/)使用生成并经人工校验的长对话，适合记忆研究，不是真实金融案卷。[LongMemEval](https://github.com/xiaowu0162/LongMemEval)明确区分信息抽取、跨会话、时序、更新与拒答能力。其答案和`has_answer`、`answer_session_ids`字段只能进评分器；oracle文件已筛出答案会话，不能拿来宣传检索性能。

技术基准可验证机制，但真实调查任务、人工修改量和错误关闭风险仍须独立评测。公开ULB检测数据若可获得，也只验证分类外部性，不能与IBM用户拼接来制造真实记忆场景。

## 持续执行与完成条件

用户要求持续推进至整体目标达成。将研究、实现、离线故障测试、源数据/公共基准验证、有限真实模型对照、产品演示与交付视为连续工作，不因写完一份文档停止。最终验收仍要求业务主线一致、来源可核查、可复现检测对照、可恢复调查与记忆闭环、诚实的效果边界。需要外部数据或新的付费授权时，仅暂停依赖该条件的动作，其余继续。
