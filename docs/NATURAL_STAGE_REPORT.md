# G6-A：自然语言范围与确认后取证

本阶段完成了“一句话需求 → 待确认计划 → 只读取证 → 代码计算 → 待审阅报告”，并完成真实模型对照。**工程闭环完成，模型优于简单路由的假设没有通过。** 不将模型入口设成默认推荐路径，保留结构化检查和离线关键词入口；`mode=live` 是显式启用的实验能力。

## 用户现在能做什么

提交“查金额和新商户”，系统展示滚动30天的两个具体检查；显式确认后，才执行三次固定查询，得到数字、结论和引用。含糊问题停止待澄清，冻结账户等请求停止并标明超出范围。模型不读取交易事实或标签，不能修改工具参数、批准自己的计划或执行资金操作。

原有混合ReAct调查保留作对照。新增路径把模型职责收窄为范围翻译，金融判断全部由代码完成，不依靠模型重新计算数字。输入、输出和运行方式见 [直白指南](NATURAL_TASK_GUIDE.md)。

## 冻结评测结果

实验代码提交 `1194e8b`。先冻结80条中文问题、提示、词表、数据引用和代码，再运行两组各80个执行单元；没有根据分数调整提示或重跑失败题。每部分40题：10单项、10组合、8否定/排除、6含糊、6越界。

| 分组 | 范围完全正确 | 真实模型请求 | 按所选范围通过SQL核验的报告 |
|---|---:|---:|---:|
| 开发：关键词 | 40/40 | 0 | 28 |
| 开发：模型 | 31/40 | 38 | 19 |
| 评测：关键词 | 37/40 | 0 | 25 |
| 评测：模型 | 33/40 | 38 | 22 |

“范围完全正确”要求动作正确，并且检查项全部且仅有所需。格式合法不等于得分。每部分2题由双方共享的窄范围安全检查直接拒绝，不能归功于模型；去掉这2题后，评测关键词35/38、模型31/38。

评测配对：模型单独答对1题，关键词单独答对5题，双方答对32题，双方答错2题。模型没有格式失败和格式修复；失败出在语义理解。80题模型有15题不必要地澄清/拒绝，1题多选三项。关键词评测3题漏识别，其中“付款之前连续刷卡”被宽泛的付款词误拒绝。该缺陷保留，不在本批原题上改分。

两组对24个应澄清/拒绝的问题均未错误执行，但这不证明通用越界防护有效；题集很小且部分由共享硬规则处理。模型少执行查询主要因为不必要地停止，不能写成查询效率提升。

## 为什么数值对了，报告还可能错

用户说：“正金额占比先跳过，本次只比较笔数Top1。”模型却选择频次、金额、新商户、笔数集中度。代码按照这个计划生成的数字全部正确，但多查了用户没有要求的三项。因此这题按范围失败计分，不能用SQL通过把它改成成功。

本轮94份自动评测报告都经独立源SQL核验：关键词53份、模型41份。自动评测**模拟接受每份合法计划，包括错误计划**，不使用标准答案替模型纠错。模型其中1份范围错误；“94份数字正确”不等于“94份需求正确”，更不等于真人审阅通过。

可看 [范围正确的例子](../examples/natural-scope-success.md) 与 [数字正确但范围错误的反例](../examples/natural-scope-overreach.md)。

## 结论与剩余工作

这次证明系统能把语义错误、数字错误、权限边界和人工确认分开处理，也再次否定了“用了模型就更好”。在当前范围，结构化选择或关键词入口更合适；真实模型入口供后续研究，不包装成已验证业务收益。

题目由项目作者编写，没有独立标注人员；默认口径如何映射简称也由作者定义，真实分析人员可能有不同理解。两部分共享意图类型，8个合成案例复用G5用户，不是新增金融用户或银行业务样本。没有欺诈识别率提升、人工时间节省、外部泛化或企业生产可用的证据。

下一个大阶段优先完成统一研究交付与最终验收准备：把预警排序、调查、候选、同容量验证和审阅材料连成一个展示入口；冻结模型/策略选择及最终测试方案；整理独立任务编写和真实匿名数据的可行性与许可。先补能证明价值的证据，再决定是否扩大模型职责。2019最终检测集本轮仍封存，实际金融候选第2版仍待审阅，未批准或部署；原V1尚未全部结项。
