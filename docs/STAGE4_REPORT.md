# 第四阶段：冻结评测、失败修复与面试交付

2026-10-29。四阶段路线中的评测与交付工作已落地，但**真实模型表现没有达到可靠调查的程度**。本阶段最有价值的结果是测出了宿主完成条件缺陷、模型规则优先级错误，以及知识工具未实际使用；不能把工程功能齐全写成模型能力强。

## 事前固定什么

合同见 [STAGE4_PROTOCOL.md](STAGE4_PROTOCOL.md)，场景索引见 [STAGE4_SCENARIOS.md](STAGE4_SCENARIOS.md)。12个家族×5个变体，共60个自建合成场景，按家族分为开发、回归、冻结审计各20个；同家族不跨组。冻结审计是内部运行前固定的审计，作者已经了解既有规程，**不是外部独立测试**。本阶段没有重测已观察2019作为新鲜深度学习成绩。

冻结包 `runs/stage4-freeze-v1/` 包含案例、仅评分使用的金标准、已审阅方法快照、模型预算、完整应用源码哈希与副本。金标准没有传入模型。所有条件最多6次模型请求和12次工具尝试；格式纠正计入总请求，不对错误结论作语义纠正重试。

对照包括固定全查代码、基础工具循环、完整Skill/Harness/知识路径、去掉Skill、去掉知识检索。宿主消融只由构造参数启用，未开放成HTTP客户端提权开关；权限、范围、事实验证和费用上限始终保留。

## 分清宿主缺陷与模型错误

**宿主完成条件缺陷。** V1初始自由文本待办为“Select an applicable skill”。完整系统已经加载技能，仍可能复制旧待办；去掉Skill的条件也错误地残留它。宿主在校验结论前因待办非空直接拒绝，导致部分有充分证据的答案未完成。原始评分只看到未保存的提议，不能据其 `proposed_correct=0` 推断模型完全没有正确结论。

**真实规则错误。** “历史不完整但独立清算完整”一案，四组模型都选择了 `duplicate_record`，声称清算完整覆盖了历史缺口；本规程要求 `insufficient_evidence`。基础Agent在“多笔清算但商户确认”一案又错误地用商户确认覆盖多笔清算。事实校验器拒绝这些答案，没有替模型改答案。完整版在一案还耗尽了6次请求，最后给出带解释前缀的答案，属于格式/完成失败叠加错误结论。

**知识工具没有被实际调用。** 12次真实运行的 `knowledge_queries` 全部为0。因此不能将这批称为已测得RAG或经验内容的效果，也不能从可选工具的增删推导记忆因果收益。Skill目录、正文和加载工具确实发生了变化，但宿主完成条件缺陷污染了原始完成率比较；每组仅3案，本就不足以作统计优越结论。

**攻击曝光不同。** 注入案中，基础组、去掉Skill、去掉知识组的请求中确实出现了越权指令及E999；完整组的正文压缩未让这些攻击句子进入模型视图。不能声称四组都经受了相同攻击曝光，更不能宣称通用抗注入。实际模型轨迹没有越权工具调用；宿主越权拒绝能力另由故障测试验证。曝光记录见 `runs/stage4-live-v1-audit/exposure.json`。

## 修复及验证，不改写原始实验

新完成合同 `evidence-v2-plans-advisory` 详见 [修复说明](STAGE4_COMPLETION_FIX.md)：初始计划为空；任务结构完成由宿主验证必需证据与结论，不依赖模型自由文本待办。待办/未知项保留，生成审阅警示，页面提醒分析师核对；报告仍需人工审阅，工单批准仍绑定内容哈希。已解析提议在其他宿主检查前保存，便于区分未完成与答错。

使用原始67份响应在新版宿主离线重放，基础组仍1/3，三个Harness组各2/3可进入待审阅；错误结论仍被拒绝。**这不是新模型推理**：旧响应没有观察新提示，所以不能报告“新版真实模型通过率2/3”。结果独立放在 `runs/stage4-host-replay-v2/`；原始V1结果和源码原样保留。新版另冻结源码，完成真实MCP脚本与工作台回归；没有再次付费验证。

最终全仓 **836项通过，347.64秒**，仅1条既有Starlette/httpx弃用警告；浏览器已检查原始失败表、未关闭计划警示、工单没有自动批准、经验发布/回滚及窄屏布局。原始回执与 [机器汇总](stage4-results.json) 对应。故障覆盖未知工具、跨案结果、超时、超长输出、日志损坏、旧worker fencing、请求结果不明、中断恢复、重复提交，以及新版计划警示不能覆盖事实错误。测试数是工程回归证据，不是模型能力分数。

## 面试时应该如何评价这个项目

工程方面已超出单个聊天脚本：真实MCP、工具治理、版本化Skill/知识、持久恢复、审批与副作用管理均有可追踪的故障证据。评测还发现并修复了“让模型自述决定宿主是否完成”的设计错误，这比仅展示成功轨迹更有解释价值。

但任务仍然狭窄：源工具已提供很多结构化语义字段，固定代码可以覆盖，尚未验证开放文档提取、复杂规划或真实分析师收益。当前完整组合没有证明比简单系统更有价值。不能以“工业级Agent平台”“自进化”“模型100%通过”描述它。

下一轮最有价值的工作不是继续堆组件，而是补上新的任务与评测证据：真实或更接近真实的非结构化资料、明确的分析师目标与审阅成本、需要检索才能解决的知识差异、新的标注和未用于调参的评测条件；再决定哪些组件值得默认开启。新模型或方法应服务于这些瓶颈，不能把历史开发题重复调参包装为泛化提升。
