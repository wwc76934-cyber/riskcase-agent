# 面试展示用失败复盘

这三个例子来自冻结实验，不是为了展示保护逻辑而事后编造的模型回答。原始索引与摘要见 [G5-A证据](../docs/mixed-stage-v1-results.json)。

## 1. 引用正确，大小比较仍然错

评测题 `u04-concentration`：短窗口笔数Top1为3/22，长窗口为8/55。

用整数比较：3×55=165，8×22=176，因此短窗口较低。固定证据模型和工具型Agent均曾提交 `increased`，被代码拒绝。

结论：有来源不代表结论正确。金额、比例和阈值应由代码核验，不能只做“引用ID存在”的检查。

## 2. 答案数值正确，仍不应算任务成功

开发题 `u01-full_counterevidence` 的Agent成功取到6份观察，又尝试第7次调用。工具没有执行新的查询，但旧运行入口随后写出了数值正确的报告。

批次审核拒绝该任务，计入失败，成本仍保留。之后增加发布前预算检查，并用相同的离线超限行为验证：结论清空、报告不生成、服务不能进入待审阅状态。修复提交 `cf8c911`，没有重跑真实任务来替换原成绩。

结论：工具拒绝越界调用与控制器拒绝发布结果，是两个都要验证的条件。只测工具会漏掉控制循环的状态问题。

## 3. 压力题暴露资料不足处理缺陷

两份独立列出的样本政策压力题把下限明确设为1000条。它们复用开发案例，没有增加独立评测用户。

固定流程两题都通过；固定证据模型两题均被拒绝；工具型Agent通过一题，另一题在协议/控制检查处停止，现有记录不足以唯一定位原因。这不是“Agent已经可靠处理资料不足”的证据。

结论：资料不足必须有可验证条件；模型失败与平台协议失败分别记录。不能把成功报告正确率替代完整任务通过率。
